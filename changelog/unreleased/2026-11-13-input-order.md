- Fixed input that reaches an app between two frames: `App.frame()` now dispatches it in the order it came, each input against a tree built from the state the inputs before it left. When a handler took an input and more input of the same frame waits, the view is built and laid out again before the next one finds its element, so two ArrowDown in one frame move the data grid's or the tree's selection by two rows, a press after a key that moved things goes where they are now, and every edit of a field, also in a row of a virtual list, builds on what the app made of the one before. Input that no handler took (pointer moves, unhandled keys, caret moves, Tab, the wheel) costs no rebuild, and the rows of virtual lists are built between inputs only when the next input needs them. Breaking: pointer presses, releases and the wheel are now hit tested when the frame dispatches them rather than when they arrive, so `App.pressed()` changes at the next frame; `App.focus`, `scrollTo` and `scrollToRow` called from a handler take effect right after it, on the element with the same identity in the rebuilt tree.
