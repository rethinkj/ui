# Changelog

What changed since the last release, for users of the library.

## Unreleased

### Added

- `El.range(from, to)` lays a child of a multi-line field over a range of its text, hit, filled and focus-ringed on the range's rows only, which makes links in a paragraph; `El.fitLines()` makes a multi-line field as high as all its rows; `El.skipTab()` lets Tab pass a focusable element by.
- `El.rows(count, heights, row)` is a virtual list whose rows are as high as their content, with their heights kept in a `RowHeights` the app holds; `Spans.strike(from, to, argb)` strikes out a range of a multi-line field.
- `Markdown.markdown(theme, document, options)` in the kit shows a Markdown document as a scroll area that builds only the blocks in view: headings, paragraphs with bold, italic, inline code, struck-out text and links that Tab reaches, code blocks with highlighting and a copy button, quotes, lists, task lists, tables and thematic breaks, selectable and copyable, in the new `Theme.Prose` tokens. The example `Manual` shows it.
- `MarkdownDocument.parse(source)` in the kit reads CommonMark with GitHub's tables, task lists, strikethrough and bare URLs into a tree of blocks and inline parts, without a library; it never throws, takes time in proportion to the text, and keeps raw HTML as text.
- `Font.sansItalic()` and `Font.sansBoldItalic()`, Inter 4.1 Italic and Bold Italic in `rethinkj-ui-fonts`.

### Fixed

- An overlay that keeps the focus where it is, such as a toast, lost the focus when it closed after Tab had moved the focus onto its action; the focus now goes back to where it last was outside the overlay, as for a menu or dialog.
- On Linux with X11, a window being resized no longer falls behind its size. Every step of a resize asks for a redraw, and `WindowLoop` drew each one in turn; now a redraw replaces one that is still waiting.
- Releasing Alt after a click made with Alt held gave the menu bar the keys; as in Windows, only Alt pressed and released with nothing between does. Core's new `El.onAnyPointerDown(handler)` runs on every press in the window, also in text fields and on scrollbars, without taking it.

### Other

- Added windows in the new package `com.rethinkj.ui.window`. `Window` opens a native window through SDL 3, with or without the system's frame, delivers its input as `WindowEvent`s (pointer, wheel, keys with stable names and modifiers, text, size, scale, close requests, and redraws while the user moves or resizes it on Windows) and gives the handles a GPU surface needs (`Window.handle()`); `Window.progress` shows progress on the taskbar. `WindowLoop` runs an `App` in a window and calls its presenter only when there is a new frame, so an idle window does nothing. A frameless window draws its own title bar: elements marked with `El.windowPart(WindowPart.DRAG)` move and snap the window, the margin along its edges resizes it, and the minimize, maximize and close parts act when clicked; `App.windowPart` reports the part at a point. On Windows 11 such a window has rounded corners and the system's shadow, shows the snap layouts on its maximize part and the system menu on a right click on a drag area.
- A modal overlay, such as a dialog, no longer blocks the parts of a frameless window's own frame (`El.windowPart`): while it is open the window can still be moved, minimized, maximized and closed, and a press on such a part neither dismisses the dialog nor reaches anything else. `App.windowPart` looks through the modal overlay for them.
- Windows have icons of their own for the taskbar, Alt+Tab and docks: `WindowIcon.of(Pixels...)` or `WindowIcon.of(size -> view)`, a view drawn at each size the system asks for, set with `Window.options().icon(...)` or `window.icon(...)`; the kit's `AppIcon.appIcon(theme, size, colour, symbol)` makes one of a rounded square and a symbol.
- Added virtual lists for long data such as query results. `El.rows(count, rowHeight, row)` makes a vertical scroll area of `count` rows of one height, of which only those in view and `El.OVERSCAN` (3) more on each side exist as elements: `App` calls `row` with an index for those after each rebuild of the view and when scrolling shows a row that does not exist yet, which builds the list's rows anew but not the view, so a million rows cost no more per frame than a thousand. Rows are identified by their index; a focused row that scrolls out stays focused and is focused again when it comes back, and Tab enters a list where the focus last was in it, or at the first row in view. `App.scrollToRow(list, row)` scrolls a row to the top, `El.isVirtualList()`, `rowCount()`, `rowHeight()` and `firstRow()` describe a list, `El.dump()` adds `rows <first>-<last>/<count>` to its line, and `Script` has the step `scroll <target> row <index>`. Breaking: scroll offsets are doubles now, so that they stay exact in lists billions of pixels tall: `El.scrollX()` and `El.scrollY()` return `double`, and `App.scrollTo(area, x, y)` takes doubles.
- Added `Tree.tree` to `rethinkj-ui-kit`, for nodes that open and close, such as a database's servers, databases, schemas, tables and columns. The app supplies the nodes through `Tree.Model` and owns which are open and which is selected; the tree reports a selection, a node to open or close, and an activation (a double press or Enter). Only the rows in view exist, so 100 000 nodes shown scroll like a dozen, and a rebuild of the view numbers the shown nodes in about a millisecond for 100 000. Children that are not known yet show a muted loading row until the app has them. Up, Down, Home, End, Page Up and Page Down move the selection, Right and Left open, close and move between parent and child, and each row has a slot for an icon before its label.
- Elements now carry the app's state with WAI-ARIA's names: `El.selected`, `checked`, `checkedMixed`, `expanded`, `disabled`, `level`, `position`, `sortAscending`, `sortDescending` and `value`. A `.tree.txt` writes them after the rectangle, in a fixed order, as in `el #row-8 role=treeitem label="created_at" 8,184 264x22 selected level=5 pos=2/3`; text fields say `disabled` and `readonly` by themselves, and the rows of `El.rows` their position among all rows. Script selectors match them, as in `press role=treeitem expanded=false label="public"`, and a selector whose states match nothing lists the lines of the elements that match the rest. The kit's components set what they know: a button without handler says `disabled`, switches and checkboxes `checked` or `checked=false`, the selected row of a grid or tree and the active tab `selected`, a tree row its level, open state and position among its siblings, a sorted header `sort=`, and a split's separator its position as `value`. Lines of stored trees change accordingly; tests that compare whole lines of a `.tree.txt` need the states added.
- The kit's tree scrolls the children of a node that opens into view below it, as far as its height allows with the node still in view: a node opened at the bottom of the tree, by the keyboard or the pointer, no longer leaves its children out of sight.
- `Tree`: a secondary press on a row selects the row before the tree's own `onSecondaryPress` handler runs, so that a context menu given to the tree with `Menu.contextMenu` acts on the row it opened on instead of the one selected before.
- Added `Tooltip.tooltip(theme, anchor, text)` to the kit: a text below an element after the pointer has rested on it for `Theme.Motion.tooltipDelay`, gone when the pointer leaves or presses, with no state for the app to keep.
- Added `Toast.toast(theme, message, action, onAction, onClose)` to the kit: a message at the bottom of the window with an optional action such as Undo, which closes itself after `Theme.Motion.toast` seconds (5) of the app's clock, without drawing frames meanwhile, and leaves the keyboard focus where it is. Core gained what it is built on: `El.atWindowEdge(side, align, gap)` places an overlay against an edge of the window, and `El.onShownFor(seconds, handler)` runs a handler once an overlay has been open that long. `Theme.Motion` gained `fade` and `toast`.
- A right click on a drag area of a frameless window (`WindowPart.DRAG`) opens the system's window menu and no longer also reaches the app as a secondary press, which had cleared the focus and dismissed overlays behind the menu. The menu opens only when the press also ends on the drag area.
- The theme has two more headings, `Type.title` and `Type.strong` (also `Label.Variant.TITLE` and `STRONG`), and `Borders.selected`, the edge of a selected card. The constructors without them still work and derive them.
- Added text, shaped but not drawn yet. `El.text("…")` makes an element that layout sizes to its text, with `.font`, `.fontSize`, `.color` and `.wrapText`; line feeds always break, and wrapping text breaks between words where it is too wide. `Font` loads a TrueType or OpenType font from bytes or a resource and frees it with `close()`; `Font.shape` turns a string into glyphs with positions through HarfBuzz, with kerning on and contextual alternates off, rounded to whole physical pixels below scale 1.5 and to quarter pixels from there. The new artifact `rethinkj-ui-fonts` carries the default fonts, Inter and JetBrains Mono in regular and bold (SIL Open Font License 1.1), for `Font.sans()` and `Font.mono()`. A text element shows in the tree dump as `text` with its string in quotes, and scripts select it with `text="…"`. `Measure` gains `placed`, which layout calls with the final content size. Text needs FreeType and HarfBuzz, so far only in `rethinkj-ui-natives-linux-x64`.
- Text is drawn. Glyphs are rasterised by FreeType into greyscale bitmaps, kept in a `text.Atlas` of 8-bit pages and drawn one texel per physical pixel, snapped to the pixel grid, by `CpuRenderer`; the GPU renderer does not draw them yet. `Scene` gains glyph instances in the same ordered list as rectangles, told apart by the slot at byte 28, which was unused and stays 0 for rectangles, plus `getInt`, `pages()` and an `of` that takes an atlas and a `TextRendering`. `TextRendering` sets the hinting and the coverage correction that keeps text blended in linear light from looking too thin or too heavy, with defaults for Linux and Windows; set it with `App.textRendering` or a new `Headless.render` overload. The correction depends on whether text is darker or lighter than its background, which the scene takes from the fills of the element and its ancestors; `El.textBackground` states it where that is wrong. Text in a box with opacity, in a scroll area, leaving with `motion`, and the text colour of an element with `motion`, which now springs, work as they do for boxes.
- Added single-line text fields: `El.text(value).editable(onEdit)`. The string stays in the app's state and every edit hands the new one to `onEdit`; an app may refuse or change an edit, and the field then shows the app's string with a sensible caret. The app keeps caret, selection, horizontal scroll, a bounded undo history and an input method's composition per element. The caret moves by graphemes and, with Control, by words; the usual keys of Windows and Linux edit, select, cut, copy, paste, undo and redo, while Enter, Escape and Tab go on to `onKey` handlers; the pointer places the caret, drags a selection, and selects a word on a double press and everything on a triple one. Caret positions follow kerning and fall inside ligatures in proportion. The caret blinks on the app's clock (`App.BLINK`, `App.nextChange`). Also `.readOnly()`, `.maxLength(codePoints)`, `.placeholder(text, argb)`, `.caretColor(argb)`, `.selectionColor(argb)`, and `.fontFeatures(...)` for any text element.
- Added `Clipboard` and `App.clipboard()`: an in-memory clipboard by default, the system's in a `WindowLoop`. Added `App.pointerDown(x, y, clicks, modifiers)`, `App.textComposition(text, cursor)` and `App.inputArea()`.
- Windows: text input is now off unless the focused element takes text, so an on-screen keyboard appears only for a field; `Window.textInputArea` and `Window.stopTextInput` control it, and `WindowLoop` does so after each frame. Compositions of input methods arrive as `WindowEvent.TextEditing` and are drawn by the app. `WindowEvent.PointerDown` reports the modifiers held. An idle `WindowLoop` wakes for the caret's blink.
- Scripts: `press` and `down` take `clicks <n>` and the modifiers held, `compose "<text>"` shows an input method's composition, `clipboard "<text>"` sets the app's clipboard, and `snap` also writes `<name>.clipboard.txt` when the clipboard holds text. A focused field's line in a `.tree.txt` ends with its caret, as in `focused caret 5 anchor 2`.
- Text fields work in the rows of a virtual list, and the GPU renderer draws them. A field in a row keeps its caret, selection and undo history by the row's index while the row exists. When a row scrolls out, its fields' state goes with it, except the focused field's, which stays with the focus and is there again when the row comes back; only an input method's composition ends.
- Added multi-line text fields: `El.text(value).editable(onEdit).multiline()`. The string holds a line feed per line break (carriage returns and U+2028/U+2029 from the app, typing and pasting become line feeds), and the field scrolls as a scroll area of its own, with the wheel and with `El.scrollbars`. Enter breaks the line and Control+Enter goes on to the `onKey` handlers; Up and Down move by rows on screen and keep their column, Page Up and Page Down by the rows in view, Home goes to the start of the row and a second Home to the indent, Control+Home and Control+End to the ends; a third press selects a line with its line feed, a fourth everything. `wrapText(boolean)` wraps the lines at the field's width or lets the field scroll sideways, `lines(n)` makes it n lines high when its style gives no height, `tabSize(n)` sets the tab stops, and `tabIndents(spaces)` makes Tab and Shift+Tab indent and outdent instead of moving the focus (Escape and then Tab, or Control+M, leave). Only the rows in view are shaped and laid out, so a text of 100 000 lines costs a frame what the lines in view cost; an edit still hands the app a new string. Masked fields cannot be multi-line.
- The undo history of every text field now keeps what each edit replaced instead of a copy of the whole string per step.
- The tree dump writes a text's string whole up to 200 characters and a longer one as its first 100 and its last 40 with its length (`"…" … "…" length 104857`), also in `Script`'s errors, and writes a tab as `\t`, which `text="..."` and `type "..."` read. A multi-line field adds the lines in view (`lines 12-20/100000`) and the caret's line and column (`caret 57 (3:12)`).
- `El.textAlign(Style.Align)` aligns each line of a text at the start, in the centre or at the end of its box, also wrapped text and lines shortened with an ellipsis. `Text.Line` has the line's start `x` and the colours of its glyphs.
- `window.attention(Window.Attention)` flashes the taskbar button, and `window.badge(icon, description)` shows a small icon over it on Windows, such as a count from the kit's `AppIcon.count`.
- Fixed the height of a virtual list (`El.rows`) whose rows are together more than 2^24 pixels tall, about 760,000 rows of 22 pixels: layout gave it a height that was off by a pixel at a million rows and by tens of pixels at a hundred million, so that it stuck out of its parent. This also left the data grid's list of a million rows a pixel short, with a strip at the bottom. Layout now counts such a list as at most `El.LAYOUT_LIMIT` (2^20) pixels tall, and a list that nothing gives a height is at most that tall and scrolls through the rest; scrolling still reaches the last row, and rows move by whole pixels there.
- **Breaking:** `Tabs.tabs` returns a card whose first row is the tab bar: the active tab has a line in the accent's edge instead of a raised fill, and the content fills the card edge to edge. A `Tab` can carry an icon (`tab.icon(Symbol.TABLE)`).
- Added what tables need to core: `El.onPress((clicks, modifiers) -> …)` is told the modifiers held at the press; `El.onPointerDown` runs as the button goes down, without taking the press or drag from an ancestor; `Drag.x()` and `Drag.y()` say where the pointer is in the dragged element's content, its scroll included; `El.fixedX()` keeps an element in place while its scroll area scrolls sideways; `El.rows(count, rowHeight, (index, from, to) -> row)` builds rows for the part in view sideways and builds them anew when scrolling sideways goes beyond it; `El.reveal(key, x, y, width, height)` keeps a rectangle of a scroll area in view whenever its key changes; `El.onRowsBuilt` tells the app which rows a list built when they change; and `El.current(boolean)` marks the current item of a set, `current` in the tree dump and in selectors. `Drag` has two more components, so code that constructs one changes.
- An app that turns on the system's fonts (`App.systemFonts(true)`, which a `WindowLoop` does) now reads them on a virtual thread at once (`Font.prepareSystemFonts`), so that the first character that needs one no longer stalls its frame for the scan: 0.2 s with the font files cached and about a second without on Windows.
- `Window.systemAppearance()` says whether the system is light or dark, its accent colour and whether high contrast is on; `WindowEvent.AppearanceChanged` and `WindowLoop.appearance(handler)` pass each change to the app, which chooses its theme from it.
- Added springs in the new package `com.rethinkj.ui.motion`. `Spring` is set by duration and bounce, as in SwiftUI, and gives position, velocity and rest time in closed form, the same on every platform; its presets are rune's motion tokens. `Track` animates one number and can change its target mid-movement without a jump.
- Added `Split.split` and `Tabs.tabs` to `rethinkj-ui-kit`, the frame of a tool such as a database manager. A split puts two parts side by side or one above the other with a line between them that the user drags, moves with the arrow keys while it has the focus, and puts back with a double press; the app keeps the line's `Split.Position`, which says what keeps its size when the split grows: the first part's pixels, the second's, or their share. Both parts keep a minimum, also when the window is smaller than the position allows, and the position is kept for when there is room again. Tabs show a bar of titles over the content of the active tab, with a dot for a modified tab and a cross that closes one; the bar scrolls sideways when the titles do not fit and shows the active tab whenever it changes. Left, Right, Home and End choose tabs while the bar has the focus, and Control+Tab, Control+Shift+Tab, Control+W and Control+F4 work from anywhere inside. `Theme.Sizes` gained `handle`, the width of the strip that takes the pointer around a split's line, and `step`, how far an arrow key moves it; its canonical constructor takes them after `field`, and the five-size constructor gives 7 and 16.
- `Split` and `Tabs` fill the room they are given and take no minimum size from their content: a tree, a data grid or another list of rows in a part or a tab scrolls inside it, also when the split or the tabs grow in a column, where they used to become as tall as the whole list. A split's parts have no minimum size of their own either.
- `Slider`: a press on the track puts the knob there; before, only a drag moved it. Enter and Space on a focused slider do nothing.
- Shift with a wheel that turns only up and down now scrolls sideways, towards the user to the right, as in Windows' own apps and GTK's: `WindowEvent.Wheel` arrives with `dx` instead of `dy` while Shift is held.
- Added shadows: `El.shadow(Shadow...)` draws one or more blurred copies of an element's rounded rectangle under it, as CSS's `box-shadow` does (offset, blur, spread and colour, the first on top), clipped like the element and faded with its opacity. They take no room and no input, and both renderers compute the blur per pixel, with no offscreen pass.
- Added `Select.select(theme, choices, selected, state, onSelect)` to the kit: a button with the current choice that opens a `Menu` of the choices below it, at least as wide as itself.
- Changed the keys of the kit's `Select` while it is closed: Arrow Down and Arrow Up choose the next and the previous choice instead of opening the list, Home and End the first and the last, a letter or digit the next choice that starts with it, and Alt+Arrow Down or Alt+Arrow Up open the list (and close it again).
- Added the secondary (right) button: `El.onSecondaryPress((x, y) -> ...)` runs with the position of the release, as for a context menu, and the Menu key and Shift+F10 run it for the focused element. `App.secondaryDown` and `secondaryUp` take the button, `WindowLoop` passes the right button to them, and scripts write `press <target> right`.
- Added scrollbars. `El.scrollbars(Scrollbars)` gives a scroll area or a list of rows a bar along each axis whose content does not fit, drawn over the content at the edges of the area's visible part, with a thumb whose length is the share in view and whose place is the offset. Dragging the thumb scrolls in proportion, from the first pixel and from the first to the last of a million rows; a press on the track beside it scrolls a page; the thumb changes colour under the pointer and while dragged. A press on a bar reaches nothing under it and leaves the focus alone. `El.horizontalBar()` and `El.verticalBar()` give where the bars are, and a tree dump shows each thumb as `thumb-x` or `thumb-y` on the area's line. The kit's `Theme` has a new group, `scrollbars()`, for `.scrollbars(theme.scrollbars())`, and `DataGrid` shows bars for its rows and columns.
- Scroll areas with scrollbars scroll their last row and column out from under a bar that crosses them: past the strip of their own bar along the other edge, and past the bar of an area around them that lies along their bottom or right edge, as the rows of a data grid scroll past the grid's bar. `El.revealRow`, `El.reveal` and scrolling the focused element into view show it clear of those bars. `DataGrid` leaves room for its rows' bar after the last column, so the last row and the last column of a grid scroll clear of both bars, and the column of the cursor stops clear of the rows' bar. Areas without scrollbars scroll as before.
- Added clipping and scrolling. `El.clip()` draws an element's children only inside its rounded rectangle, with a smoothed edge, and what it clips away takes no input; any `overflow` other than visible now clips. `El.scroll()` and `El.scrollBoth()` make a scroll area whose children keep their natural size; `App.wheel(x, y, deltaX, deltaY)` scrolls the innermost area under the pointer that can still move, `App.scrollTo(area, x, y)` sets the offset, and `El.scrollX()` and `El.scrollY()` read it. `App` keeps the offset across rebuilds by the element's key or position. `El.x()` and `El.y()`, `El.dump()` and hit testing show the scrolled positions, and `dump()` adds `scroll x,y` to a scrolled area. `Script` has the step `wheel <target> <deltaX> <deltaY>`, and its selectors skip elements that are clipped away. `Scene` has a clip table (`clips()`, `clipOf`, `clipGet`) that each instance refers to by index in its formerly unused slot at byte 24.
- Added `Script`, which drives an `App` without a window from a plain-text script: `size`, `press`, `down` and `up` on a position or on an element selected by `#key`, `role=` and `label=`, `advance`, `frame`, and `snap`, which writes the frame's PNG and tree. Only `frame` runs a frame. Errors name the line and say what to write instead. `Script.handle(args, app)` gives an app's `main` the options `--script <file> --out <folder>`.
- Fixed the rows of a virtual list (`El.rows`) that scrolling, a moving list or the focus builds: they take their `whenHovered`, `whenFocused` and `whenPressed` looks in the frame that builds them, as rows built with the view do, without the view being built again for it. The row under the pointer is found after the rows are laid out, so after a scroll it is the one that is under the pointer now, and a row whose look changes its layout is laid out again.
- The focus ring no longer disappears where an element is flush with the edge of a pane, a scroll area or the window: where a clip or the window's edge would cut the ring outside the element, it lies just inside the element's border box instead, whole. Rings with room around them stay where they were.
- `El.revealRow(index)` now also works on a scroll area that is not a list of rows, where it keeps the child with that index in view whenever the index changes. A wheel that turns only up and down scrolls an area that scrolls only sideways (`overflow-x: scroll` without `overflow-y: scroll`), such as a row of tabs, sideways.
- The resize margin of a frameless window gives way to controls: where a press would go to an element with a press or drag handler, a text field, a scrollbar or a title bar button, it narrows to `Window.CONTROL_MARGIN` (2 pixels), so that a scrollbar along the window's edge can be grabbed at its outer pixels while the rest of the edge resizes as before. `App.windowPart` reports such places as the new `WindowPart.CONTROL` instead of `CONTENT`.
- Changed `El.whenPressed` on a text field: the look now applies while a press selects in the field, from the pointer down to the pointer up, as CSS's `:active` does, and `App.pressed()` returns the field meanwhile; before, a field never showed it. Elements around the field still do not count such a press as theirs. The kit's text field has no pressed look; the focus look a press gives it is its feedback.
- `El.onPress((clicks, modifiers, x, y) -> …)` and `El.onPointerDown` of the same form tell a press handler where the pointer was, in the element's content as `Drag.x` and `Drag.y` are; Enter and Space give the middle of the element. `El.onPress()` and `El.onPointerDown()` now return this richer `El.PressAtHandler`.
- The kit's buttons, toggles, checkboxes, selects, tab bar and split dividers no longer take the keyboard focus when pressed: Tab still reaches them and Enter and Space press them, but a press or a drag leaves the focus, and its ring, in the editor or grid they act on (`El.keepFocus()` on a focusable element). Text fields, the data grid, the tree and menus still take it. A menu opened from a button gives the focus back to where it was before the press.
- Added `El.onPress(IntConsumer)`, a press handler that is told how many presses in quick succession the press completes: 1 for a single press, 2 for the second of a double press, and so on; Enter and Space give 1. `El.onPress()` now returns that `IntConsumer`; `onPress(Runnable)` is unchanged.
- Added `El.opacity(float)`, from 0 to 1, for an element and everything below it; it springs with `El.motion`. An element with motion now fades in when it appears after the app's first frame, and one with a key and motion that a rebuild leaves out fades out where it was before it is removed. Until then it stays in the tree with `El.isExiting()` true, takes no input, takes no part in layout, and its line in `El.dump()` ends in `exiting`. If it comes back first, it goes on from where it is. Elements at opacity 0 take no presses.
- Added a way back from other threads, so that a slow query does not stop the window. `App.post(Runnable)`, the one method of `App` that any thread may call, queues a task that runs on the app's thread at its turn among the input, as the handler of an input, and a `WindowLoop` wakes for it at once. `App.background(name, compute, onResult, onFailure)` runs a computation on a virtual thread and delivers its result or failure on the app's thread; the returned `Work` cancels it, after which nothing arrives. `App.await(Duration)` and the script step `await` wait for that work, and a script lets posted tasks in only there, so scripts and tests show the same however fast the work is.
- Added the pointer's position, looks for hovered, focused and pressed elements, and cursors. `App.pointerMove(x, y)` and `App.pointerLeave()` tell the app where the pointer is, and `App.hovered()`, `App.pressed()` and `App.cursor()` say what is under it, what a press is on and which shape it asks for. `El.whenHovered`, `El.whenFocused` and `El.whenPressed` take a function that changes an element's look and layout properties while it is in that state (hovered also while the pointer is over an element inside it); the app applies them to each tree the view builds, before layout, in that order, they spring with `motion`, and a change of state rebuilds the view only when an element involved has such a look. A look that changes children, key, handlers or `focusable()` fails. `El.cursor(Cursor)` sets the pointer's shape for an element and those inside it, from the new `Cursor` enum (`DEFAULT`, `POINTER`, `TEXT`, `NOT_ALLOWED`, `EW_RESIZE`, `NS_RESIZE`, `NWSE_RESIZE`, `NESW_RESIZE`). `WindowLoop` now passes pointer moves, leaving and the wheel to the app, a wheel step as `WindowLoop.WHEEL_STEP` (48) logical pixels with fractions kept and rolling towards the user scrolling down, and shows the app's cursor with the new `Window.cursor(Cursor)`, except over a frameless window's resize margin, where the system's resize cursors stay. A press now survives rebuilds that shift child indexes: the app finds the pressed element by its key or position, as for animation and focus. `El.dump()` ends the line of the element that a press under the pointer would go to with `hovered`, and `Script` has the steps `move <target>` and `leave`.
- Sharp edges at fractional scales such as 125, 150 and 175 %: the scene puts the edges of boxes at rest on whole physical pixels, borders, separators and the focus ring are whole pixels wide (a hairline of 1 logical pixel is 1 physical pixel at 1.5), clips, shadows, scrollbar thumbs and the text inside a box follow the snapped box, and what fills a bordered box meets its border without a gap. Boxes that a spring moves stay between pixels until they rest (`El.isMoving`). `Scene.of(root, scale)` and `Scene.of(root, ring, ringColour, atlas, rendering, scale)` build such a scene; at scales 1 and 2 nothing changes.
- Added masked text fields for passwords: `El.text(value).editable(onEdit).masked()` (or `masked(boolean)`, set on every build, so an app shows the password by building the field without it) shows one `Text.MASK` bullet per grapheme, or the character of `.maskCharacter(c)`. The theme has a new token group, `Theme.Grid`, for row height, minimum column width, resize handle and the grid's backgrounds; `Theme` records made with the constructor need it as their last argument.
- Added rendering without a window: `Scene` (the draw list in native memory), `CpuRenderer` (the reference renderer) and `Png` for reading and writing images.
- `CpuRenderer`, which `Headless.render` and the snaps of scripts use, is 9 to 26 times faster (an 800 by 600 rectangle in 5 ms instead of 137, a data grid of 1120 by 480 in 14 ms instead of 216) and draws the same bytes as before.
- The kit has `CodeEditor.codeEditor`, a code area with line numbers, the caret's line and matching brackets highlighted and an error underlined, and `Sql`, a highlighter of SQL and PostgreSQL. `Theme` has a new token group `code` with the colours of code in both themes; the constructor without it picks them by the theme's lightness.
- Added `Radio.radioGroup`, `Segmented.segmented`, `NumberField.numberField` with steppers and `Slider.slider`, each one stop for Tab and driven by the arrow keys, and `Callout.callout` and `EmptyState.emptyState` for notes and empty lists.
- **Breaking:** `Card`'s variants lie on the panel's surface, and an outlined card is lifted by `Theme.Elevation#card`. New: `Card.flush` for parts edge to edge, such as a data grid, with `Card.toolbar`, `Card.footer` and `Card.inset`; `Split.cards` for two cards side by side on the window; `Button.button` with an icon before its text and `Button.icon` with an icon alone and a tooltip; `TextField.withIcon`; `Font.sansMedium()` and `Font.sansSemibold()`. The data grid has a header band, row hairlines and no column lines, menus highlight with the selection's tint, and the tree's rows are rounded.
- `El.autofocus()` makes an element take the keyboard focus in the build of the view that adds it, such as an editor that a key lays over a grid's cell, and inside an overlay names the element its opening focuses instead of the first focusable one, such as a dialog's second field. `El.autofocus(key)` also takes the focus whenever a build gives the element another key, such as the first field with an error after each Save. A focus that has lost its element prefers an `autofocus` element around it.
- Added `App`, which runs a view from a state object, and `El.onPress`: input queues handlers, `App.frame` runs them and rebuilds the view. It needs no window.
- `Window.identity(id, name)`, called before the first window, gives the app its own taskbar button on Windows (an AppUserModelID, so it no longer groups with every Java program) and its app id and window class on Linux.
- `App.after(seconds, action)` runs an action on the app's thread once the app's clock has moved on by that much, so that an app can change its state later without input or another thread: a delay, a timeout. It runs as a posted task does, in the first frame that begins at or after its time, after the input and the tasks that came before that frame, and the view is built again before the next input. `App.nextChange()` includes it, so a window wakes for it; in a script `advance` and `frame` run it, and `await` does not wait for it.
