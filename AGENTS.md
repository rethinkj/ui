# rethinkj UI

A native, GPU-rendered UI framework for Java, modelled on [rune](https://github.com/anomalyco/rune) (Rust, MIT): its own renderer, text, layout and animation, plus a headless mode in which an agent renders to PNG, dumps the element tree and drives an app with scripted input.

- Repository: https://github.com/rethinkj/ui
- Documentation for users: https://ui.rethinkj.com, its source in `docs/`
- License: MIT

This file holds the rules for working on the repository, and nothing else. What the framework does is in the code, its Javadoc and the documentation site. Do not describe features, findings, measurements or your own work here; the file changes only when a rule changes.

## Targets

- Desktop only: Windows 11 or later and Linux. macOS, web and mobile are not targets.
- Runs on an ordinary JRE. GraalVM native image is not a goal, but it has to stay possible. That means:
  - `core` and `kit` depend on `java.base` only. No `java.desktop`: no AWT, no ImageIO, no `java.awt.Font`.
  - No reflection, dynamic proxies or classes generated at run time, in this code or in anything it depends on at run time.
  - Native code is called through the Foreign Function & Memory API only, not JNI or JNA. Every native function's descriptor is a `static final` constant, so it can be registered for native image.
- Rendering without a window must not need the native libraries: never call `Natives` from a static initialiser that the headless path can reach.

## Modules

| Directory | Artifact | Purpose |
| --- | --- | --- |
| `core/` | `rethinkj-ui-core` | The framework itself, package `com.rethinkj.ui` |
| `kit/` | `rethinkj-ui-kit` | Theme and components built on `core`, package `com.rethinkj.ui.kit` |
| `natives-<platform>/` | `rethinkj-ui-natives-<platform>` | SDL3, wgpu-native, FreeType and HarfBuzz for `windows-x64` and `linux-x64`; no Java code |
| `fonts/`, `icons/` | `rethinkj-ui-fonts`, `-icons` | The default fonts and the icon font; no Java code |
| `examples/` | not published | Runnable apps, written as a user of the library writes them |
| `docs/` | not a Maven module | The documentation site, a Node project of its own |

Dependencies point one way: `kit` depends on `core`, never the reverse.

## Build

Requires JDK 25 and Maven 3.9+. What the first build needs for the native libraries is on the site's page `docs/content/docs/reference/platforms.mdx`.

```sh
mvn verify                        # build and test everything
mvn -pl kit -am verify            # one module plus the modules it depends on
mvn verify -P '!natives-<platform>'   # without the native libraries; tests that load them skip
mvn spotless:apply                # format; mvn verify fails on a file that is not formatted
```

The site, with Node 24 in `docs/`: `npm ci`, then `npm run build`.

## Tests

- Keep tests few and fast. A test earns its place by failing when behaviour a user can notice breaks. No benchmarks and no timing printouts in the test suite, no tests of tests, and no second test for what another already covers.
- Image tests compare a script's snaps with the PNG and tree files under `<module>/src/test/resources/golden`. Store an image at one theme and one scale unless the theme or the scale is what the test is about.
- After a deliberate change of the output, rewrite the stored images with `mvn -pl <module> -am test -Dgolden.update=true` and look at them before committing. A failing image test leaves the expected image, the actual one and their difference in `<module>/target/golden`.
- Tests that open real windows run only with `-Dwindows.tests=true`. Do not add such a test to the default build, and do not run them on a machine somebody works at unless asked.
- The steps of a script and the format of a tree dump are on the site, under `docs/content/docs/testing`.

## Rules the code does not show

- `GpuRenderer.WGSL` and `CpuRenderer` draw the same pixels by the same formulas. Change them together.
- Renderer code uses only the safe layer of `com.rethinkj.ui.gpu`: wgpu-native ends the process where WebGPU would report an error. After adding or changing a struct, function or callback of the raw layer, run `scripts/LayoutCheck.java`.
- A kit component is a static function whose first parameter is the theme, and it reads only tokens: no colour, size or spring of its own. Colour literals live in `Palette.java`, colour arithmetic in core's `Colors`.
- `Symbol.java` is generated by `scripts/GenerateSymbols.java`.
- No binaries are committed. `natives-<platform>/natives.properties` pins each native library; `scripts/FetchNatives.java` fetches and builds them.
- Shared build configuration belongs in the root `pom.xml`. The version is changed with `mvn versions:set -DnewVersion=<version>`.

## Documentation

- The site in `docs/` is the documentation, for people and agents. Keep it short and current: a change that users notice updates the page it concerns in the same pull request, and a new component gets a page under `docs/content/docs/components` and a tile on its index.
- Nothing on a page is written by hand that the build could check: images are the tests' stored images (`<Shot>`), Java code is a snippet from `examples/src/test/java/com/rethinkj/ui/examples/docs`. `docs/scripts/docs.mjs` fails the build on what does not exist.
- What changed goes into the changelog (below). Plans, status, findings and reports go into the issue tracker, never into the repository: no `PLAN.md`, `SUMMARY.md`, `VALIDATION.md` or review notes, and nothing of the kind in this file.

## Changes

- Nobody pushes to `main`. Work on a branch from `origin/main`, push it and open a pull request on GitHub. It is merged by squash once its checks pass.
- One pull request per topic, small enough to review. Its description says what changed and why, in a few sentences.
- Commit messages and pull request titles follow [Conventional Commits](https://www.conventionalcommits.org/): `<type>(<scope>): <summary>`, for example `feat(core): add text shaping`. The scope is the module when the change stays in one. A breaking change gets `!` before the colon. The subject has at most 72 characters; a body only when the diff does not show why.
- A change that users of the library can notice (new or changed API, changed behaviour, a fix, a raised requirement) adds `changelog/unreleased/<YYYY-MM-DD>-<slug>.md` with one top-level bullet written for those users. These files are folded into `CHANGELOG.md` at release.

## This repo is public

Everything pushed stays public in history. Before committing, run `git diff --cached | grep -nE '/home/|/Users/|/private/var/|\.ts\.net|ses_[A-Za-z0-9]{20}'` and keep these out:

- secrets, tokens and credential file contents;
- home folder and temp paths, machine names and tailnet hostnames. Write repo-relative paths, and use `host.example.ts.net` in tests;
- session IDs, chat or Slack links, and quotes from private sessions, chats or calls;
- issue numbers, links and suggested branch names from a private issue tracker;
- teammates' names attached to their plans, opinions or internal discussions, and private repos or branches;
- quotes of, or citations to, internal guides and rules. Say what the code does and why on its own terms;
- agent handoff notes, raw evidence, logs and benchmark dumps;
- generated videos and strips nothing links to. Commit the stills a doc shows.
