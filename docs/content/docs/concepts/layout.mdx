Everything on screen is an `El`: a box (`el()`), a horizontal row (`row()`), a vertical column (`col()`), text (`text("…")`), or an image (`El.image(image)`). Builder methods chain fluently and layout follows CSS flexbox rules. For the full API, see [`El`](/api/com/rethinkj/ui/El.html) and [`Style`](/api/com/rethinkj/ui/Style.html).

## Sizing

| Method | Description |
| --- | --- |
| `w(px)`, `h(px)`, `size(w, h)` | Fixed width/height in logical pixels |
| `wFull()`, `hFull()` | Fill parent's content width or height |
| `minSize(w, h)`, `maxSize(w, h)` | Size constraints (`minSize(0, 0)` lets text shrink inside flex containers) |
| `grow(factor)`, `shrink(factor)`, `basis(px)` | Flex grow, shrink, and base size along the parent's main axis |

Note: `Len.pixelsOrZero()` returns a fixed pixel value, or `0` for percentages, `AUTO`, and `FIT_CONTENT`.

## Spacing and alignment

| Method | Description |
| --- | --- |
| `padding(all)`, `padding(vertical, horizontal)`, `padding(top, right, bottom, left)` | Inner spacing |
| `margin(...)` | Outer spacing |
| `gap(px)` | Space between child elements |
| `align(Style.Align)`, `alignSelf(...)` | Cross-axis alignment (`START`, `CENTER`, `END`, `STRETCH`) |
| `justify(Style.Content)` | Main-axis alignment (`START`, `CENTER`, `END`, `SPACE_BETWEEN`, …) |
| `center()` | Centers children on both axes |
| `wrap()` | Wraps children onto multiple lines |
| `absolute(left, top)` | Positions element relative to parent, outside normal flow |
| `follow(key)` | Used with `absolute`: aligns along the parent's axis to the sibling with that key; with `motion`, slides smoothly when the key changes (like an active tab indicator) |

## Visual styling and scrolling

| Method | Description |
| --- | --- |
| `fill(argb)` | Background color (`0xAARRGGBB`) |
| `radius(px)`, `radius(tl, tr, br, bl)` | Rounded corner radius |
| `border(width, argb)`, `border(top, right, bottom, left, argb)` | Border width and color |
| `borderColors(top, right, bottom, left)` | Sets a separate color for each border side (call after `border(...)`) |
| `shadow(Shadow...)` | Drop shadows (like CSS `box-shadow`) |
| `opacity(value)` | Element opacity (`0` to `1`) |
| `arc(start, sweep)` | Draws only an arc of the fill and border (such as a ring or pie), measured in turns clockwise from the top |
| `segments(Segment...)` | Draws straight lines over the fill (see [Drawing lines](#drawing-lines)) |
| `clip()` | Clips children to the rounded border box |
| `scroll()`, `scrollBoth()`, `scrollbars(look)` | Enables vertical or 2D scrolling with optional scrollbars |
| `fixedX()` | Freezes an element horizontally inside a horizontal scroll area (for frozen table columns). Place it after scrolled elements and give it an opaque fill |

Prefer theme tokens (`theme.surface().panel()`, `theme.text().muted()`) over raw hex colors (see [Themes](/docs/concepts/themes)).

## Drawing lines

`segments(...)` draws anti-aliased straight lines inside an element (for example, diagram edges or chart lines). Each [`Segment`](/api/com/rethinkj/ui/Segment.html) runs from `x1, y1` to `x2, y2`, measured in pixels from the element's top-left corner. Every segment has a width, a color, and round ends:

```java snippet="lines"
```

<Shot src="examples/docs/lines/view-{theme}" alt="A rounded card with a line chart of six points rising from left to right over a thin axis" />

- Lines draw over the element's fill and under its text and children.
- Lines are clipped just like children, so `clip()` keeps them inside the element's box.
- Lines do not receive clicks. The element's box handles clicks instead.
- A horizontal or vertical line is sharpest when its edges land on physical pixel boundaries. At scale 1, put a 1-pixel line at `y = 70.5`. At a whole number, it spreads across two rows.

## Scrollbars

`scrollbars(look)` adds overlay scrollbars whenever content overflows. Dragging the thumb scrolls smoothly; clicking the track scrolls by one page without moving keyboard focus. Pass `theme.scrollbars()` or a custom [`Scrollbars`](/api/com/rethinkj/ui/Scrollbars.html):

| Field | Description |
| --- | --- |
| `thickness` | Bar thickness in pixels (must be > 0) |
| `margin` | Margin from container edges (hit area width is `thickness + 2 * margin`, returned by `look.strip()`) |
| `radius`, `minThumb` | Thumb corner radius and minimum thumb length |
| `thumb`, `thumbHovered`, `thumbDragged` | Thumb colors for default, hover, and drag states |

After layout, `el.horizontalBar()` and `el.verticalBar()` return `Scrollbars.Bar` geometry (or `null`). Tree dumps list thumbs as `thumb-x` and `thumb-y`.

On a multi-line field, `scrollMarks(List<Scrollbars.Mark>)` adds marks for ranges of its text, drawn as ticks along the vertical bar under the thumb; each call adds to the marks of the calls before. A press on a tick scrolls its line into the middle of the view. `el.verticalTicks()` returns the ticks as placed.

## Custom measurement

Use `El.measure(measure)` for leaf elements that compute their own size dynamically:

```java snippet="measure"
```

[`Measure`](/api/com/rethinkj/ui/Measure.html)`.measure(knownWidth, knownHeight, availableWidth, availableHeight)` returns `Measure.Size(width, height)` (or `Size(width, height, baseline)` for `BASELINE` alignment). Unknown sizes are `NaN`; available sizes are pixels, `Measure.MAX_CONTENT`, or `Measure.MIN_CONTENT`. Override `placed(width, height)` to react to the final resolved size.

## Reacting to element size

`el.onResize((width, height) -> …)` notifies your app whenever layout gives an element a new size (similar to CSS `ResizeObserver`). For example, [Toolbar](/docs/components/toolbar) uses this to move overflowing buttons into a menu.

- Fires on the first build and whenever the element's laid-out size changes.
- Runs like an event handler right after layout, then rebuilds the view before the frame ends (up to three times). As a result, the first frame at a new size already shows the updated layout.
- Keep the element's size independent of its own contents (e.g., `wFull()`) to avoid resize loops.
- Not called inside virtual list rows (`rows`) or during intermediate animation frames (`motion`).

## Logical pixels and scaling

All coordinates and sizes use logical pixels. Display scaling (1×, 1.25×, 1.5×, 2×, …) converts them to physical pixels automatically, snapping edges to whole pixels for sharp rendering.

## Adding children

Use `child(el)` for one child or `children(el...)` for multiple. `null` children are safely ignored, so `condition ? element : null` works cleanly. Later children draw on top of earlier ones.
