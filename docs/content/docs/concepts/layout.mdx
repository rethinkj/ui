Everything on screen is an `El`: a box (`el()`), a row (`row()`), a column (`col()`), a text (`text("…")`) or an image (`El.image(image)`). Calls chain and return the element, so a view is one expression. Layout is flexbox, as in CSS. This page shows the calls a view needs most; all of them are in the Javadoc of [`El`](/api/com/rethinkj/ui/El.html) and [`Style`](/api/com/rethinkj/ui/Style.html).

## Size

| Call | |
| --- | --- |
| `w(px)`, `h(px)`, `size(w, h)` | A fixed size in logical pixels |
| `wFull()`, `hFull()` | As wide or high as the parent's content box |
| `minSize(w, h)`, `maxSize(w, h)` | Limits; `minSize(0, 0)` lets text shrink below its width |
| `grow(factor)`, `shrink(factor)`, `basis(px)` | How an element takes and gives room along its parent's axis |

## Space and alignment

| Call | |
| --- | --- |
| `padding(all)`, `padding(vertical, horizontal)`, `padding(top, right, bottom, left)` | Inside the border |
| `margin(...)` | Outside |
| `gap(px)` | Between children |
| `align(Style.Align)`, `alignSelf(...)` | Across the axis: `START`, `CENTER`, `END`, `STRETCH` |
| `justify(Style.Content)` | Along the axis: `START`, `CENTER`, `END`, `SPACE_BETWEEN`, … |
| `center()` | Both, in the middle |
| `wrap()` | Children wrap onto more lines |
| `absolute(left, top)` | Placed in the parent, out of the flow |

## Look

| Call | |
| --- | --- |
| `fill(argb)` | Background color, `0xAARRGGBB` |
| `radius(px)`, `radius(tl, tr, br, bl)` | Rounded corners, each its own |
| `border(width, argb)`, `border(top, right, bottom, left, argb)` | A border, each side its own width |
| `shadow(Shadow...)` | Shadows, as CSS's `box-shadow` |
| `opacity(value)` | For the element and everything in it |
| `clip()` | Cut children at the rounded border box |
| `scroll()`, `scrollBoth()`, `scrollbars(look)` | A scroll area, up and down or both ways, with bars |
| `fixedX()` | Does not scroll sideways with the nearest horizontal scroll area, but scrolls up and down with it: frozen table columns. Put it after what it covers in the tree and give it a fill |

Colors are `int`s in ARGB. Prefer the theme's tokens (`theme.surface().panel()`, `theme.text().muted()`) to literals ([Themes](/docs/concepts/themes)).

## Scrollbars

`scrollbars(look)` gives a scroll area a vertical bar while its content is taller than the area and a horizontal one while it is wider, drawn over the content. Dragging the thumb scrolls; a press on the track scrolls a page and does not move the focus. Pass the kit's `theme.scrollbars()`, or your own look:

| [`Scrollbars`](/api/com/rethinkj/ui/Scrollbars.html) | |
| --- | --- |
| `thickness` | The width of a vertical bar and the height of a horizontal one, above 0 |
| `margin` | The space between a bar and the area's edges, and between the two bars; presses land on the strip of `thickness + 2 * margin` along the edge |
| `radius`, `minThumb` | The thumb's corner radius, and the shortest it gets however long the content |
| `thumb`, `thumbHovered`, `thumbDragged` | The thumb's colors at rest, under the pointer and while dragged |

`look.strip()` is that strip's width in logical pixels; use it to leave room beside a bar for controls or an overlay.

After a frame, `el.horizontalBar()` and `el.verticalBar()` return each bar as shown, or null: a `Scrollbars.Bar` with the track's and the thumb's rectangles in window coordinates (`trackX`, `trackY`, `trackWidth`, `trackHeight`, `thumbX`, …) and the thumb's current color. A tree dump writes the thumbs as `thumb-x` and `thumb-y`.

| `Style` field | Values |
| --- | --- |
| `width`, `height`, `minWidth`, `minHeight`, `maxWidth`, `maxHeight`, `basis` | A `Len`: `Len.px(pixels)`, `Len.percent(fraction)` of the parent's content box, where 1 is all of it (`Len.percent(0.5f)` is 50 %), `Len.AUTO`, `Len.ZERO`, or `Len.FIT_CONTENT`: as large as the content and never stretched by the parent's `STRETCH` |
| `aspectRatio` | Width divided by height, NaN when unset: the axis without a size follows the other. A set height is never raised by the ratio |
| `rowGap`, `columnGap` | The gap between lines of wrapped children and between the children of a line; `gap(px)` sets both |
| `direction` | `ROW`, `COLUMN`, `ROW_REVERSE`, `COLUMN_REVERSE`; `row()` and `col()` set the first two |
| `wrap` | `NO_WRAP`, `WRAP`, `WRAP_REVERSE` |
| `alignItems`, `alignSelf` | `START`, `END`, `FLEX_START`, `FLEX_END`, `CENTER`, `BASELINE` (the first baselines of the children on one line, as text of several sizes in a row), `STRETCH`; null is CSS's default |
| `justifyContent`, `alignContent` | `START`, `END`, `FLEX_START`, `FLEX_END`, `CENTER`, `STRETCH`, `SPACE_BETWEEN`, `SPACE_EVENLY`, `SPACE_AROUND` |
| `overflowX`, `overflowY` | `VISIBLE`, `CLIP`, `HIDDEN`, `SCROLL`. Any value but `VISIBLE` on either axis clips the children on both; `SCROLL` also lets the wheel scroll that axis (`scroll()` and `scrollBoth()` set it) |
| `boxSizing` | `BORDER_BOX` (the default: a width includes padding and border) or `CONTENT_BOX` |
| `display` | `FLEX` or `NONE`, which leaves the element out of layout and drawing |
| `position`, `left`, `right`, `top`, `bottom` | `RELATIVE` or `ABSOLUTE`, and the offsets from the parent's edges; `absolute(left, top)` sets them |
| `margin…`, `padding…`, `border…` of each side | `Len`s; margins may be `Len.AUTO`, which takes the free room as in CSS |


## Content that sizes itself

`El.measure(measure)` sizes an element without children, as text and images are sized: layout calls it, possibly several times, for the content size under different constraints.

```java snippet="measure"
```

[`Measure`](/api/com/rethinkj/ui/Measure.html)`.measure(knownWidth, knownHeight, availableWidth, availableHeight)` returns a `Measure.Size(width, height)` of the content box in logical pixels, or `Size(width, height, baseline)` with the distance from the top to the first baseline, for `BASELINE` alignment. A known size is NaN where layout has not fixed it; an available size is a number of pixels, `Measure.MAX_CONTENT` or `Measure.MIN_CONTENT`. Override `placed(width, height)` to learn the final size, as text does to break its lines.

## Reacting to the size

`el.onResize((width, height) -> …)` tells the app the size layout gave an element, as a browser's `ResizeObserver` does, so that a view can show what fits. The kit's [Toolbar](/docs/components/toolbar) moves the buttons it has no room for into a menu this way.

- The handler is told in the first build that has the element and whenever a rebuild gives it another size than it told last.
- It runs as an input handler does: after the input of the frame that laid the element out, or in the next frame. Then the view is built and laid out again, which may tell it again, so a view that depends on its own size settles a frame or two later.
- Keep the element's own size independent of what it shows, as a bar that fills its parent; otherwise the two can change each other in turn.
- It is not told inside the rows of a virtual list (`rows`), nor for the sizes an element passes through while it animates (`motion`).

## Pixels and scale

Layout works in logical pixels; a window's scale (1, 1.25, 1.5, 2 …) turns them into physical ones. Boxes at rest snap to whole physical pixels, so edges stay sharp at every scale.

## Children

`child(el)` adds one child, `children(el...)` several; null children are left out, so `cond ? part : null` composes. Children are drawn in order, later ones on top.
