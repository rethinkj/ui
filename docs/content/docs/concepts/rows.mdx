---
title: Lists of many rows
description: Virtual lists that build only the rows in view, for a million rows, with rows of one height or of their own.
---

[`El.rows(count, rowHeight, row)`](/api/com/rethinkj/ui/El.html#rows(int,float,java.util.function.IntFunction)) turns a scroll area into a list that builds only the visible rows and a few around them, so a list of a million rows costs as much as one of twenty. The [DataGrid](/docs/components/data-grid), the [Tree](/docs/components/tree), [Markdown](/docs/components/markdown) and the kit's lists are built on it.

## Variants

| Call | |
| --- | --- |
| `rows(count, rowHeight, index -> row)` | Rows of one height |
| `rows(count, rowHeight, (index, from, to) -> row)` | Rows built for the part in view sideways, for very wide rows such as hundreds of columns |
| `rows(count, RowHeights, index -> row)` | Rows as high as their content; a `RowHeights` in the state estimates the rows not yet built and keeps what was measured |

| Call | |
| --- | --- |
| `revealRow(index)` | Keep this row in view whenever it changes: a cursor |
| `reveal(key, x, y, w, h)` | Keep a rectangle of the content in view whenever the key changes |
| `onRowsBuilt((first, last) -> …)` | Which rows were built, so the app can load their data |
| `scrollState(ScrollState)` | Keep the scroll offsets in the state, so the list comes back where it was |
| `scrollbars(theme.scrollbars())` | Bars that drag and page |
| `app.scrollToRow(list, row)` | Scroll from a handler |

The list needs a height or room to `grow`. Give rows keys (`row-<index>`) so scripts find them; a selector finds only built rows, so a script scrolls first: `scroll #rows row 765432`.

## Rows as high as their content

Log messages, document blocks and wrapping cells each have their own height. `rows(count, heights, row)` lays out each row it builds at the list's width, without `h(...)`, and a `RowHeights` in the state remembers the measured heights. Rows not built yet get the height its function estimates:

- The estimate is in logical pixels, above 0, from what the app knows without layout, such as the length of a row's text. The closer it is, the less the scrollbar thumb jumps as rows are measured.
- A list of a million such rows scrolls as fast as one with a fixed row height.
- When rows above the view turn out higher or lower than estimated, the offset adjusts, so the rows in view stay in place.
- `app.scrollToRow(list, row)` keeps following the row while the rows before it are measured, until the user's next press, key or wheel.
- Heights are kept by index. When rows are inserted or removed anywhere but at the end, or are sorted or moved, make a new `RowHeights`.

`new RowHeights(estimate)` takes an `IntToDoubleFunction` from a row's index to its estimated height. Its other methods, in the [`RowHeights` Javadoc](/api/com/rethinkj/ui/RowHeights.html), tell a row's height, where it starts and which row is at an offset.
