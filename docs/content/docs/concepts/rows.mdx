---
title: Lists of many rows
description: Render lists of up to a million rows efficiently using virtual scrolling.
---

[`El.rows(count, rowHeight, row)`](/api/com/rethinkj/ui/El.html#rows(int,float,java.util.function.IntFunction)) turns a scrollable element into a virtual list. It only builds the visible rows (plus a small buffer), so rendering a million rows is just as fast as rendering twenty. When you scroll, it reuses rows that stay in view when possible instead of rebuilding them. If the list's width is animating with a spring, it rebuilds its rows on each frame so they match the new width. [DataGrid](/docs/components/data-grid), [Tree](/docs/components/tree), and [Markdown](/docs/components/markdown) all use this mechanism.

## Variants and options

| Method | Description |
| --- | --- |
| `rows(count, rowHeight, index -> row)` | Fixed-height rows |
| `rows(count, rowHeight, (index, from, to) -> row)` | Fixed-height rows with horizontal viewport range `(from, to)` for very wide tables |
| `rows(count, RowHeights, index -> row)` | Variable-height rows measured automatically using a `RowHeights` object in your state |

| Helper | Description |
| --- | --- |
| `revealRow(index)` | Scrolls to keep `index` visible whenever it changes |
| `reveal(key, x, y, w, h)` | Scrolls to keep a rectangle visible whenever `key` changes |
| `onRowsBuilt((first, last) -> …)` | Notifies you which row indices were built (useful for lazy data loading) |
| `onRowsInView((first, last) -> …)` | Notifies you when the first or last row fully in view changes (useful for a status line like "Rows 201–223") |
| `scrollState(ScrollState)` | Preserves scroll position across view switches; couple two areas with `ScrollState.scrollWith`, or stay at the bottom with `ScrollState.followEnd()` |
| `ScrollState.atEnd()` / `scrollToEnd()` | Checks whether the area is at its vertical end and scrolls it to the end on the next build |
| `scrollbars(theme.scrollbars())` | Adds draggable scrollbars |
| `app.scrollToRow(list, row)` | Programmatically scrolls to a row from a handler |
| `coverY()` | After layout, returns how much of the list's bottom a horizontal scrollbar covers |

Give the list a height (or `grow(1)`) and give each row a key (such as `row-<index>`). In headless scripts, scroll to a row before clicking it (`scroll #rows row 765432`), since only built rows appear in the tree.

## Variable-height rows


- Pass an estimate function (`IntToDoubleFunction`, > 0 logical pixels) based on what you know before layout (such as text length). Closer estimates reduce scrollbar thumb jumping.
- Scrolling stays smooth even with a million variable-height rows, and scroll positions auto-adjust when rows above the viewport are measured.
- `app.scrollToRow(list, row)` keeps tracking the target row as earlier rows are measured until the user scrolls or clicks.
- **End** and `app.scrollTo(list, x, Double.POSITIVE_INFINITY)` keep the list at its end while its last rows are measured, with or without a `ScrollState`.
- Pass a key function (`new RowHeights(estimate, key)`) returning a unique, stable key per row (such as a message ID) when rows can be inserted, removed, or reordered before the view: measured heights stay with their row and the scroll position moves on the same frame so the row in view does not jump. Without a key, heights stay by index (appending at the end is fine; otherwise create a new `RowHeights`).
- Pass a version function too (`new RowHeights(estimate, key, version)`) when the list sits in an `El.selectionScope()` wrapped with [`Find.find`](/docs/components/find): return a value that changes (by `equals`) whenever anything the row shows as text changes—such as a `MarkdownDocument` or a revision counter—so unchanged out-of-view rows keep their indexed text across builds instead of being rebuilt on every frame.

See [`RowHeights` Javadoc](/api/com/rethinkj/ui/RowHeights.html) for helper methods to query row heights and offsets.

## Following the end

For a chat transcript or log where new entries arrive at the bottom (or the last row grows as an answer streams in), call `followEnd()` on the area's [`ScrollState`](/api/com/rethinkj/ui/ScrollState.html). It works on both plain scroll areas (`El.scroll()`) and virtual lists (`El.rows` with or without `RowHeights`). While the area is at its bottom end, added content and taller last rows keep it there on the same frame. Scrolling away (with the wheel, scrollbar, keys, or `reveal`) stops following; reaching the end again or calling `scrollToEnd()` resumes it.
