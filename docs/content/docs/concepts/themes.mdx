The kit's look comes from [`Theme`](/api/com/rethinkj/ui/kit/Theme.html), a record of token groups: surfaces, text colors, borders, accent, status colors, spacing, radii, type, sizes, motion, elevation, the grid's and code colors, and more. `Theme.DARK` and `Theme.LIGHT` are the defaults; change a group with a `with` method or pick a named accent. Components read only tokens, so a changed theme changes every component at once.

## Providing the theme

Components read the theme from `Theme.CURRENT`, and so does the view's own code, with `Theme.CURRENT.get()`. It is `Theme.DARK` until the app provides another: `app.provide(Theme.CURRENT, state -> theme)` gives the theme to every build of the view and to the rows of its lists, and `Theme.CURRENT.with(theme, () -> part)` to a part of the view, as above, so two themes can be on screen at once. Handlers run outside the view: one that needs the theme reads it from the state.

- A handler that changes `mode` or `accent` rebuilds the view, and every component reads the new theme.
- `WindowLoop.appearance(handler)` calls the handler at the start and whenever the system's setting changes, as a task of the app, so the view is built again. The app above keeps the system's choice in `systemDark` and uses it only in System mode. Nothing follows the system by itself.
- The [`SystemAppearance`](/api/com/rethinkj/ui/window/SystemAppearance.html) it passes holds `scheme()`: `DARK`, `LIGHT`, or `UNKNOWN` where the system does not say, as on a Linux desktop without the portal; `dark()` is false then. `accent()` is the system's accent color as `0xFFRRGGBB` on Windows and 0 on Linux. `highContrast()` says whether high contrast is on; the kit has no theme for it.
- `window.frameDark(dark)` makes a framed window's title bar follow the app's theme on Windows ([Windows, icons and dialogs](/docs/concepts/platform#the-systems-appearance)).

## The groups

| Group | Tokens |
| --- | --- |
| `surface()` | `window` (the page), `panel` (cards), `raised` (controls), `band` (bars inside cards), `hover`, `pressed`, `scrim`, `popup` (menus, lists, the palette, popovers, tooltips, toasts), `highlight` (the item under the pointer or the keys in a popup's list) |
| `text()` | `primary`, `muted`, `disabled`, `onAccent` |
| `border()` | `subtle` (edges of cards, grid lines), `divider` (hairlines that separate content: dividers, menu separators, a group's rows), `control` (buttons, popups, a field's top and sides), `strong` (a field's bottom line, a checkbox's box), `track` and `trackOnAccent` (a spinner's ring, on the surfaces and on a primary button) |
| `accent()` | `color`, `hover`, `pressed`, `selection`, `edge` (lines, rings, the grid's cursor) |
| `status()` | `danger`, `warning`, `success` |
| `space()` | `xs`, `s`, `m`, `l`, `xl`, `xxl` |
| `radius()` | `small` (4), `medium` (6), `large` (10) |
| `type()` | `body` (13), `small` (12: secondary text beside what it is about), `mono` (12), `strong` (13, medium), `heading` (14, semibold: cards), `section` (16, semibold: a section of a page), `dialog` (16, semibold: a dialog's title), `title` (20, semibold: a page) |
| `size()` | `control`, `field`, `icon`, `checkbox`, `stroke`, … |
| `motion()` | `feedback`, `move`, `fade` springs; tooltip and submenu delays; how long a toast stays |
| `elevation()` | Shadows of `card` (the least), `popup`, `dialog` (the most) |
| `grid()`, `scrollbars()`, `code()`, `prose()`, `badge()`, `caption()`, `danger()`, `callout()` | The tokens of the grid, scrollbars, code editor, Markdown, badges, the close button, buttons that destroy (`Theme.Danger`, `withDanger`) and callouts (`Theme.Callouts`, `withCallout`) |

Each group's `with` method returns a changed copy: `withSurface`, `withText`, `withBorder`, `withAccent`, `withStatus`, `withSpace`, `withRadius`, `withType`, `withSize`, `withMotion`, `withGrid`, `withScrollbars`, `withCode`, `withElevation`, `withProse`, `withBadge` and `withCaption`. The tokens of each group are in the Javadoc of [`Theme`](/api/com/rethinkj/ui/kit/Theme.html).

## Accents

`theme.withAccent(Theme.Hue.VIOLET)` picks a named accent: `BLUE` (the default), `VIOLET`, `PURPLE`, `PINK`, `RED`, `ORANGE`, `AMBER`, `GREEN`, `TEAL` or `GRAY`, for example a color per connection or per window. Each hue has a version for dark themes (`hue.dark()`) and one for light themes (`hue.light()`), and `withAccent` picks the one that fits. All of them meet the same contrast as the default accent in both themes. Only the accent changes: the grid's selection, links, the tint of a changed cell and that of a code editor's marked block stay blue.

Your own accent is a `Theme.Accent` of a color and its hover and pressed tones. The selection is then the color at 40 % and the edge (focus rings, the grid's cursor) the color itself; in a dark theme the edge may need a lighter tone, which the five-value constructor takes, to reach 3:1 contrast:

## Colors

A color is an `int`, `0xAARRGGBB` in 8-bit sRGB with straight (not premultiplied) alpha, everywhere: in `El.fill`, `color`, `border`, `Shadow` and the theme. [`com.rethinkj.ui.Colors`](/api/com/rethinkj/ui/Colors.html) creates, reads and mixes them, so code needs no alpha hex digits or bit masks:

```java snippet="colors"
```

| Method | What it does |
| --- | --- |
| `rgb(0x3D6FE6)`, `rgb(red, green, blue)`, `argb(alpha, red, green, blue)` | A color from 24 bits or from channels of 0 to 255; `rgb` makes it opaque, `argb` takes its alpha too |
| `alpha(color, 0.4f)` | The color at that alpha, `round(share * 255)`: 0.4 is `0x66` |
| `hex("#3D6FE6")`, `hex("#663D6FE6")`, `toHex(color)` | Parse from text and format back; a parse error shows the expected form |
| `alpha(color)`, `red(color)`, `green(color)`, `blue(color)` | The channels, 0 to 255 |
| `over(base, overlay)` | A translucent color over an opaque one, mixed in linear light as the renderer does |
| `mix(from, to, amount)` | `amount` of the way from `from` to `to`, in linear light; `mix(color, BLACK, 0.2)` is `color` with 20 % less light |
| `luminance(color)`, `contrast(first, second)`, `lightness(color)` | WCAG's relative luminance and contrast ratio, and CIELAB's L* |
| `BLACK`, `WHITE`, `TRANSPARENT` | |

The default themes use the colors of the kit's `Palette`, named by hue and lightness: `BLUE_496` is a blue of L* 49.6. An app may use them too, but prefer the theme's token for a purpose, `theme.accent().color()` rather than `Palette.BLUE_496`, so a changed theme changes it.

## Contrast

In the default themes, primary and muted text reach WCAG AA contrast (4.5:1) on every surface they appear on; disabled text is deliberately lower. A theme of your own should do the same; `Colors.contrast(text, surface)` measures it.
