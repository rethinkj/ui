The kit's look comes from `Theme`, a record of token groups: surfaces, text colours, borders, accent, status colours, spacing, radii, type, sizes, motion, the grid's, elevation, code colours and more. `Theme.DARK` and `Theme.LIGHT` are the defaults; an app copies one and changes a group with a `with` method. Components read only tokens, so a changed theme changes everything at once.

```java snippet="theme"
```

## Passing the theme

Every component takes the theme as its first parameter. There is no global theme: the view gets it from the state or a constant, so two themes can be on screen at once, and a switch between dark and light is a field in the state:


## The groups

| Group | Tokens |
| --- | --- |
| `surface()` | `window` (the page), `panel` (cards), `raised` (controls, popups), `band` (bars inside cards), `hover`, `pressed`, `scrim` |
| `text()` | `primary`, `muted`, `disabled`, `onAccent` |
| `border()` | `subtle` (hairlines), `control` (buttons, popups), `strong` (fields) |
| `accent()` | `color`, `hover`, `pressed`, `selection`, `edge` (lines, rings, the grid's cursor) |
| `status()` | `danger`, `warning`, `success` |
| `space()` | `xs`, `s`, `m`, `l`, `xl`, `xxl` |
| `radius()` | `small` (4), `medium` (6), `large` (10) |
| `type()` | `body`, `mono`, `heading`, `title`, `strong` |
| `size()` | `control`, `field`, `icon`, `checkbox`, `stroke`, … |
| `motion()` | `feedback`, `move`, `fade` springs; tooltip and submenu delays; how long a toast stays |
| `elevation()` | Shadows of `card`, `popup`, `dialog` |
| `grid()`, `scrollbars()`, `code()`, `prose()`, `badge()`, `caption()` | The tokens of the grid, scrollbars, code editor, Markdown, badges and the close button |

`withSurface`, `withText`, `withBorder`, `withAccent`, `withStatus`, `withSpace`, `withRadius`, `withType`, `withSize`, `withMotion`, `withGrid`, `withScrollbars`, `withCode`, `withElevation`, `withProse`, `withBadge` and `withCaption` return a changed copy.

## The look

The look is layered: the window's background is a page, each region a card on it, controls and popups raised above. Hairlines of low contrast separate rows; buttons and popups have a slightly stronger edge, fields a strong one. The full accent fills primary buttons and what is on; its lighter edge draws the focus ring, the active tab's line and the grid's cursor. The default themes hold text to WCAG AA contrast (4.5:1) on every surface it appears on, which the kit's tests check; a theme of your own should too.

`Theme.over(base, overlay)` mixes a translucent colour into a surface as the renderer does, in linear light.

## Following the system

`WindowLoop.appearance(look -> …)` tells the app the system's scheme, accent colour and high contrast at the start and whenever they change, so an app can choose `DARK` or `LIGHT` (and the accent) like the system. See [Windows, icons and dialogs](/docs/concepts/platform).
