The kit's look comes from `Theme`, a record of token groups: surfaces, text colours, borders, accent, status colours, spacing, radii, type, sizes, motion, elevation, the grid's and code colours, and more. `Theme.DARK` and `Theme.LIGHT` are the defaults; change a group with a `with` method or pick a named accent. Components read only tokens, so a changed theme changes every component at once.

## Passing the theme

Every component takes the theme as its first parameter. There is no global theme: the view gets it from the state or a constant, so two themes can be on screen at once, and switching between dark and light is a field in the state:

## The groups

| Group | Tokens |
| --- | --- |
| `surface()` | `window` (the page), `panel` (cards), `raised` (controls), `band` (bars inside cards), `hover`, `pressed`, `scrim`, `popup` (menus, lists, the palette, popovers, tooltips, toasts), `highlight` (the item under the pointer or the keys in a popup's list) |
| `text()` | `primary`, `muted`, `disabled`, `onAccent` |
| `border()` | `subtle` (edges of cards, grid lines), `divider` (hairlines that separate content: dividers, menu separators, a group's rows), `control` (buttons, popups, a field's top and sides), `strong` (a field's bottom line, a checkbox's box), `track` and `trackOnAccent` (a spinner's ring, on the surfaces and on a primary button) |
| `accent()` | `color`, `hover`, `pressed`, `selection`, `edge` (lines, rings, the grid's cursor) |
| `status()` | `danger`, `warning`, `success` |
| `space()` | `xs`, `s`, `m`, `l`, `xl`, `xxl` |
| `radius()` | `small` (4), `medium` (6), `large` (10) |
| `type()` | `body` (13), `small` (12: secondary text beside what it is about), `mono` (12), `strong` (13, medium), `heading` (14, semibold: sections and cards), `dialog` (16, semibold: a dialog's title), `title` (20, semibold: a page) |
| `size()` | `control`, `field`, `icon`, `checkbox`, `stroke`, … |
| `motion()` | `feedback`, `move`, `fade` springs; tooltip and submenu delays; how long a toast stays |
| `elevation()` | Shadows of `card` (the least), `popup`, `dialog` (the most) |
| `grid()`, `scrollbars()`, `code()`, `prose()`, `badge()`, `caption()`, `danger()`, `callout()` | The tokens of the grid, scrollbars, code editor, Markdown, badges, the close button, buttons that destroy (`Theme.Danger`, `withDanger`) and callouts (`Theme.Callouts`, `withCallout`) |

`withSurface`, `withText`, `withBorder`, `withAccent`, `withStatus`, `withSpace`, `withRadius`, `withType`, `withSize`, `withMotion`, `withGrid`, `withScrollbars`, `withCode`, `withElevation`, `withProse`, `withBadge` and `withCaption` return a changed copy.

## Accents

`theme.withAccent(Theme.Hue.VIOLET)` picks a named accent: `BLUE` (the default), `VIOLET`, `PURPLE`, `PINK`, `RED`, `ORANGE`, `AMBER`, `GREEN`, `TEAL` or `GREY`, for example a colour per connection or per window. Each hue has a version for dark themes (`hue.dark()`) and one for light themes (`hue.light()`), and `withAccent` picks the one that fits. All of them meet the same contrast as the default accent in both themes. Only the accent changes: the grid's selection, links and the tint of a changed cell stay blue.

Your own accent is a `Theme.Accent` of a colour and its hover and pressed tones. The selection is then the colour at 40 % and the edge (focus rings, the grid's cursor) the colour itself; in a dark theme the edge may need a lighter tone, which the five-value constructor takes, to reach 3:1 contrast:

## Colours

A colour is an `int`, `0xAARRGGBB` in 8-bit sRGB with straight (not premultiplied) alpha, everywhere: in `El.fill`, `color`, `border`, `Shadow` and the theme. `com.rethinkj.ui.Colors` creates, reads and mixes them, so code needs no alpha hex digits or bit masks:

```java snippet="colours"
```

| Method | What it does |
| --- | --- |
| `rgb(0x3D6FE6)`, `rgb(r, g, b)`, `argb(a, r, g, b)` | An opaque colour from 24 bits or from channels of 0 to 255 |
| `alpha(colour, 0.4f)` | The colour at that alpha, `round(share * 255)`: 0.4 is `0x66` |
| `hex("#3D6FE6")`, `hex("#663D6FE6")`, `toHex(colour)` | Parse from text and format back; a parse error shows the expected form |
| `alpha(c)`, `red(c)`, `green(c)`, `blue(c)` | The channels, 0 to 255 |
| `over(base, overlay)` | A translucent colour over an opaque one, mixed in linear light as the renderer does |
| `mix(a, b, t)` | `t` of the way from `a` to `b`, in linear light; `mix(c, BLACK, 0.2)` is `c` with 20 % less light |
| `luminance(c)`, `contrast(a, b)`, `lightness(c)` | WCAG's relative luminance and contrast ratio, and CIELAB's L* |
| `BLACK`, `WHITE`, `TRANSPARENT` | |

The default themes use the colours of the kit's `Palette`, named by hue and lightness: `BLUE_496` is a blue of L* 49.6. An app may use them too, but prefer the theme's token for a purpose, `t.accent().color()` rather than `Palette.BLUE_496`, so a changed theme changes it.

## Contrast

In the default themes, primary and muted text reach WCAG AA contrast (4.5:1) on every surface they appear on; disabled text is deliberately lower. A theme of your own should do the same; `Colors.contrast(a, b)` measures it.

## Following the system

`WindowLoop.appearance(look -> …)` reports the system's dark or light scheme, accent colour and high contrast at the start and whenever they change, so the app can pick `DARK` or `LIGHT` (and the accent) to match. See [Windows, icons and dialogs](/docs/concepts/platform).
