All kit components read their styling from [`Theme`](/api/com/rethinkj/ui/kit/Theme.html), a record containing design token groups: surfaces, text colors, borders, accent colors, status colors, spacing, corner radii, typography, sizes, motion, and elevation.

`Theme.DARK` and `Theme.LIGHT` are built in. Because components only use theme tokens, updating the theme updates your entire UI at once.

## Providing a theme

Read the active theme in your view with `Theme.CURRENT.get()` (defaults to `Theme.DARK`).

- **App-wide theme:** Call `app.provide(Theme.CURRENT, state -> theme)` so every view rebuild and virtual list row receives your chosen theme.
- **Scoped override:** Wrap part of a view in `Theme.CURRENT.with(theme, () -> part)` to mix two themes on screen.
- **Custom contexts:** `Theme.CURRENT` is a core [`Context`](/api/com/rethinkj/ui/Context.html); create your own with `new Context<>(fallback)` to pass any shared value down the view tree.

- Changing `mode` or `accent` in a handler rebuilds the view with the new theme immediately.
- `WindowLoop.appearance(handler)` notifies your app at startup and whenever the OS theme changes, passing [`SystemAppearance`](/api/com/rethinkj/ui/window/SystemAppearance.html) (`scheme()`: `DARK`, `LIGHT`, or `UNKNOWN`; `accent()` on Windows; `highContrast()`).
- On Windows, call `window.frameDark(dark)` to match a framed window's title bar to your app theme (see [Windows, icons and dialogs](/docs/concepts/platform#the-systems-appearance)).

## Theme token groups

| Group | Key tokens |
| --- | --- |
| `surface()` | `window` (page background), `panel` (cards), `raised` (controls), `band` (toolbars/bars), `hover`, `pressed`, `scrim`, `popup`, `highlight` |
| `text()` | `primary`, `muted`, `disabled`, `onAccent` |
| `border()` | `subtle` (cards, grid lines), `divider` (separators), `control` (buttons, popups, inputs), `strong` (input bottom border, checkboxes), `track`, `trackOnAccent` |
| `accent()` | `color`, `hover`, `pressed`, `selection`, `edge` (focus rings, grid cursor) |
| `status()` | `danger`, `warning`, `success` |
| `space()` | `xs`, `s`, `m`, `l`, `xl`, `xxl` |
| `radius()` | `small` (4), `medium` (6), `large` (10) |
| `type()` | `body` (13), `small` (12), `mono` (12), `strong` (13 medium), `heading` (14 semibold), `section` (16), `dialog` (16), `title` (20) |
| `size()` | `control`, `field`, `icon`, `checkbox`, `stroke`, `tooltip`, … |
| `motion()` | `feedback`, `move`, `fade` springs; tooltip/submenu delays; toast duration |
| `elevation()` | Shadows for `control`, `controlHover`, `card`, `popup`, `dialog` |
| `grid()`, `scrollbars()`, `code()`, `prose()`, `badge()`, `caption()`, `danger()`, `callout()` | Component-specific token groups |

Each group has a `with…` method (`withSurface`, `withAccent`, `withSpace`, etc.) that returns a modified copy of the `Theme`. See [`Theme` Javadoc](/api/com/rethinkj/ui/kit/Theme.html) for every token.

## Accent colors

Pick any built-in accent hue with `theme.withAccent(Theme.Hue.VIOLET)`: `BLUE` (default), `VIOLET`, `PURPLE`, `PINK`, `RED`, `ORANGE`, `AMBER`, `GREEN`, `TEAL`, or `GRAY`. Each hue automatically adapts to dark and light themes with accessible contrast.

## Working with colors

Colors are 32-bit ARGB integers (`0xAARRGGBB`, sRGB, non-premultiplied alpha). Use [`Colors`](/api/com/rethinkj/ui/Colors.html) instead of manual bit-shifting:

```java snippet="colors"
```

| Method | Description |
| --- | --- |
| `rgb(0x3D6FE6)`, `rgb(r, g, b)`, `argb(a, r, g, b)` | Create a color from hex or 0–255 channels |
| `alpha(color, 0.4f)` | Set alpha from `0.0f` to `1.0f` |
| `hex("#3D6FE6")`, `hex("#663D6FE6")`, `toHex(color)` | Parse or format hex strings |
| `alpha(c)`, `red(c)`, `green(c)`, `blue(c)` | Extract 0–255 channels |
| `over(base, overlay)` | Blend a semi-transparent color over a base color in linear light |
| `mix(from, to, amount)` | Interpolate between two colors in linear light |
| `luminance(c)`, `contrast(c1, c2)`, `lightness(c)` | WCAG relative luminance, contrast ratio, and CIELAB L* |
| `BLACK`, `WHITE`, `TRANSPARENT` | Common constants |

Prefer semantic theme tokens (`theme.accent().color()`) over raw `Palette` constants so theme switches work everywhere. All primary and muted text in the default themes meets WCAG AA (4.5:1) contrast; check custom themes with `Colors.contrast(text, surface)`.
