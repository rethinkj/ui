## Mouse and pointer

| Method | Description |
| --- | --- |
| `onPress(Runnable)` | Runs when the element is clicked (mouse down + up on the same element), or when Enter/Space is pressed while focused |
| `onPress((clicks, modifiers) -> …)` | Includes click count (`2` for double-click) and held modifier keys |
| `onPress((clicks, modifiers, x, y) -> …)` | Also includes click coordinates inside the element |
| `onSecondaryPress((x, y) -> …)` | Right-click handler (for example, to open a context menu) |
| `onPointerDown(...)` | Runs immediately when the mouse button goes down |
| `onDrag(drag -> …)` | Drag handler (starts once the pointer moves more than 4 pixels) |
| `cursor(Cursor.POINTER)` | Sets the mouse cursor shape on hover |

Clicks go to the innermost element under the cursor that has an `onPress` or `onDrag` handler (so a child with `onDrag` prevents even a stationary click from reaching an ancestor's `onPress`).

A [`Drag`](/api/com/rethinkj/ui/Drag.html) provides `phase` (`START`, `MOVE`, `END`, `CANCEL`), distance from the start (`dx`, `dy`), and current position inside the element (`x`, `y`). Pressing **Escape** cancels an active drag.

## Keyboard and focus

| Method | Description |
| --- | --- |
| `focusable()` | Allows the element to receive keyboard focus via Tab or click |
| `onKey(key -> …)` | Handles key presses while this element (or a child) is focused. Return `true` to consume the key. Replaces any previous `onKey` on this element |
| `onKeyFirst(key -> …)` | Runs **before** the element's own `onKey` handler — useful for adding shortcuts to a kit component like `CodeEditor` |
| `onKeyUp(...)`, `onText(text -> …)` | Handles key releases and typed text |
| `onTypeAhead(text -> …)` | Receives incrementally typed characters for jump-to-item search (resets after `App.TYPE_AHEAD` seconds or Escape) |
| `keepFocus()` | Prevents clicking this element from stealing keyboard focus (used by toolbar buttons acting on an editor) |
| `skipTab()` | Allows click focus, but skips this element during Tab navigation |
| `autofocus()`, `autofocus(key)` | Focuses the element when it first appears; with a non-null `key`, re-triggers whenever `key` changes (e.g., focusing the first invalid field after Save) |
| `takeFocus(key)` | Like `autofocus(key)`, but wins over the `autofocus` elements, opening overlays and rows that ask for the focus in the same build (e.g., a tab group's bar after a split) |
| `defaultFocus()` | Marks the preferred focus target when `app.focus(container)` focuses an enclosing container (for example, focusing a page's data grid instead of its toolbar) |
| `focusRing(argb)`, `focusRingGap(px)` | Customizes the keyboard focus ring color and gap |

**Key dispatch order** (stops at the first step that consumes the key):
1. Focused element's `onKeyFirst` and `onKey` handlers.
2. Focused text field's built-in editing.
3. **Enter** or **Space** (without modifiers) triggers `onPress` on the focused element.
4. Ancestors' `onKey` handlers, from innermost to outermost.
5. **Menu** key or **Shift+F10** triggers `onSecondaryPress` on the focused element or its nearest ancestor.
6. **Tab** / **Shift+Tab** moves focus in tree order. **Page Up** / **Page Down** scrolls the nearest scroll container by a page (or the first scroll container inside a modal dialog), and **Home** / **End** scroll it to its start or end.

[`Key`](/api/com/rethinkj/ui/Key.html) uses standard web key names (`"Enter"`, `"ArrowDown"`, `"A"`) and modifier flags (`Key.CONTROL`, `SHIFT`, `ALT`, `META`).

**Focus restoration:** If the focused element is removed from the tree (for example, closing a tab), focus automatically moves to the nearest remaining focusable container. You can also move focus programmatically in a handler with `app.focus(element)`. If you pass a non-focusable container, `App` focuses the last focused element inside it, or its `defaultFocus()` child, or its `autofocus()` child, or its first focusable child.

## Looks

Style an element dynamically based on hover, press, or focus state (combine with `.motion(...)` to animate transitions):

| Method | Description |
| --- | --- |
| `whenHovered(element -> …)` | Applies styles while hovered |
| `whenPressed(element -> …)` | Applies styles while pressed |
| `whenFocused(element -> …)`, `whenFocusWithin(element -> …)` | Applies styles while this element (or a child) is focused |
| `onFocusIn(handler)` | Runs when keyboard focus moves from outside this element into it or a descendant (by pointer, Tab, or code) |
| `whenHoveredFor(seconds, element -> …)` | Applies styles or attaches an overlay after hovering for a delay (used by [Tooltip](/docs/components/tooltip)) |
| `whenFocusVisibleFor(seconds, element -> …)` | Same as above for keyboard focus (clears on blur or non-navigation key press) |
| `onHoverFor(seconds, handler)` | Runs a handler once after hovering for a delay (`0` runs immediately on hover) |

Hover delays run on the app clock (advanced with `advance` in scripts). After clicking an element, delayed hover effects wait until the mouse leaves and re-enters. Once a delayed hover overlay (like a tooltip) has appeared, hovering adjacent items shows their tooltips immediately without waiting again.

## Global input observers

Sometimes a component needs to observe input anywhere in the window without consuming it (for example, committing a cell editor when the user clicks outside):

| Method | Description |
| --- | --- |
| `onAnyPointerDown(handler)` | Runs on any mouse button down anywhere in the window, before normal dispatch |
| `onAnyKeyDown(key -> …)` | Runs on any key down, before `onKey` or text fields |
| `onPressOutside(handler)` | Runs when a click lands outside this element and its children (overlays inside it count as outside) |

System title-bar clicks on frameless windows do not trigger these observers.

## Holding focus in a region

`holdFocus()` temporarily traps focus inside a non-overlay region (used by [MenuBar](/docs/components/menu-bar) when activated with Alt or F10). When enabled, focus moves into the element; clicking outside calls `onDismiss`; when removed, focus returns to its previous element.

## Scroll wheel

Scrolling the mouse wheel scrolls the innermost scroll container under the cursor that can still scroll in that direction, bubbling outward if it is already at the edge. Holding **Shift** scrolls horizontally. To scroll from a handler, call `app.scrollTo(area, x, y)` or `app.scrollToRow(list, row)`.

To handle the scroll wheel yourself (for example, a canvas that zooms with **Ctrl**+wheel and pans without it), add `onWheel((deltaX, deltaY, modifiers, x, y) -> …)`. The handler receives the scroll distance in logical pixels (positive is down or right), the held modifiers (`Key.CONTROL`, `SHIFT`, `ALT`, `META`), and the pointer position inside the element. Return `true` to consume the event. Wheel events bubble from the innermost element outward, and each element's `onWheel` runs before its own scrolling. An inner scroll container that can still scroll handles the wheel before an outer `onWheel` handler runs. If no handler consumes the event, the wheel scrolls as usual.

To notice when the user actually moved a scroll area or any scroll area inside an element — by the wheel, a scrollbar (dragging the thumb, clicking the track or a tick), **Page Up**, **Page Down**, **Home** or **End** outside a text field, or a key that scrolled it to show the selection or the focus — without hearing layout clamps, `app.scrollTo`, `app.scrollToRow`, or `ScrollState`, add `onUserScroll(handler)`. Because it hears inner scroll areas too, attaching it to `DataGrid.dataGrid(...)` hears scrolls of the grid's rows and columns. Handlers run after the input that changed an offset, from innermost to outermost, and rebuild the view if state changes.
