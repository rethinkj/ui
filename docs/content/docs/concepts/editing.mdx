title: Editing records
description: A form over a record or a POJO, with drafts, rules and the server's errors kept in one Editing.

An [`Editing<T>`](/api/com/rethinkj/ui/kit/Editing.html) holds the edit of one value, such as a record in a dialog: the original, the edited value, the text of fields that does not parse yet (drafts), and the fields' errors. Keep it in the state while the edit lasts. Kit components take its fields as a `Prop`, so the view needs no value, draft and handler per field, and Save asks one object whether it may save. Use it for a dialog or page that edits a value and saves it; for a value that applies at once, such as a theme switch, `Prop.of` over the state is enough.

The constant is the field's identity: the editing keeps drafts and errors per part, so `e.at(Order.AMOUNT)` is the same field in every build. Do not create parts in the view: `e.at(Part.of(...))` is a new field in each build and loses its draft. For a record inside a record, `Profile.TLS.then(Tls.MODE)` names the nested field, the same as `e.at(Profile.TLS).at(Tls.MODE)`; rules and errors can use it. A data grid's [typed column](/docs/components/data-grid/typed) takes the same constant: `table.column("amount", 100, Format.DECIMAL, Order.AMOUNT)`.

| Call | |
| --- | --- |
| `Editing.of(record)` | The edit of a value that does not change, such as a record |
| `Editing.of(pojo, copy)` | The edit of a copy of a POJO, as `Editing.of(settings, Settings::new)`, since setters change the object |
| `.rule(part, test, message)` | A rule over the whole value; while it fails, the message shows at the part's field and the edit is not valid |
| `e.at(part)` | The `Prop` of a field: its value, where it is written, its draft and its error |
| `value()`, `original()` | The edited value, and the one the edit began with or last saved |
| `changed()` | Whether the value differs from the original, by `equals` |
| `valid()` | No field holds text that does not parse, no error set by the app stands, and every rule holds |
| `reset()` | Back to the original, drafts and errors forgotten |
| `showErrors()` | Every field shows its error, also fields not edited yet, such as an empty required field: call it when Save is pressed while the edit is not valid |
| `saved()` | The value is the new original: `changed()` is false until the next edit |
| `prop.error(message)` | An error from the app, such as the server's refusal: shown at the field until its next edit |

The rest is in the Javadoc of [`Editing`](/api/com/rethinkj/ui/kit/Editing.html) and [`Prop`](/api/com/rethinkj/ui/kit/Prop.html).

A field's error is the first of: a parse error (also for a value that has none, such as null in a required field), an error set by the app, the first failing rule that names the field. `valid()` counts parse errors from the start, but a field shows its parse error only after the user edited it or the app called `showErrors()`, so a form for a new record does not open with parse errors. Errors set by the app and failing rules show at once. The component shows the error (`invalid` and `error="…"` in a dump, a danger border on a text field), and a [Form](/docs/components/form) field shows it below the control. A field that is hidden keeps its draft, and a parse error in it still makes the edit invalid.

## Components that take a prop

Each has an overload that takes a `Prop` in place of the value and its handler. A read-only prop disables the component, as a null handler does.

| Component | With a prop |
| --- | --- |
| [TextField](/docs/components/text-field) | `textField(t, prop[, placeholder])`, `passwordField(t, prop, placeholder)` |
| [ValueField](/docs/components/format) | `valueField(t, format, prop[, placeholder])`: the draft is the editing's |
| [Checkbox](/docs/components/checkbox), [Toggle](/docs/components/toggle) | `checkbox(t, prop, text)`, `toggle(t, prop, text)` |
| [Select](/docs/components/select), [Radio](/docs/components/radio), [Segmented](/docs/components/segmented) | `select(t, values, prop, text, menuState)`, `radioGroup(t, values, prop, text)`, `segmented(t, values, prop, text)` |
| [ComboBox](/docs/components/combo-box) | `comboBox(t, values, prop, text, state)`, `items(t, values, prop, item, state)`, `free(t, prop, suggestions, state)` |
| [NumberField](/docs/components/number-field), [Slider](/docs/components/slider) | `numberField(t, prop, min, max, step)`, `slider(t, prop, min, max, step)` |

`Prop.of(() -> s.dark, v -> s.dark = v)` is a prop over the state, without an editing: it writes at once, keeps no draft and has no errors. `prop.at(part)` is the prop of one field; writing it writes back the whole value, a new record through the wither.
