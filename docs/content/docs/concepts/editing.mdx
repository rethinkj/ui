[`Editing<T>`](/api/com/rethinkj/ui/kit/Editing.html) manages the state of editing a record or object in a form or dialog. It tracks:
- The original value and current edited value
- Draft text for fields that cannot be parsed yet (such as a partially typed number or date)
- Validation errors and server errors

Keep one `Editing<T>` in your state while the form is open. Kit inputs accept `editing.at(part)` as a `Prop`, so you do not have to manage separate value, draft, error, and change handler fields for every input.

(For simple instant settings like a dark-mode switch, you do not need `Editing` — use `Prop.of(...)` or direct handlers instead.)

Because `Editing` tracks drafts and errors by `Part` identity, always reuse the same `Part` constants — never call `Part.of(...)` inside your view function.

- **Nested records:** Chain parts with `Profile.TLS.then(Tls.MODE)` (equivalent to `editing.at(Profile.TLS).at(Tls.MODE)`).

| Method | Description |
| --- | --- |
| `Editing.of(record)` | Starts editing an immutable record |
| `Editing.of(pojo, copy)` | Starts editing a mutable POJO by copying it (e.g., `Editing.of(settings, Settings::new)`) |
| `.rule(part, test, message)` | Adds a validation rule; when `test` fails, `message` appears on `part` and `valid()` becomes `false` |
| `editing.at(part)` | Returns the `Prop` for a field (value, writer, draft text, and error) |
| `value()`, `original()` | Returns the current edited value or the original/last-saved value |
| `changed()` | Returns `true` if `value()` differs from `original()` (using `equals`) |
| `valid()` | Returns `true` when there are no parse errors, no custom errors, and all rules pass |
| `reset()` | Reverts to `original()` and clears all drafts and errors |
| `showErrors()` | Reveals errors on all fields, including untouched required fields (call when Save is clicked while invalid) |
| `saved()` | Commits `value()` as the new `original()` so `changed()` resets to `false` |
| `prop.error(message)` | Attaches a custom error (such as a server validation error) until that field, an ancestor, or a descendant is edited |

See [`Editing`](/api/com/rethinkj/ui/kit/Editing.html) and [`Prop`](/api/com/rethinkj/ui/kit/Prop.html) Javadoc for more methods.

**How errors are shown:** Each field displays its first active error in priority order: parse error, custom error (`prop.error(...)`), then failing `.rule(...)`. Parse errors count toward `valid()` immediately, but stay hidden on screen until the user edits the field or you call `showErrors()` (so empty "New item" forms do not open covered in red). Custom errors and rule errors appear immediately. [Form](/docs/components/form) displays the error text below the input. Hidden fields keep their drafts and still affect `valid()`.

## Components that take a prop

All of these kit components have an overload accepting a `Prop`. A read-only `Prop` automatically disables the control:

| Component | `Prop` overload |
| --- | --- |
| [TextField](/docs/components/text-field) | `textField(prop[, placeholder])`, `passwordField(prop, placeholder)` |
| [ValueField](/docs/components/format) | `valueField(format, prop[, placeholder])` (draft stored in `Editing`) |
| [Checkbox](/docs/components/checkbox), [Toggle](/docs/components/toggle) | `checkbox(prop, text)`, `toggle(prop, text)` |
| [Select](/docs/components/select), [Radio](/docs/components/radio), [Segmented](/docs/components/segmented) | `select(values, prop, text, menuState)`, `radioGroup(values, prop, text)`, `segmented(values, prop, text)` |
| [ComboBox](/docs/components/combo-box) | `comboBox(values, prop, text, comboBoxState)`, `items(values, prop, item, comboBoxState)`, `free(prop, suggestions, comboBoxState)` |
| [NumberField](/docs/components/number-field) | `numberField(prop, min, max, step)` (draft stored in `Editing`) |
| [Slider](/docs/components/slider) | `slider(prop, min, max, step)` |

You can also create a standalone prop directly over state with `Prop.of(() -> state.dark, value -> state.dark = value)` (writes immediately, no draft or errors).
