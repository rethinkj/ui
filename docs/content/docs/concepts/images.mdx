## HiDPI scale

Each `Image` has a scale factor (physical pixels per logical pixel, default `1`). For example, a 200×100 pixel image created with `Image.decode(bytes, 2)` or `Image.of(pixels, 2)` displays at 100×50 logical pixels and renders crisp on 2× displays.

## Decode on a background thread

Decoding large images can take noticeable time. Always decode inside `app.background` and store the resulting `Image` in your state — never decode inside your view function. The renderer caches uploaded GPU textures by `Image` instance identity.

**Supported formats:** All PNG color types and bit depths (including Adam7 interlaced), plus baseline and progressive JPEG (with automatic EXIF orientation). CMYK JPEG throws an error.

## Sizing and fit

By default, an image renders at its logical size, shrinking proportionally if the container is narrower. Setting one dimension scales proportionally. Setting both width and height uses `.fit(...)` (`Image.Fit.FILL`, `CONTAIN`, or `COVER`, just like CSS `object-fit`). Corner radius, borders, shadows, opacity, and motion work on images just like any other element.

## GPU memory limit

`app.imageMemory(bytes)` sets the GPU texture cache limit (default: 256 MB). When full, least-recently-used images are evicted and re-uploaded if displayed again. Images visible in the current frame are never evicted.
