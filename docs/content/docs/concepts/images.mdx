`Image.decode(bytes)` reads a PNG or JPEG file, `Image.of(pixels)` takes pixels you computed, and `El.image(image)` shows the image. It is drawn pixel for pixel where possible and filtered smoothly when scaled. Decoding needs no `java.desktop`. The kit's [Image](/docs/components/image) adds rounded corners and a placeholder.

## Scale

An image is made for a scale, the physical pixels per logical pixel: 200 by 100 pixels made for scale 2 are 100 by 50 logical pixels, drawn pixel for pixel in a window at scale 2. `Image.decode(bytes, scale)` and `Image.of(pixels, scale)` take it; the default is 1.

## Decode off the app's thread

Decoding a large image takes noticeable time, so decode with `app.background` and keep the `Image` in the state. Do not create it in the view: the renderer knows an image by its identity and uploads it to the GPU once.

PNG of every colour type and bit depth and baseline and progressive JPEG (with EXIF orientation) are supported; interlaced PNG and CMYK JPEG fail with a message.

## Size and fit

An image element is as large as the image in logical pixels, but no wider than the space available, keeping its aspect ratio. A width or height scales it; with both, `fit(Image.Fit.FILL)`, `CONTAIN` or `COVER` says how it fills the box, as CSS's `object-fit` does. Rounded corners, borders, shadows, opacity and motion work as on any element.

## Memory

`app.imageMemory(bytes)` (default 256 MB) limits the GPU memory for images. Beyond it, the images drawn least recently are released and uploaded again when shown. Images in the current frame are never released, so a frame of many large images may use more.
