title: Several windows

One `WindowLoop` runs any number of windows. Each has its own `App` (focus, hover, scroll, animations); windows that show the same data share one state object, and a change in one shows in the others in the same frame. Handlers open windows with `app.windows().open(...)`; drags can leave a window and drop in another. The kit's [TabGroups](/docs/components/tab-groups) uses all of it for tabs that tear off.

## Opening a window

`windows.open(title, width, height, options, app)` opens a window that runs `app` and returns a `Windows.Handle`: `close()`, `raise()`, `moveTo(x, y)`, `onCloseRequest(handler)`, `isOpen()`, and the window's position and scale. `windows.all()` lists the open windows; `of(app)` finds an app's window.

Apps with the same state object rebuild together: when a handler in one runs, the others' views are built in the same pass.

## Closing

A close request (the close button, Alt+F4, a script's `close`) runs the window's `onCloseRequest` handler, which closes the window now, after asking, or not at all. Without a handler the window closes. The loop ends when its last window closes.

## Drags between windows

`El.dragPayload(object)` on an element with `onDrag` makes its drags carry the object; `El.onDrop(drop -> …)` lets an element in any window receive it, with the phases `OVER`, `LEAVE` and `DROP`. Each `Drag` step also gives the pointer's screen position, whether it has left the window it started in, and which window it is over, so a handler can open a window that follows the pointer.

Files and text dropped from other applications reach `El.onFileDrop`.

## Platforms

On Windows and X11 an app can place windows anywhere. Wayland does not let apps place their windows: a torn-off window opens where the compositor puts it and does not follow the pointer, so offer menu items such as Move to new window and Move back.

## Under a script

A handler that opens a window adds it to the script under its title; `window <name>` sends the following steps there, `snap` writes every window, and targets may say `in <window>`. See [Scripts](/docs/testing/scripts).
