A single `WindowLoop` can manage any number of desktop windows. Each window runs its own `App` (with independent focus, hover, scroll positions, and animations). Windows that share the same state object automatically stay in sync: when a handler updates state in one window, all other windows sharing that state rebuild in the same frame.

The kit's [TabGroups](/docs/components/tab-groups) uses this for tear-off tabs.

```java snippet="tab-groups"
```

It returns a [`Windows.Handle`](/api/com/rethinkj/ui/window/Windows.Handle.html) with `close()`, `raise()`, `moveTo(x, y)`, `onCloseRequest(handler)`, `onClosed(handler)`, `onShown(handler)`, `isOpen()`, and window position/scale getters. Use `windows.all()` to list all open windows or `windows.of(app)` to find a specific app's handle.

## Handling window close

- **`onCloseRequest(handler)`:** Runs when the user clicks the close button or presses Alt+F4. Your handler can close the window immediately, show a confirmation dialog, or ignore the request. Without a handler, the window closes directly (or ends `WindowLoop` if it is the last open window).
- **`onClosed(handler)`:** Runs on the UI thread after a window closes (as long as at least one other window stays open). Use it to clean up per-window state:

## Knowing a window was shown

`onShown(handler)` runs once the window has shown its first frame on the screen, on the UI thread in the window's next frame. A minimized or hidden window shows no frame, so its handler waits until one is shown. Use it to tell an updater that a new version runs, to close a splash screen, or to measure the time to the first frame. The first window of a `WindowLoop` has its handle before `run()`:

## Dragging between windows

Attach `El.dragPayload(object)` to a draggable element (`onDrag`) and `El.onDrop(drop -> …)` to drop targets in any window (`OVER`, `LEAVE`, and `DROP` phases). Each `Drag` event includes screen coordinates, `outside()` (whether the pointer left the origin window), and which window is currently under the cursor — allowing tear-off windows to follow the mouse.

To accept files or text dragged from external applications, use `El.onFileDrop`.

## Platform notes

Windows and Linux X11 allow apps to position windows freely. Linux Wayland does not allow apps to set window positions, so detached windows cannot follow the mouse cursor — provide menu actions like **Move to new window** and **Move back** as alternatives.

## Testing multiple windows in scripts

Windows opened by handlers are registered in headless scripts under their window title. Use `window <name>` to switch targets, `in <window> <target>` for cross-window pointer actions, and `snap` to save screenshots of every open window. See [Scripts](/docs/testing/scripts).
