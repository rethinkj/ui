`Window` creates desktop windows on Windows and Linux, and `WindowLoop` runs your app inside them. For the full API, see [`Window`](/api/com/rethinkj/ui/window/Window.html) and [`WindowLoop`](/api/com/rethinkj/ui/window/WindowLoop.html).

## Window options

| `Window.options()` method | Description |
| --- | --- |
| `frameless()` | Removes the OS title bar so you can draw your own (e.g., with [TitleBar](/docs/components/title-bar)) |
| `minimumSize(w, h)`, `fixedSize()` | Sets minimum resize bounds or disables resizing |
| `icon(WindowIcon)` | Sets the window and taskbar icon |
| `position(x, y)` | Sets the initial window position |
| `placement(placement)` | Restores saved position, size, and maximized state (see [below](#open-where-the-user-left-it)) |
| `underPointer()` | Suppresses focus activation and opening animation (combine with `position(x, y)` to place a tear-off window under the cursor) |

See [`Window.Options`](/api/com/rethinkj/ui/window/Window.Options.html) for all options.

Clicking an inactive window activates it and triggers the click immediately, just like in native apps. If you want the first click to only activate the window, start your app with the environment variable `SDL_MOUSE_FOCUS_CLICKTHROUGH=0`.

## Open where the user left it

Save `window.placement()` before closing and pass it to `options.placement(...)` on the next launch:

```java snippet="placement"
```

- `window.placement()` returns a [`Window.Placement`](/api/com/rethinkj/ui/window/Window.Placement.html) with position, size, maximized flag, and display name. Read it while the window is still open.
- `placement.toString()` formats it as a single line (e.g., `120,80 1200x720 maximized display "DELL U2720Q"`), and `Window.Placement.parse(line)` parses it back. Store it in your own settings file (throws `IllegalArgumentException` if malformed).
- If the saved monitor is disconnected or smaller, rethinkj UI clamps the window to fit the current display's work area. Wayland ignores explicit window positions.

## Custom title bars

In a frameless window, mark your custom title bar elements with `El.windowPart(part)` so dragging, edge resizing, double-click maximize, and Windows 11 snap layouts work natively. The kit's [TitleBar](/docs/components/title-bar) does this automatically.

Inside your view, read `WindowState.CURRENT.get()` to check `active()` and `maximized()` (for example, to show a Restore icon or dim an inactive title bar). You can also read `scale()` to measure text at the window's layout scale (call `text.scale(scale)` before `measure`). Window parts continue to work even when a modal dialog is open.

| [`WindowPart`](/api/com/rethinkj/ui/WindowPart.html) | Behavior |
| --- | --- |
| `CONTENT` | Normal content (use inside a `DRAG` area for non-draggable items like a search box) |
| `CONTROL` | Interactive control (automatically inferred for buttons, inputs, and scrollbars; narrows resize edge to 2 px) |
| `DRAG` | Drags the window; double-click maximizes/restores (except on Wayland) |
| `MINIMIZE`, `MAXIMIZE`, `CLOSE` | Native window buttons (hovering `MAXIMIZE` shows Windows 11 snap layouts) |

## App identity and icons

Call `Window.identity(id, name)` before opening your first window. On Windows, this groups your windows under their own taskbar icon instead of `java.exe`; on Linux, it sets the app ID for Wayland and X11.

Create icons with `WindowIcon.of(pixels...)` or `WindowIcon.of(size -> view)`. `AppIcon.appIcon(size, color, symbol)` creates a rounded-square icon from any kit symbol. For packaging, `icon.ico()` returns the icon as Windows `.ico` file bytes (see [Ship your app](/docs/get-started/ship#optional-app-icon)).

## Taskbar indicators (Windows)

```java snippet="taskbar"
```

- `window.badge(icon, description)` adds a badge overlay to the taskbar button (`AppIcon.count` and `AppIcon.dot` generate common badges).
- `window.progress(kind, value)` shows progress in the taskbar button (`NORMAL`, `PAUSED`, `ERROR` with `0.0`–`1.0`, `INDETERMINATE`, or `NONE`).
- `window.attention(...)` flashes the taskbar button (`BRIEFLY` or `UNTIL_FOCUSED`).

Taskbar badges and progress are Windows-only (no-op on Linux).

## The system's appearance

Register `WindowLoop.appearance(handler)` to receive a [`SystemAppearance`](/api/com/rethinkj/ui/window/SystemAppearance.html) at startup and whenever the OS theme changes (dark/light mode, Windows accent color, and high contrast). See [Themes](/docs/concepts/themes#switching-themes) for an example that follows the system theme.

On Windows, call `window.frameDark(boolean)` to match a standard framed window's title bar to your app's dark/light theme.

## Native file dialogs


```java snippet="images-handlers"
```

`app.fileDialog(dialog, onChoice, onError)` opens the OS file picker asynchronously without freezing the UI:

| [`FileDialog`](/api/com/rethinkj/ui/FileDialog.html) method | Description |
| --- | --- |
| `open(title)`, `.many()` | Pick one or multiple files |
| `save(title)`, `.fileName("orders.csv")` | Pick a save location |
| `chooseFolder(title)` | Pick a directory |
| `.filter("SQL", "sql")`, `.in(folder)` | Add file extension filters and initial directory |

The `Choice` result contains the selected paths (empty if canceled) and the index of the chosen filter (-1 if canceled or unknown, such as on Linux). On Linux, file dialogs use the XDG Desktop Portal (falling back to `zenity`).

## Native message boxes

```java snippet="message-box"
```

`app.messageBox(box, onButton, onError)` shows a system alert ([`MessageBox`](/api/com/rethinkj/ui/MessageBox.html)`.information`, `warning`, or `error`) with up to three `.buttons(...)` and returns the clicked button index. Configure default/cancel buttons with `.defaultButton(index)` and `.cancelButton(index)` (call after `.buttons(...)`).

Because native message boxes block all windows, prefer the kit's [Dialog](/docs/components/dialog) for normal in-app confirmations.

## Open a web address

```java snippet="open-uri"
```

`app.openUri(uri, onError)` opens an `http` or `https` address in the system's default browser. It passes the address to the OS and returns right away. If the OS reports a failure, `onError` runs later as a posted task. Any other scheme, such as a `file:` or `mailto:` link, also goes to `onError` as a posted task, and nothing opens. Getting no error does not guarantee that a browser started or that the page loaded.

## Desktop notifications

```java snippet="notify"
```

`app.notify(title, body, onClick, onError)` shows a system desktop notification. Clicking it while the app runs asks for the window to come to the front (a Wayland compositor may refuse) and runs `onClick` on the app's thread as a posted task; failures go to `onError` the same way.

- Set `Window.identity(id, name)` before opening the first window: Windows requires an identity to show WinRT toast notifications (and uses it together with `Window.Options#icon` for the app's name and icon), and Linux passes the name and `desktop-entry` hint over D-Bus (`org.freedesktop.Notifications`).
- Notifications do not include action buttons, and clicks are delivered only while the app is running.

## Tray icon

```java snippet="tray"
```

`app.tray(tray, onError)` shows a system tray icon ([`Tray`](/api/com/rethinkj/ui/Tray.html)) with a tooltip and a context menu of buttons, checkboxes, separators, submenus, and disabled entries (`.disabled()`). Calling `app.tray(...)` again updates the icon, tooltip, and menu in place without recreating the tray; `app.removeTray()` removes it. Entry handlers (checkboxes receive their new checked state) and `onError` run on the app's thread as posted tasks. To close to the tray, call `window.hide()` from `onCloseRequest`: the window stays open without a taskbar button, draws no frames, and keeps its tray icon until a tray entry calls `window.show()` to show it again or `window.close()` to quit. The tray icon is removed automatically when the window closes or `WindowLoop` ends.

- On Windows 11, the icon and hover tooltip appear in the notification area, and a left or right click opens the menu.
- On Linux, SDL creates a StatusNotifierItem through AppIndicator: it loads `libayatana-appindicator3` (or `libappindicator3`) and GTK 3 at run time when a tray is created. GNOME requires the AppIndicator extension, and AppIndicator does not display a tooltip. If the libraries are missing, `onError` receives SDL's error message.

## Headless scripts

In headless mode, scripts answer dialogs automatically with `dialog "<path>"`, `dialog cancel`, and `dialog button "<text>"`, click shown notifications with `notification click "<title>"` and tray entries with `tray click "<label>"`, and simulate file drops with `drop`. They do not open a browser, show OS notifications, or a system tray icon; instead, `snap` writes out the addresses opened, the notifications shown, and each window's tray menu. See [Scripts](/docs/testing/scripts).

## Clipboard

`app.clipboard()` returns the system clipboard in desktop windows and an in-memory clipboard in headless scripts.
