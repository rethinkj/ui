Calling `.motion(spring)` smoothly animates changes to an element's size, position, color, opacity, and corner radius instead of snapping immediately. Elements with both `.key(...)` and `.motion(...)` also fade in when added and fade out when removed. For continuous animations like spinners, use `.cycle(...)`.

All animations run on the app clock (which scripts control with `advance`).

## Springs

[`Spring(duration, bounce)`](/api/com/rethinkj/ui/motion/Spring.html) controls animation duration and overshoot. Built-in presets:

| Preset | Best for |
| --- | --- |
| `INSTANT` | Pointer-tracking transitions |
| `SNAP` | Small controls reacting to clicks |
| `SETTLE` | Default state transitions (smooth stop, no bounce) |
| `REFLOW` | Layout shifts |
| `GLIDE` | Large panels, drawers, and sheets |
| `MORPH` | Shape transitions |
| `POP` | Playful release animations |
| `DRIFT` | Slow, noticeable reveals |
| `NONE` | Disable animation |

When using kit components, prefer theme springs: `theme.motion().move()`, `theme.motion().feedback()`, and `theme.motion().fade()`. Springs preserve velocity when interrupted, so rapid toggling reverses smoothly.

## Enter and exit animations

When a keyed element with `.motion(...)` is removed from the tree, it stays in place, fades out, ignores input, and is removed once invisible. In a tree dump, fading-out elements are marked `exiting`. Menus, dialogs, and toasts use this automatically.

## Continuous animations (`cycle`)

```java snippet="cycle"
```

`cycle(seconds, (element, phase) -> …)` runs on every frame while visible, passing `phase` from `0` to `1` over each period. You can update position, fill color, or opacity inside the callback. Note that active cycles keep the window redrawing at the display refresh rate.

## Idle power efficiency

When nothing is changing (no input, no active springs or cycles, no blinking cursor, and no due timers), the window sleeps and uses zero CPU.
