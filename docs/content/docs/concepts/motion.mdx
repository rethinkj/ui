With `.motion(spring)`, an element's size, position, color, opacity and radii animate from what the last frame showed to what the new view says, instead of jumping. Elements with a key and motion fade in when they appear and fade out when they leave the tree. `.cycle(...)` is an endless animation, for spinners and progress bars. All of it runs on the app's clock, which a script moves with `advance`.

## Springs

[`Spring(duration, bounce)`](/api/com/rethinkj/ui/motion/Spring.html): how long the motion takes and how much it overshoots. The presets:

| Spring | For |
| --- | --- |
| `INSTANT` | Tied to the pointer: takes the edge off a jump |
| `SNAP` | Small controls answering a click |
| `SETTLE` | The default state change: arrives and stops |
| `REFLOW` | Layout moving out of the way |
| `GLIDE` | Big surfaces travelling: drawers, sheets |
| `MORPH` | One shape becoming another |
| `POP` | A release with a little life in it |
| `DRIFT` | Slow reveals the eye should follow |
| `NONE` | No motion |

In kit code, use the theme's springs: `theme.motion().move()`, `feedback()`, `fade()`. When the target changes mid-motion, the spring keeps its velocity, so a quick second press reverses smoothly.

## Presence

An element with a key and `motion` that leaves the tree stays where it was and fades out. It takes no input and is removed once invisible; in a tree dump its line ends in `exiting`. Menus, dialogs and toasts fade in and out this way.

## Cycles

```java snippet="cycle"
```

`cycle(seconds, (element, phase) -> …)` runs in every frame while the element is shown, with the phase from 0 to 1 within each period. It may move, fill and fade the element; it runs after layout and motion. While a cycle is shown, the window draws every refresh. Under a script, `advance` moves it.

## Idle windows

A window draws only when something changes: an input, a moving spring, a cycle, a caret that blinks, a timer that is due. Otherwise it waits and uses no CPU.
