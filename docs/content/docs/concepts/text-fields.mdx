Call `El.text(value).editable(onEdit)` to create a single-line text input, and add `.multiline()` for a multi-line editor capable of handling 100,000+ lines. Your app owns the string: you pass the current value on every build, and `onEdit` receives the updated string on each edit.

For styled inputs out of the box, use the kit's [TextField](/docs/components/text-field) and [CodeEditor](/docs/components/code-editor).

## Filtering or modifying edits

Your `onEdit` handler can reject an edit (by not updating state) or transform it (for example, keeping only digits). The field always displays your state's string and adjusts the cursor accordingly. If you replace the string programmatically, the undo history resets.

To inspect what changed between two strings, call `TextChange.between(before, after)` to get the UTF-16 start and exclusive end offsets in both strings.

## Preserving cursor and undo across tabs

By default, `App` tracks a field's cursor, selection, scroll offset, undo history (100 steps), and IME composition per element key, and discards them when the field leaves the tree (such as switching tabs).

To preserve cursor, selection, scroll position, and undo history across tab switches or windows, store a `FieldState` in your app state and pass it to `.fieldState(...)`. Active IME composition is not preserved and ends if the field leaves the tree. You can also set the selection ahead of the next build with `fieldState.select(caret, anchor)`.

From a handler (such as a button that inserts a snippet), call `fieldState.replaceSelection(text)`. It replaces the selection right after the handler, as one undo step. The cursor moves to the end of the inserted text, or to `caret` within it when you call `replaceSelection(text, caret)`. To replace a specific range instead of the selection, call `fieldState.replace(from, to, text, caret)`. It replaces characters `from` to `to`, and Ctrl+Z restores the previous selection. To follow the edits a field itself made (for example, to shift markup without diffing), call `fieldState.revision(text)` and `fieldState.editsSince(revision, text)`, which return sequential `TextEdit`s when all changes since `revision` came from the field.

## One document in several views

To show one text in several fields, such as a split editor, keep a `TextDocument` in your app state and give each field a `new FieldState(shared)`, or each `CodeEditor` a `new CodeEditor.State(shared)`. Every field still gets your string and your `onEdit` handler. The fields share one undo history; each keeps its own caret, selection, scroll, folds and blocks. An edit in one field moves the caret of the others by where the edit was.

To let two multi-line fields scroll together, give each a `ScrollState` and call `scrollWith` on one of them. Its `ScrollState.Anchor(line, otherLine)` pairs say which lines show the same place; between two anchors the lines are matched proportionally, and without anchors line n stays beside line n. Sideways both keep the same offset.

## Options

| Method | Description |
| --- | --- |
| `multiline()`, `lines(n)`, `fitLines()` | Multi-line mode; fixed height of `n` lines; or auto-height to fit all lines |
| `wrapText()` | Wraps long lines to the field width instead of horizontal scrolling. A single-line field without a set width grows to fit its text, up to the space its layout allows |
| `readOnly()`, `editable(null)` | Read-only (selectable/copyable) vs. disabled |
| `maxLength(n)` | Maximum length in Unicode code points |
| `masked()` | Password field (displays `•`) |
| `placeholder(text, argb)` | Placeholder text shown when empty |
| `codeWords()` | Treats letters, digits, `_`, and any extra characters from the highlighter (`Highlighter.wordCharacters()`, such as `$`) as word characters for Ctrl+Arrow and double-click |
| `highlight(key, highlighter)` | Syntax highlighting (colors, fonts, backgrounds, underlines) |
| `decorate(decorator)`, `alsoDecorate(decorator)` | Multi-line only: adds line highlights, search matches, or error underlines (`alsoDecorate` layers on top of an existing decorator) |
| `gutter(line -> cell)`, `gutter(cells, rail)` | Adds a left gutter (line numbers, markers) with an optional background rail |
| `folds(folds, unfold)`, `folds(folds, unfold, mark)` | Multi-line only: hides line ranges (`El.Fold(first, last)` keeps `first` shown with a placeholder mark and hides `first + 1` through `last`), calling `unfold` when the user clicks a mark, edits into a fold, or lands a selection/undo inside one |
| `blocks(blocks, block, reveal)` | Multi-line only: inserts elements before a line (`El.Block.insert(line)`) or replaces a whole-line range (`El.Block.replace(first, last)`), calling `reveal` when an edit, find, undo/redo, or selection enters a replaced range |
| `onTextPointerMove(handler)` | Multi-line only: calls `(position, modifiers)` when the character under the pointer or the held modifier keys change (`-1` when outside text, over a block band, past a line's end, or on a scrollbar) |
| `onTextHoverFor(seconds, handler)` | Multi-line only: calls `(position, modifiers)` once after the pointer rests on a character for `seconds` (suppressed after a press until moving) |
| `lineEnds(line -> elements)` | Multi-line only: places elements after the end of lines in view, such as inline blame or a diagnostic's message |
| `hints(hints, hint)` | Multi-line only: places inline hint elements (`El.Hint(at, affinity, text)`) inside lines, reserving width during shaping and wrapping |
| `coveredTop(height)` | Multi-line only: tells the field that something (such as a find bar) covers its top `height`. The field can scroll that far above its first line (where the scrollbar thumb sits at the top), and `app.select` scrolls selections into view below it |

See [`El` Javadoc](/api/com/rethinkj/ui/El.html#method-summary) for additional options (custom mask character, caret/selection colors, `tabIndents`, tab width, `onSelect`, and `textPositionAt(x, y)` to query the character offset at an element-local point). `onSelect` runs after every edit once your app has handled it, so its offsets always match your app's string. A field that is not in the tree, such as one in a row scrolled out of view, gets the call once it is back. If your app rejects an edit, `onSelect` reports the restored selection. The build right after an edit still sees the caret your `onSelect` handler stored before the edit. The following build, after `onSelect` runs, sees the new caret.

From event handlers, you can programmatically edit or undo/redo a field with `app.edit(field, from, to, text, caret)`, `app.edit(field, edits, caret)` (for several non-overlapping `TextEdit`s in one undo step), `app.select(field, caret, anchor)`, `app.undo(field)`, and `app.redo(field)`. You can also pass an `anchor` argument to `app.edit` to select text with the edit, and an `expected` string after it to skip the edit if the field's string changed before it runs. If your app rejects the edit, the selection stays unchanged.

## Folding lines

Pass `folds(List<El.Fold>, Consumer<El.Fold>)` on a multi-line field to collapse line ranges. Each `El.Fold(first, last)` keeps line `first` visible with a placeholder mark (`…` by default, or an element built by the three-argument overload's `mark` function) after its end and hides lines `first + 1` through `last`. Ranges may be unsorted, overlapping, or nested (a line is hidden if any fold hides it, and the outermost fold owns the visible mark); ranges past the end of the text are clamped or ignored.

- Your app owns the fold list and keeps its line indices current with the field's string; core never mutates fold state.
- Scrolling, line backgrounds, wrapping, hit testing, and the gutter skip hidden lines while `El.Gutter.Line.index()` stays the real line index.
- Arrow keys, Home/End, and Page Up/Down (with or without Shift) skip hidden lines and never leave the caret inside a fold. A selection spanning a fold still contains the hidden lines, so copying keeps them.
- Clicking a fold's placeholder mark (keyed `fold-<first>` in tree dumps unless the mark sets its own key), making an edit whose range touches a hidden line, or placing the caret or selection end on a hidden line via `app.select`, `FieldState.select`, or undo/redo calls `unfold` with the affected fold.

## Blocks between lines

Pass `blocks(List<El.Block>, Function<El.Block, El>, Consumer<El.Block>)` on a multi-line field to place elements between lines in two placements: `El.Block.insert(line)` inserts vertical space before `line` (or after the last line when `line` equals the line count) without hiding text, and `El.Block.replace(first, last)` hides every line from `first` through `last` inclusive and shows its element in place of them. Call `.lines(n)` on a block to fix its height to an exact number of text lines instead of measuring its element.


- Your app owns the block list and keeps its line indices current with the field's string; core never mutates block state. `REPLACE` blocks must not overlap each other, and several `INSERT` blocks before the same line stack in list order.
- Block elements are built only while in view, laid out at the field's content width, and keyed `block-<first>` (and `block-<first>-<n>` for further blocks at the same line) unless they set a key; explicit keys of blocks at the same line must differ. In a field that does not wrap, blocks scroll sideways with the text and are cut off at the content box, so they never cover the gutter; like line-end elements, they do not widen the scroll range. An enclosing fold hides blocks inside it, and while an empty field shows its placeholder, `INSERT` blocks anchored to line 0 still show.
- Up and Down step over blocks, Left and Right jump across replaced ranges, and Home/End never land inside one. Selections stay in source text, tint covered blocks, and copy hidden lines without revealing them.
- Interactive elements inside a block take presses (without moving the focus, showing their `whenPressed` look while held), drags, keyboard focus (Tab and Shift+Tab visit focusable controls in order), and text input (editable fields take focus and typing without changing the outer field's caret or text). A look that makes a block higher moves the rows below it. Overlays opened from an element in a block take and restore the focus like other overlays. Pressing elsewhere in the block band places the caret at the start of the following line. An edit touching a replaced range, or a caret or selection end placed inside one by find, undo/redo, `app.select`, or `FieldState.select`, calls `reveal`.
- Gutter line numbers stay source line numbers: inserted blocks get no gutter cell, and each replaced range gets one cell at the block's top spanning `first` through `last`, bounded and clipped to the block's band when the block is shorter than a row.

## Elements after a line's end

Pass `lineEnds(IntFunction<List<El>>)` on a multi-line field to place elements after the end of a line, such as inline blame or a diagnostic's message. The function gets a line index and returns that line's elements, or an empty list for none.


- Elements are built only for shown lines whose last row is in view, never for folded or replaced lines, and laid out left to right after the line's end, after the fold mark if the line starts a fold.
- In tree dumps an element is keyed `end-<line>` (and `end-<line>-<n>` for the `n`-th further element on the line) unless it sets a key.
- A press on a line-end element runs its own press handler and shows its `whenPressed` look without moving the caret or the focus; focusable elements in one are reachable by Tab, and editable fields take focus and typing.
- Line-end elements do not widen the field or its scroll range: one that reaches past the content box is cut off at its edge.

## Inline inlay hints

Pass `hints(List<El.Hint>, Function<El.Hint, El>)` on a multi-line field to place inline elements inside a line without turning them into editable text — such as parameter names (`folder:`) or inferred types (`: List<Path>`). Each `El.Hint(at, affinity, text)` takes a UTF-16 offset into the field's string, an `El.Hint.Affinity` (`BEFORE` belongs to the text before `at`, `AFTER` belongs to the text after `at`), and the hint text.


- Your app owns the hint list and keeps its offsets current with the field's string; core keeps no hint state of its own.
- Hint widths are reserved during shaping and wrapping (applied before tab stops so tabs stay on the grid). Elements are placed only for rows in view, vertically centered in the row, and keyed `hint-<at>` (and `hint-<at>-<n>` for further hints at the same offset) unless they set a key; explicit keys of hints at the same offset must differ. Hints in folded or replaced lines do not show.
- Horizontal stepping with Left and Right stops on both sides of a hint (and between a `BEFORE` group and an `AFTER` group at the same offset); word moves, Home/End, vertical moves, and edits use the default stop between the two groups. A `BEFORE` hint that ends a wrapped row has no stop on its left: the caret at its offset shows at the start of the next row.
- Copy and cut ignore hints, selections highlight a hint only when it lies strictly inside the selected range, and `textPositionAt(x, y)` reports `-1` over a hint.
- A press on an interactive hint runs its own press handler without moving the caret or focus; a press on a non-interactive hint places the caret at that offset at the nearer stop, or, on a hint that ends a wrapped row, at the nearest position of that row. Focusable hints are reachable by Tab, and a look that changes a hint's width reshapes its line so the text after it moves.

## Built-in keyboard and mouse shortcuts

- **Navigation & selection:** Arrow keys, Home, End, Page Up/Down (with **Shift** to select and **Ctrl** to jump by word), double-click to select a word, triple-click to select a line.
- **Editing:** Backspace, Delete, **Ctrl+A** (select all), **Ctrl+C/X/V** (copy/cut/paste), **Ctrl+Z** (undo), **Ctrl+Y** / **Ctrl+Shift+Z** (redo).
- **Multi-line:** **Enter** inserts a newline (auto-indenting when `tabIndents` is enabled). **Ctrl+Enter** bubbles to your app's `onKey` handlers, and **Enter** also bubbles in a read-only field.
- **IME:** Input methods compose inline with an underline (shown as `composing "…"` in tree dumps). Making the field read-only ends any active composition, just like losing focus.
