Call `El.text(value).editable(onEdit)` to create a single-line text input, and add `.multiline()` for a multi-line editor capable of handling 100,000+ lines. Your app owns the string: you pass the current value on every build, and `onEdit` receives the updated string on each edit.

For styled inputs out of the box, use the kit's [TextField](/docs/components/text-field) and [CodeEditor](/docs/components/code-editor).

## Filtering or modifying edits

Your `onEdit` handler can reject an edit (by not updating state) or transform it (for example, keeping only digits). The field always displays your state's string and adjusts the cursor accordingly. If you replace the string programmatically, the undo history resets.

To inspect what changed between two strings, call `TextChange.between(before, after)` to get the UTF-16 start and exclusive end offsets in both strings.

## Preserving cursor and undo across tabs

By default, `App` tracks a field's cursor, selection, scroll offset, undo history (100 steps), and IME composition per element key, and discards them when the field leaves the tree (such as switching tabs).

To preserve cursor, selection, scroll position, and undo history across tab switches or windows, store a `FieldState` in your app state and pass it to `.fieldState(...)`. Active IME composition is not preserved and ends if the field leaves the tree. You can also set the selection ahead of the next build with `fieldState.select(caret, anchor)`.

From a handler (such as a button that inserts a snippet), call `fieldState.replaceSelection(text)`. It replaces the selection right after the handler, as one undo step. The cursor moves to the end of the inserted text, or to `caret` within it when you call `replaceSelection(text, caret)`. To replace a specific range instead of the selection, call `fieldState.replace(from, to, text, caret)`. It replaces characters `from` to `to`, and Ctrl+Z restores the previous selection.

## Options

| Method | Description |
| --- | --- |
| `multiline()`, `lines(n)`, `fitLines()` | Multi-line mode; fixed height of `n` lines; or auto-height to fit all lines |
| `wrapText()` | Wraps long lines to the field width instead of horizontal scrolling. A single-line field without a set width grows to fit its text, up to the space its layout allows |
| `readOnly()`, `editable(null)` | Read-only (selectable/copyable) vs. disabled |
| `maxLength(n)` | Maximum length in Unicode code points |
| `masked()` | Password field (displays `•`) |
| `placeholder(text, argb)` | Placeholder text shown when empty |
| `codeWords()` | Treats letters, digits, `_`, and any extra characters from the highlighter (`Highlighter.wordCharacters()`, such as `$`) as word characters for Ctrl+Arrow and double-click |
| `highlight(key, highlighter)` | Syntax highlighting (colors, fonts, backgrounds, underlines) |
| `decorate(decorator)`, `alsoDecorate(decorator)` | Multi-line only: adds line highlights, search matches, or error underlines (`alsoDecorate` layers on top of an existing decorator) |
| `gutter(line -> cell)`, `gutter(cells, rail)` | Adds a left gutter (line numbers, markers) with an optional background rail |
| `folds(folds, unfold)`, `folds(folds, unfold, mark)` | Multi-line only: hides line ranges (`El.Fold(first, last)` keeps `first` shown with a placeholder mark and hides `first + 1` through `last`), calling `unfold` when the user clicks a mark, edits into a fold, or lands a selection/undo inside one |
| `coveredTop(height)` | Multi-line only: tells the field that something (such as a find bar) covers its top `height`. The field can scroll that far above its first line (where the scrollbar thumb sits at the top), and `app.select` scrolls selections into view below it |

See [`El` Javadoc](/api/com/rethinkj/ui/El.html#method-summary) for additional options (custom mask character, caret/selection colors, `tabIndents`, tab width, and `onSelect`). `onSelect` runs after every edit once your app has handled it, so its offsets always match your app's string. A field that is not in the tree, such as one in a row scrolled out of view, gets the call once it is back. If your app rejects an edit, `onSelect` reports the restored selection. The build right after an edit still sees the caret your `onSelect` handler stored before the edit. The following build, after `onSelect` runs, sees the new caret.

From event handlers, you can programmatically edit or undo/redo a field with `app.edit(field, from, to, text, caret)`, `app.select(field, caret, anchor)`, `app.undo(field)`, and `app.redo(field)`. You can also pass an `anchor` argument to `app.edit` to select text with the edit. If your app rejects the edit, the selection stays unchanged.

## Folding lines

Pass `folds(List<El.Fold>, Consumer<El.Fold>)` on a multi-line field to collapse line ranges. Each `El.Fold(first, last)` keeps line `first` visible with a placeholder mark (`…` by default, or an element built by the three-argument overload's `mark` function) after its end and hides lines `first + 1` through `last`. Ranges may be unsorted, overlapping, or nested (a line is hidden if any fold hides it, and the outermost fold owns the visible mark); ranges past the end of the text are clamped or ignored.

- Your app owns the fold list and keeps its line indices current with the field's string; core never mutates fold state.
- Scrolling, line backgrounds, wrapping, hit testing, and the gutter skip hidden lines while `El.Gutter.Line.index()` stays the real line index.
- Arrow keys, Home/End, and Page Up/Down (with or without Shift) skip hidden lines and never leave the caret inside a fold. A selection spanning a fold still contains the hidden lines, so copying keeps them.
- Clicking a fold's placeholder mark (keyed `fold-<first>` in tree dumps unless the mark sets its own key), making an edit whose range touches a hidden line, or placing the caret or selection end on a hidden line via `app.select`, `FieldState.select`, or undo/redo calls `unfold` with the affected fold.

## Built-in keyboard and mouse shortcuts

- **Navigation & selection:** Arrow keys, Home, End, Page Up/Down (with **Shift** to select and **Ctrl** to jump by word), double-click to select a word, triple-click to select a line.
- **Editing:** Backspace, Delete, **Ctrl+A** (select all), **Ctrl+C/X/V** (copy/cut/paste), **Ctrl+Z** (undo), **Ctrl+Y** / **Ctrl+Shift+Z** (redo).
- **Multi-line:** **Enter** inserts a newline (auto-indenting when `tabIndents` is enabled). **Ctrl+Enter** bubbles to your app's `onKey` handlers, and **Enter** also bubbles in a read-only field.
- **IME:** Input methods compose inline with an underline (shown as `composing "…"` in tree dumps). Making the field read-only ends any active composition, just like losing focus.
