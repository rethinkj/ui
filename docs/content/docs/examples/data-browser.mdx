DataBrowser shows a million orders in the kit's [DataGrid](/docs/components/data-grid), flush in a card with a filter in its toolbar and the status in its footer. Its cells edit, and the changes wait until Commit.

<Shot dark="examples/browser-dark" light="examples/browser-light" alt="The grid with pending changes marked, a filter on the status column, a filter bar and Commit (n) in the toolbar" />

```sh
mvn -q -pl examples -am compile exec:exec -Dexample=DataBrowser
```

## What to try

- Type words into Filter: the rows that hold each word in a text column stay.
- Double-press a cell to edit it, then Commit or press Control+S; Revert forgets the changes.
- Filter a column from its header, and choose the columns with Columns.

## How it works

### A typed table

The orders are records, and each column is a typed value of an `Order`: a getter, a [Format](/docs/components/format) and, for the columns that edit, a wither ([Rows of records](/docs/components/data-grid/typed)).


### Pending changes

The edits wait in a `GridChanges`. Its `Rows` give each row shown a key, here the order's number, so that a change stays with its order while the filter or the sort moves the rows ([Editing and changes](/docs/components/data-grid/editing)).

```java snippet="data-browser-changes"
```

Commit takes the changes as typed values and applies them to the orders: changed orders are kept beside the made-up ones, new orders come after the million, and deleted orders leave the rows.
