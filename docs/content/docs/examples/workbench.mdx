Workbench is a database manager demo using mock servers that respond slowly on background threads. It shows how to keep a complex desktop app responsive while loading data.

**Demonstrates:** [Tree](/docs/components/tree), [TabGroups](/docs/components/tab-groups), [CodeEditor](/docs/components/code-editor), [Completion](/docs/components/completion), [DataGrid](/docs/components/data-grid), [CommandPalette](/docs/components/command-palette), and [Background work](/docs/concepts/background-work).

<Shot dark="examples/workbench-dark-2x" light="examples/workbench-light-2x" alt="The Workbench: a tree of connections, a query editor and a result grid in cards" />

## Run it

From the cloned repository root (see [Build from source](/docs/get-started/from-source)):

```sh
mvn -q -pl examples -am compile exec:exec -Dexample=Workbench
```

## What to try

- Expand `staging` in the tree: it connects in the background with a loading spinner. `prod-eu` fails to connect and shows the reason in the status bar.
- Double-click a table (or press Enter) to open it in a tab. `localhost/shop/public/orders` loads one million rows.
- Type inside the SQL editor: autocomplete suggests columns, tables, and SQL keywords. Press **Ctrl+Enter** to run the query. Unknown table names are underlined as errors.
- Press **Ctrl+Shift+P** to open the command palette (`@` searches tables, `:` jumps to a line).
- Drag a tab outside the window to tear it off into its own window, drag it back to dock it, or right-click a tab (or press **Ctrl+\**) to split groups side by side or stacked within any window.
