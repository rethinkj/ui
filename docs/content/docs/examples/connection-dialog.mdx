ConnectionDialog is a standalone dialog window featuring a [Form](/docs/components/form) for database connection details (host, port, database, user, and password) with field validation and a default **Connect** button.

**Demonstrates:** [Form](/docs/components/form), [Editing records](/docs/concepts/editing), [TextField](/docs/components/text-field), [ComboBox](/docs/components/combo-box), [TitleBar](/docs/components/title-bar), and [Dialog](/docs/components/dialog).

## Run it

From the cloned repository root (see [Build from source](/docs/get-started/from-source)):

```sh
mvn -q -pl examples -am compile exec:exec -Dexample=ConnectionDialog
```

## What to try

- Fill in the fields: **Connect** stays disabled until host, port, database, and user are all filled in.
- Enter a port other than `5432` and click **Connect**: the port field displays a connection error.
- Enter `postgres` as the user with a host other than `localhost`: a cross-field validation rule shows an error on the user field.
- Press **Enter** inside any text field to submit the form.

### Editing and validation rules

The form edits a `Profile` record using `Editing`, which tracks draft text and validation errors ([Editing](/docs/concepts/editing)). A cross-field rule validates `user` and `host` together. **Connect** is enabled only when the form is valid, modified, and complete. A failed connection attaches an error directly to the port field:

```java snippet="connection-dialog-editing"
```

### Form fields

Each field binds to a property via `editing.at(...)`. The port uses an `Integer` `ValueField`, the database uses an editable [ComboBox](/docs/components/combo-box) with suggestions, and the password uses a [TextField](/docs/components/text-field) with a show/hide toggle. Passing a `null` handler disables a button:


`Dialog.enterPresses(connect)` makes pressing **Enter** in any single-line field trigger **Connect**, while a focused button or checkbox still activates itself:
