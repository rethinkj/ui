`options().filters(filters, onFilter)` adds a filter icon to each column header that opens a popover matched to the column type (text contains/starts with/equals/regex, numeric/date ranges — with a [DatePicker](/docs/components/date-picker) calendar button on `DATE` and `DATE_TIME` fields — boolean/choice checkboxes, searchable and scrolling when there are more than eight choices, and `IS NULL` / `NOT NULL`).

`DataGrid` does not filter data itself: it passes updated `DataGrid.Filter` records to `onFilter` so your app can filter in SQL or in memory with `filter.matches(...)`.

Javadoc: [`DataGrid.Filter`](/api/com/rethinkj/ui/kit/DataGrid.Filter.html).

## `Filter` API

A `Filter` is a column and a `Spec`, a sealed type with one record per shape of filter:

| Spec | Keeps |
| --- | --- |
| `new TextMatch(Kind, value)` | Text that `CONTAINS`, `STARTS_WITH` or `EQUALS` the value, whatever the case, or `EXACTLY` (the value exactly, case and all) |
| `new RegexMatch(expression)` | Text in which a case-insensitive regular expression finds a match; compiled once, it throws `PatternSyntaxException` for an invalid expression |
| `new Between(from, to)` | A range, as numbers where both ends are (leave either end empty for an open end) |
| `new OneOf(values)` | Any listed value |
| `new NullCheck(isNull)` | `NULL`, or not `NULL` |

Filters are equal when their column and spec are, a `RegexMatch` by its expression. To translate a filter to SQL, switch over `filter.spec()`.

| Method | Description |
| --- | --- |
| `filter.matches(cell)` | Returns `true` if a cell's text matches (for in-memory filtering) |
| `filter.describe(title)` | Human-readable summary used on filter badges |

Use `options().filterable(column -> …)` to enable filters only on specific columns. Press **Alt+ArrowDown** to open the filter popover for the active column.
