`DataGrid` supports inline cell editing matched to each column's data type. Use `GridChanges` to stage edited cells, inserted rows, and deleted rows on top of your data with built-in undo/redo until the user clicks Commit.

Javadoc: [`GridChanges`](/api/com/rethinkj/ui/kit/GridChanges.html), [`DataGrid.Options`](/api/com/rethinkj/ui/kit/DataGrid.Options.html).

- Store `GridChanges` and `DataGrid.Selection` in your app state.
- Create `new GridChanges(count, (row, column) -> value)` (or pass a `GridChanges.Rows` with stable row keys if your app sorts or filters rows).
- Wire column cells through `changes.cell(column)`, row count through `changes.rowCount()`, and pass `options().changes(changes)` to automatically enable editing, pasting, inserting/deleting rows, status highlights, and Ctrl+Z / Ctrl+Y undo/redo.
- Read `changes.count()` for a badge like `"Commit (n)"`, iterate `changes.changes()` to save `UPDATE`/`INSERT`/`DELETE` operations, and call `changes.clear()` after saving or reverting.
- Call `changes.error(row, column, message)` to highlight cells rejected by your database.

## Built-in cell editors

| Column type | Editor |
| --- | --- |
| Text | Inline single-line field (Alt+Enter or multi-line values open a 6-line popup editor) |
| `INTEGER`, `DECIMAL` | Validated numeric input |
| `BOOLEAN` | Toggles directly on Space, Enter, F2, or double-click (`false` / `true` / `NULL` if nullable) |
| `choices(list)` or `ENUM` | Dropdown menu (up to 8 choices) or searchable listbox (more than 8) |
| `DATE`, `TIME`, `DATE_TIME` | Validated ISO 8601 text (`2026-11-13`, `14:30`, `2026-11-13 14:30`) |
| `editor((value, onChange) -> El)` | Custom editor element |

In `nullable()` columns, `NULL` appears as muted placeholder text; typing enters a string, and **Ctrl+0** sets `NULL`. Invalid values keep the editor open with an error message below it.

## Custom editing without `GridChanges`

For typed records or POJOs, use `options().onCommit(table, (row, value) -> error)` (see [Rows of records](/docs/components/data-grid/typed)). Or wire individual hooks manually:

| Option | Description |
| --- | --- |
| `onCommit((row, column, value) -> error)` | Accepts an edit (`return null`) or rejects it with an error message |
| `onPaste(cells)` | Receives pasted `CellValue(row, column, value)` entries in one batch |
| `onInsertRow(after)`, `onDeleteRows(ranges)`, `appendRow()` | Row insertion/deletion (`appendRow()` adds a trailing `*` row for quick entry) |
| `status(rows, cells)` | Row/cell status badges (`CHANGED`, `NEW`, `DELETED`, `ERROR`) |
| `errors((row, column) -> message)` | Error tooltip message for cells with `Status.ERROR` |
| `history(undo, redo)` | Custom Ctrl+Z / Ctrl+Y handlers |
| `onEdit((row, column) -> …)` | Handle cell editing completely yourself |

| `Selection` method | Description |
| --- | --- |
| `commitEdit()` | Commits and closes the open editor; returns `false` if rejected |
| `cancelEdit()` | Discards edits and closes the editor |
| `isEditing()` | Whether a cell editor is currently open |
| `editingRow()`, `editingColumn()` | Active editor cell coordinates (`-1` if none) |
| `draft()` | Current text in the open editor |

With `GridChanges`, an open editor tracks its row by key across sorts and filters. Without `GridChanges`, call `commitEdit()` or `cancelEdit()` before reordering or replacing rows.

## Showing database errors

When a backend commit fails, mark the rejected cells with `changes.error(change, column, message)` (or `changes.error(row, column, message)`) and keep pending changes so the user can fix them. Error cells show a danger border, error tooltip, and `invalid` in tree dumps, and clear automatically when edited or undone.

## `GridChanges` helper methods

| Method | Description |
| --- | --- |
| `count()`, `isEmpty()` | Number of pending row changes |
| `canUndo()`, `canRedo()`, `undo()`, `redo()` | Undo/redo history state and actions |
| `changes()`, `changes(table, columns)` | List of pending changes (as text or typed values via [GridTable](/docs/components/data-grid/typed)) |
| `set(row, column, value)`, `set(cells)` | Programmatically stage cell edits as one undo step |
| `rows(rows)` | Update underlying `Rows` after sorting or filtering while preserving keyed changes |

See [`GridChanges` Javadoc](/api/com/rethinkj/ui/kit/GridChanges.html) for more methods.

## Keyboard

| Key | Action |
| --- | --- |
| Enter, F2, double-click, typing | Open cell editor |
| Enter / Shift+Enter | Commit and move down / up (inserts newline in multi-line editor) |
| Tab / Shift+Tab | Commit and move right / left |
| Ctrl+Enter | Commit and stay (also commits multi-line editor) |
| Escape | Cancel edit |
| Delete | Clear selected cells (`NULL` if nullable, else empty string) |
| Ctrl+0 | Set `NULL` |
| Ctrl+V, Shift+Insert | Paste tab-separated values |
| Insert, Ctrl+Plus | Insert row below cursor |
| Ctrl+Minus, Ctrl+Delete | Mark selected rows deleted |
| Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z | Undo / redo (when no editor is open) |

## In a tree dump

Changed rows show `value="changed"`, `"new"`, `"deleted"`, or `"error"`. Cells show `value="changed"` or `"error"` (otherwise their column [detail](/docs/components/data-grid#details)) and `invalid` on errors. An open editor appears as `#editor` with `#field` (`role=textbox`), and validation errors appear as `role=alert`.
