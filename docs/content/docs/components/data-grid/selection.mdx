A `DataGrid.Selection` holds the grid's cursor, the anchor that Shift extends from, and the selected ranges. The app keeps it in its state, and the grid changes it as the user selects. Pass it with `options().select(selection)` to make the grid selectable; most other options need it.

Javadoc: [`DataGrid.Selection`](/api/com/rethinkj/ui/kit/DataGrid.Selection.html), [`DataGrid.Commands`](/api/com/rethinkj/ui/kit/DataGrid.Commands.html).

## Copying

`options().copy(clipboard)` lets Control+C and Control+Insert put the selection on the clipboard as tab-separated lines: the rows and columns that have a selected cell. A field is quoted only where a tab, a line break or a quote needs it, and when it is an empty field alone on the last line. Pass `app.clipboard()`, which is the system's clipboard in a window and an in-memory one under a script.

| Option | |
| --- | --- |
| `nullText(String)` | What a copied `NULL` is; `""` unless set, as spreadsheets read an empty cell |
| `copyLimit(cells)` | The most cells the grid copies itself; 100 000 unless set |
| `onLargeCopy(handler)` | Gets a larger copy, or one with rows not loaded, as a `Copy` (ranges, headers, cell count) with the cell limit. The handler builds the text with `DataGrid.copyText` on another thread, fetches it from the database, or tells the user why nothing was copied |
| `copyLimit(cells, handler)` | Sets the limit and the handler in one call |
| `contextMenu(menuState, items)` | Adds Copy and Copy with headers to the grid's menu, before your items. Paste, Set NULL, Insert row and Delete rows follow when their handlers are set, and a submenu `Column <title>`, where the column has header items, holds the header's items for the cursor's column: the keyboard's way to sort, filter, hide, freeze and fit it |

`DataGrid.copyText(columns, ranges, headers, nullText)` builds the same text from your code, and `DataGrid.parseText(text)` reads it back into rows of cells.

## Commands from an external menu

Keep a `DataGrid.Commands` in the app's state and pass it with `options().commands(handle)` on each build, as the example above does. Its `run(command)` runs `DataGrid.Command.COPY`, `COPY_WITH_HEADERS`, `PASTE` or `SELECT_ALL` from a handler on the app's thread. `canRun(command)` tells a menu whether to enable the item:

```java snippet="grid-command"
```

- The handle uses the last build's columns, rows, selection, clipboard and handlers. Pass it even when that build has no selection or editing handlers. One handle belongs to one grid at a time; before the first build, commands do nothing.
- Commands work as the keys do, with the same limits and checks. Copy needs selected cells and a clipboard. Paste needs a cursor on a data row, a clipboard and an `onPaste` handler. Select all needs rows. `run` leaves the focus where it is.
- While a cell editor is open, the commands are unavailable, and the editor keeps its own text selection and clipboard keys. A press on a menu title closes a single-line editor and hands on its value first, as any press outside does. When the value is refused, the editor stays open with its error and the commands stay unavailable.

## The state

| Method | |
| --- | --- |
| `row()`, `column()` | The cursor's cell |
| `ranges()` | The selected `Range`s: `top`, `left`, `bottom`, `right`, inclusive; `Range.ALL` columns for whole rows |
| `select(row, column)`, `selectAll(rowCount)`, `clear()` | Select from the app's own handlers |
| `reset()` | Clear everything and scroll back to the start, for a new result |

The anchor, questions such as `contains(row, column)`, and `extend` and `toggle` are on [`DataGrid.Selection`](/api/com/rethinkj/ui/kit/DataGrid.Selection.html).

`onSelect(handler)` tells the app when the selection changes, for a status line such as "3 cells selected". `DataGrid.cellCount(ranges, columns)` counts the cells.

With `options().changes(changes)`, the selection follows its rows by their keys when the app sorts, filters, inserts or removes rows. So Delete, Control+Minus, Control+0 and a paste act on the rows the user selected. A range that a sort tears apart becomes several. When the cursor's row is gone, the cursor goes to the nearest remaining row; when every selected row is gone, the selection shrinks to the cursor. A selection of more than `Selection.FOLLOWED_ROWS` (10 000) rows shrinks to the cursor when its rows move. Without keys, the selection stays on its row indexes, so an app that reorders rows calls `clear()` or `reset()`.

The selection also keeps where the grid is scrolled to, so a grid built again with it, after its tab was away or in another window, comes back to the same rows and columns. One selection belongs to one grid at a time.

## What the user does

- A press selects as the button goes down. Shift extends from the anchor; Control adds or removes.
- Dragging from a cell or a row number extends to the cell under the pointer. Beyond an edge, the grid scrolls. A drag that begins below the rows or right of the columns changes nothing.
- A press on a row number selects the row.
- The arrows, Page Up and Page Down, Home and End move the cursor; with Shift they extend the selection. Control+A selects all. The grid scrolls to keep the cursor in view.
