## Copying

Pass `options().copy(app.clipboard())` to enable **Ctrl+C** and **Ctrl+Insert** copying as tab-separated values (TSV).

| Option | Description |
| --- | --- |
| `nullText(String)` | Text exported for `NULL` cells (default `""`) |
| `copyLimit(cells)` | Max cells copied synchronously (default `100,000`) |
| `onLargeCopy(handler)` | Called when a copy exceeds the limit or includes unloaded rows, so you can export in the background |
| `copyLimit(cells, handler)` | Sets both limit and handler together |
| `contextMenu(menuState, items)` | Adds Copy, Copy with headers, Paste, Set NULL, Insert/Delete row, and a `Column <title>` submenu before your custom items |

Use `DataGrid.copyText(columns, ranges, headers, nullText)` and `DataGrid.parseText(text)` to format or parse TSV directly.

## `Selection` API

| Method | Description |
| --- | --- |
| `row()`, `column()` | Active cursor coordinates |
| `ranges()` | Selected `Range`s (`top`, `left`, `bottom`, `right`, inclusive; `Range.ALL` for full rows) |
| `select(row, column)`, `selectAll(rowCount)`, `clear()` | Update selection from handlers |
| `reset()` | Clear selection and scroll back to top-left (call when loading a new dataset) |
| `scrollToRow(row)` | Scroll `row` to the top on the next build (or as far as the end allows); keeps the selection |
| `firstRowInView()`, `lastRowInView()` | First and last row fully in view (not covered by the horizontal scrollbar); `-1` before layout or when no full row fits |

Use `onSelect(handler)` to update a status bar (e.g., `"3 cells selected"`), and `DataGrid.cellCount(ranges, columns)` to count selected cells.

For buttons that page through a long result, call `scrollToRow`. For example, `scrollToRow(lastRowInView() + 1)` moves one page forward. Later builds do not jump back to the cursor. Once the cursor moves to another row, the grid scrolls to show it as usual. Calling `firstRowInView()` and `lastRowInView()` does not trigger a rebuild. If you build a status line (such as "Rows 201–223") after the grid, those methods reflect the grid's latest build, including where that build scrolled to. The grid height and horizontal scrollbar state come from the previous layout until the next layout runs.

To keep a status line or paging buttons up to date while the user scrolls, pass `options().onRowsInView((first, last) -> …)`. It runs and rebuilds the view only when `first` or `last` changes, including after a single-row scroll or `scrollToRow`. It passes `-1, -1` when no full row fits. Scrolling that does not change either row triggers no rebuild. If `loading` is also notified in the same frame, both share one rebuild. `onRowsInView` works without `select`.

With `options().changes(changes)`, selections follow rows by key across sorts and filters (up to `Selection.FOLLOWED_ROWS`, 10,000 rows). Without keys, call `clear()` or `reset()` when reordering rows. `Selection` also preserves scroll position across tab switches.

## Mouse and keyboard interaction

- Click to select; **Shift+click** extends a range; **Ctrl+click** adds or removes ranges; drag to select across cells.
- Click a row number to select the whole row.
- Arrow keys, Page Up/Down, Home, End (with **Shift** to extend), and **Ctrl+A** select all.
