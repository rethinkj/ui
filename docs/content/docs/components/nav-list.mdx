`NavList.navList` displays a vertical list of selectable navigation items with optional icons, count badges, indentation, and section headings. Use it for app sidebars and settings pages.

For hierarchical expandable data, use [Tree](/docs/components/tree). For horizontal tabs, use [Tabs](/docs/components/tabs).

Javadoc: [`NavList`](/api/com/rethinkj/ui/kit/NavList.html).

| Method | Description |
| --- | --- |
| `navList(entries, selected, onSelect)` | List of `NavList.Entry` items and headings (`selected` index includes headings) |
| `navList(count, index -> entry, selected, onSelect)` | Virtualized list for large navigation lists |
| `outline(entries, current, onPress)` | Table of contents that marks the `current` heading and tells every press, also one on the current item or Enter or Space on it, so a press goes back to its heading |
| `NavList.item([icon,] label)` | Navigation item with optional `.detail(text)`, `.count(text)`, `.trailing(element)`, `.actions(buttons...)`, `.contextMenu(state, items)`, `.indent(levels)`, `.key(name)`, and `.disabled(true)` |
| `NavList.heading(label)` | Non-selectable section heading with optional `.leading(element)`, `.count(text)`, `.actions(buttons...)`, and `.open(open, onToggle)` |
| `NavList.group(label)` | Group header on a quiet filled surface with strong text, optional `.leading(element)`, `.count(text)`, `.actions(buttons...)`, and a far-right chevron with `.open(open, onToggle)` |

Inside a card, wrap the list with `Card.inset(list)`.

## Second line, trailing elements, and group headers

Items can carry a quiet second line (`.detail(text)`), a trailing element after the count (`.trailing(element)`, such as a time the app formats and a status icon), and action buttons at the far right (`.actions(buttons...)`) that show only while the item is selected or under the pointer; pressing one does not select the item.

Headings can carry a passive leading element (`.leading(element)`, such as an [Avatar](/docs/components/avatar)), a quiet count (`.count(text)`), always-visible action buttons at the right end (`.actions(buttons...)`), and an open/close toggle (`.open(open, onToggle)`): the app keeps which groups are open and leaves a closed group's items out of the entries. Use `NavList.group(label)` for a group header on a quiet filled surface with strong text and its chevron at the far right, or `NavList.heading(label)` for a plain caption heading. Heading actions sit as siblings of the toggle button, so pressing one never toggles the group, and a disabled list (`onSelect` is `null`) leaves them disabled and inert.

Heading actions are icon-sized, such as `Button.icon`: a collapsible heading keeps room for each by its set width and height, else that of one control.

All rows share one height, so that the virtual form stays virtual: two lines high when any item has a detail, or in the virtual form when its first item has one.

## Context menus

Items can carry a per-row context menu with `.contextMenu(state, items)`. One `Menu.State` can be shared across all items of a list. Right-clicking a row opens that row's menu without changing the selection; **Shift+F10** or the **Menu** key while the list has focus opens the selected row's menu. Disabled items and disabled lists (`onSelect` is `null`) open no menu.

## Keyboard

The list is one Tab stop: **Up**, **Down**, **Home**, **End**, **Page Up**, and **Page Down** move selection, skipping headings and disabled items, and **Shift+F10** or the **Menu** key opens the selected row's context menu. Collapsible headings are focusable buttons; **Enter** or **Space** while focused runs `onToggle`, and **Tab** moves from the toggle to its heading actions.

## In a tree dump

`role=listbox` (`disabled` if `onSelect` is `null`). Items are `role=option` with `selected`/`disabled`, `pos`, and key `#item-<index>` (unless `.key(...)` is set), with any detail text, trailing element, and action buttons as children, and an open row context menu attached as an overlay on that row (so scripts can open it with `press <row> right`), or on the list when a key opened it. Plain headings have no role; collapsible headings are `role=button` with `expanded` or `expanded=false`, with any heading actions as siblings after the toggle:
