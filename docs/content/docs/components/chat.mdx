`Chat` provides the building blocks of a chat transcript and composer in the theme's tokens: right-aligned plain or composed user message bubbles up to `Theme.Chat.bubbleWidth()`, collapsible or static context blocks, full-width agent answers rendered with `Markdown.fragment` or composed from parts, collapsible one-line tool call rows, quiet collapsible tool call groups with an optional latest-step preview, a quiet working indicator with a spinner, and a growing multi-line composer with an action bar.

Javadoc: [`Chat`](/api/com/rethinkj/ui/kit/Chat.html), [`Chat.Options`](/api/com/rethinkj/ui/kit/Chat.Options.html), [`Chat.ComposerOptions`](/api/com/rethinkj/ui/kit/Chat.ComposerOptions.html), [`Chat.ToolState`](/api/com/rethinkj/ui/kit/Chat.ToolState.html), [`Chat.Step`](/api/com/rethinkj/ui/kit/Chat.Step.html).

## Options

Configure message footers and Markdown rendering with `Chat.options()`:

| Option | Description |
| --- | --- |
| `time(text)` | Muted timestamp shown in tabular figures under the message |
| `copy(clipboard)` | Adds a quiet copy button that writes the message text (or `Markdown.text(document)`) to `clipboard`; no copy button is shown on composed `user(options, parts…)` or `agent(options, parts…)` messages without explicit text |
| `copy(clipboard, text)` | Adds a quiet copy button that writes explicit `text` to `clipboard` (for composed `user(options, parts…)` and `agent(options, parts…)` messages, or when copying source text other than the rendered plain text) |
| `copied(Button.Copied)` | Enables brief check-mark and tooltip confirmation on the copy button (and on code blocks in `agent(document, options)` when `markdown(...)` is omitted); keep one `Button.Copied` per message |
| `actions(El…)` | Adds extra quiet actions (such as ghost icon buttons) to the message footer |
| `markdown(Markdown.Options)` | Forwards custom `Markdown.Options` to `Markdown.fragment` in `agent(document, options)` |

## Tool calls

`Chat.tool` renders as a quiet, borderless single-line row—the same row `Chat.toolGroup` uses for each step—aligned with the surrounding prose, with hover and focus feedback. It is controlled: keep each tool call's `open` boolean in your app state and pass a toggle handler in `onToggle` (or `null` to disable expanding). While `open` is `false`, the row shows an optional leading icon, an ellipsized title, a state mark (`Progress.spinner()` while `RUNNING`, check mark when `DONE`, error icon when `FAILED`), and a chevron. When `open` is `true`, its detail elements—plain text, monospace output, a `CodeEditor`, or a `DiffView`—render in a borderless inset aligned to the title. Inside `Chat.agent`, consecutive `Chat.tool` and `Chat.toolGroup` parts stack with no gap between them while prose, code, `Chat.working()`, and the footer keep the regular spacing.

## Tool call groups

When a turn runs many tool calls, pass `Chat.Step` values built with `Chat.step(...)` to `Chat.toolGroup(...)` instead of stacking individual `Chat.tool` rows. Like `Chat.tool`, both the group and each step are controlled by the app (`open` and `onToggle`, or `null` to disable toggling).

While `open` is `false`, `latest` decides how many trailing steps stay visible along the vertical track line below the header: pass `0` once a turn finishes to fold the sequence into a single borderless summary row, or `1` (for example `working ? 1 : 0`) while the turn runs so the newest step stays in view behind a quiet `Show N earlier steps` row that runs the group's `onToggle`. When `open` is `true`, all steps show as flat rows and each step can expand its own details inset.

Passing `null` for `title` falls back to the step count from `Texts` (for example `4 steps`); passing `null` for `meta` falls back to the step count plus any failure count (`4 steps · 1 failed`), or only the failure count when `title` already fell back. The group header shows a spinner while any step is `RUNNING` and a check mark once finished; failed steps are surfaced in the metadata and on each step's own error icon rather than marking the whole group failed.

## Context blocks

Use `Chat.user(options, parts…)` with `Chat.text` and `Chat.context` to compose structured user messages—such as review comments with code excerpts, attached queries, tables, or file references—while passing the underlying raw prompt to `options.copy(clipboard, text)`. Composed user bubbles always span `Theme.Chat.bubbleWidth()` so opening or closing a context block does not shift the bubble horizontally.

`Chat.context` is controlled like `Chat.tool`: pass the block's `open` flag and an `onToggle` handler, or pass `null` for `onToggle` to render a static row without a chevron (which still shows its details when `open` is `true`). Its details can be any elements: a `Label.Variant.MONO` excerpt, or a read-only [`CodeEditor`](/docs/components/code-editor) for syntax highlighting, as for the query below. `Chat.text` and read-only editors join the transcript's selection; a label does not.

## Transcript

`Chat.transcript` renders a virtual list of messages of any height centered in a readable column up to `Theme.Prose.measure()` wide. Keep a [`ScrollState`](/api/com/rethinkj/ui/ScrollState.html) and a [`RowHeights`](/api/com/rethinkj/ui/RowHeights.html) in your app state and pass the same instances on every build. While the user is at the bottom, appended messages and a growing last message (such as a streaming [`MarkdownDocument`](/api/com/rethinkj/ui/kit/MarkdownDocument.html) updated with `next`) stay pinned to the end. Scrolling up holds the current place and shows a floating `Jump to newest` button over the bottom until the user presses it or scrolls back to the end. A drag or Shift+click selects across user messages and the Markdown of agent messages (`Markdown.fragment`), including ones scrolled out of view, and Control+C copies them in order. Wrap the transcript with [`Find.find`](/docs/components/find) to find a text in all messages; construct `RowHeights` with a row version (`new RowHeights(estimate, key, version)`) so find keeps each out-of-view message's text across builds while its version is unchanged.

Pass an optional `onLoadOlder` callback to fetch earlier messages when the top of the list comes near the view (it can be called more than once for one look at the top, so ignore the calls while a page loads, and pass `null` once no older messages remain), and construct `RowHeights` with a stable key per message (`new RowHeights(estimate, key)`) so inserting older messages at index `0` keeps what is in view at the same place.

## Composer

`Chat.composer` is the input card at the bottom of a chat: a borderless multi-line field that grows with its text up to six lines before scrolling, above a row of removable attachment chips and an action bar with start slots, end slots (such as a `Select` for the model), and a send button that switches to a stop button while the agent works.

<Shot src="examples/docs/chat-composer/view-{theme}" alt="A chat composer card with a two-line prompt, an attach button, two removable file chips, a model select, and a primary send button" />

```java snippet="chat-composer"
```

Plain `Enter` sends when the text is not blank and the agent is not working; `Shift+Enter` inserts a new line. While an input method is composing, `Enter` stays with the input method and does not send. Dropping files onto the card delivers their paths to `onFiles`.

Configure the composer with `Chat.composerOptions()`:

| Option | Description |
| --- | --- |
| `placeholder(text)` | Placeholder and accessible label of the field; defaults to `Texts.composerPlaceholder()` |
| `working(boolean, onStop)` | While `true`, turns the send button into a stop button that runs `onStop` and suppresses `Enter` |
| `attachments(names, onRemove)` | Removable file chips in a row above the action bar; `onRemove` receives the removed chip's index (or `null` for non-removable chips) |
| `start(El…)` | Elements placed at the start of the action bar, such as an attach button; `null` entries are skipped |
| `end(El…)` | Elements placed at the end of the action bar before the send/stop button, such as a `Select`; `null` entries are skipped |
| `onFiles(Consumer<List<Path>>)` | Receives file paths dropped onto the composer card via `El.onFileDrop` |

## Localization and theming

All built-in labels (`Transcript`, `Jump to newest`, `User message`, `Agent message`, `Copy message`, `Working…`, tool state names, step counts, failure counts, `Show N earlier steps`, `Write a message`, `Send`, `Stop`, and chip removal labels) come from `Texts.CURRENT`, with German translations in `GermanTexts`. User bubble fill and width fraction live in `Theme.chat()` (`Theme.Chat.DARK` and `Theme.Chat.LIGHT`).

User bubble text (`Chat.user` and `Chat.text`), the composer field, and agent Markdown all read their fonts from [`Theme.Prose`](/api/com/rethinkj/ui/kit/Theme.Prose.html), so wrapping a chat (such as `Chat.transcript` and `Chat.composer`) in `Theme.CURRENT.with(theme.withProse(...), ...)` swaps every prose and code font for that part of the view only:

## In a tree dump

`Chat.transcript` contains a `role=log` virtual list labeled `Transcript` and, while scrolled away from the end, a `role=button` labeled `Jump to newest`.
