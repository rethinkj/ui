title: Format and ValueField

`Format<T>` says how a value of a Java type is written as text and read back: `BigDecimal`, `LocalDate`, an enum, or a type of the app's own. `ValueField.valueField` is a text field for such a value: it hands the app values instead of strings, and keeps a text that is no value yet as a draft with the format's message. A [DataGrid](/docs/components/data-grid)'s typed columns take their alignment, icon and editor from the same formats. Use them wherever a field or column holds something other than text; for an `int` stepped by arrows and buttons, a [NumberField](/docs/components/number-field) stays the better fit.

## Formats

| Format | Type | Text |
| --- | --- | --- |
| `TEXT` | `String` | As it is; the empty text is the empty string |
| `INTEGER`, `LONG`, `BIG_INTEGER` | `Integer`, `Long`, `BigInteger` | `-12`, `+7`; refused beyond the type's range |
| `DECIMAL` | `BigDecimal` | `12.50`, `-.5`, `1e3`; written without an exponent, the scale kept, so an exponent that would write more than 4096 zeros (`1e5000`) is refused |
| `DATE` | `LocalDate` | `2026-11-13` |
| `TIME` | `LocalTime` | `14:30`, `14:30:15` |
| `DATE_TIME` | `LocalDateTime` | `2026-11-13 14:30`, also with a `T` |
| `OFFSET_DATE_TIME` | `OffsetDateTime` | `2026-11-13 14:30+01:00` |
| `BOOLEAN` | `Boolean` | `true`, `false`; also `t`, `1`, `yes`, `on` and their opposites |
| `choice(values, label)` | any, such as an enum | Each value by its label: `Format.choice(List.of(Status.values()), Status::label)`; labels are unique, and two values with one label are refused |
| `of(text, parse, message)` | any | The app's own: `Format.of(UUID::toString, UUID::fromString, "Expected a UUID")`; a parser that throws or returns null fails with the message |

Numbers have a full stop and no grouping, dates and times are ISO 8601's, whatever the system's locale; another notation is another format. Each format answers a text that is no value with a message that says what a valid one looks like (`Expected a date such as 2026-11-13`), and says with `allows(text)` whether typing may still lead there, so that a field refuses a letter in a number but keeps `12.` and `-`.

| Changed copy | |
| --- | --- |
| `.optional()` | The empty text is null; without it, the empty text is the message `A value is required` (`Format.REQUIRED`), except for `TEXT` |
| `.where(test, message)` | Only values that pass, as a range: `Format.INTEGER.where(p -> p >= 1 && p <= 65535, "1 to 65535")` |

`parse(text)` returns a `Format.Parsed<T>` with the value or the error, `text(value)` the text. Formats need no native libraries; keep them in constants.

| Method | |
| --- | --- |
| `text(value)` | The value as text, the empty text for null |
| `parse(text)` | A `Parsed<T>`: `value()` and `error()`, the error null for a valid text |
| `allows(text)` | Whether typing may still lead from this text to a valid one |
| `isOptional()` | Whether the empty text is null rather than an error, as after `.optional()` |
| `choices()` | The labels of a `choice` format, empty for the others |
| `type()` | The `DataGrid.DataType` a grid's column of these values takes its look and editor from; `OTHER` for a format of `of` |

Two limits keep a number from taking seconds to read on the app's thread: a text longer than `Format.MAX_NUMBER_LENGTH` (100 000) characters is refused unread by every number format, also by `allows`, and a `DECIMAL` whose exponent would write more than `Format.MAX_ZEROS` (4096) zeros is refused too.

`valueField(t, format, value, [placeholder,] draft, onChange)` is a [TextField](/docs/components/text-field) in every other way, so `.key`, `.w` and `.maxLength` chain onto it. How it behaves:

- **When the handler runs**: on every edit whose text is a valid value, as a text field's handler runs on every edit. The state always holds what the field shows, so a button that saves needs no Enter or leaving the field first.
- **A text that is no value yet**, such as `12e` or a half-typed date, stays in the `ValueField.Draft`, which the app keeps in its state as it keeps a `Menu.State`. The field shows it with the danger border, `invalid` and `error="…"` in the dump, and a [Form](/docs/components/form) field shows the message below it without the app passing an error; an error the app passes wins. The app's value stays the last valid one meanwhile, so a Save button checks `draft.error() == null`.
- **The empty text** is what the format says: `A value is required`, or null handed on for an `.optional()` format. Mark the form field `.required()` for the star.
- **A value from outside** replaces the draft: when the app's value is another than the one the field handed on last (a reset, a value loaded), the field shows its text. A handler that stores another value than it was given, or none, shows the same way. `draft.clear()` forgets the draft even where the value stays.
- **A value the format refuses**, such as null in a required field or 20 in a field of 1 to 10, is checked as a typed text is: `draft.error()` says so from the start, so Save stays off. The field shows it (danger border, `invalid`, the message) only once the user has edited it or the app calls `draft.showError()`, or `editing.showErrors()` for a whole [Editing](/docs/concepts/editing), as Save does when it is pressed too early; so a form over a new record does not open in red.
- A valid text stays as typed while it stands for the value: `007` stays `007` and the app has `7`.

## With a Prop

`valueField(t, format, prop[, placeholder])` takes a `Prop` of an [Editing](/docs/concepts/editing) in place of the value, the draft and the handler: the editing keeps the draft, so the state needs none. It writes the prop back, shows its field's error, and is disabled when the prop cannot be written.
