---
title: Form
description: Labelled fields, beside or above them, with help, errors, warnings and required marks, and buttons at the end.
---

`Form.form` lays out fields with their labels, either beside them in a column as wide as the widest label, or above them. Fields have help text, error messages, warnings and a mark when required. Longer forms group their fields under headings, with one label column for all groups, and put fields that belong together, such as host and port, in one row. `Form.buttons` puts buttons at the end of a form, a card or a page. Use it for dialogs and connection settings; for rows of settings, use a [Group](/docs/components/group).

| | |
| --- | --- |
| `Form.form(t, Labels.BESIDE \| ABOVE, fields...)` | The form |
| `Form.field(label, control)` | A field. The label names the control, or the first control inside it, when that is a text field or has no label yet (a select keeps its choice as its label) |
| `.help(text)` | Muted text below that wraps |
| `.error(text)` | Replaces the help in the danger colour and makes the control `invalid`; null for none. It wins over the message of a [ValueField](/docs/components/format) whose text is no value |
| `.warning(text)` | Replaces the help in the warning colour after a warning symbol and leaves the control valid, for a value worth a second thought; null for none. An error wins over it |
| `.required()` | A `*` after the label |
| `.grow()` | In a row, the field takes the room the others leave; its control's width is the least it has |
| `Form.row(fields...)` | Fields side by side, each with its own label, help, error and mark; a row of one field is that field |
| `Form.group(title, entries...)` | Fields and rows under a heading (`role=group`, the heading `level=4`); a group holds no groups |
| `.description(text)` | Muted text under the group's heading that wraps |
| `.divided()` | A line between the group and what comes before it; without it, space alone sets groups apart |
| `.level(n)` | The heading's level, 4 unless set (below a card's title, which is 3) |
| `Form.labelWidth(t, entries...)` | The width of the label column the entries need |
| `Form.form(t, labels, labelWidth, entries...)` | A form whose label column is at least that wide |
| `Form.buttons(t, buttons...)` | Buttons at the end, at the right |

`form` takes fields, rows and groups in any order (`Form.Entry` is their common type). It leaves out a null entry, a null field in a row or a group, and a row or group whose entries are all null, so `shown ? field(...) : null` shows a field under a condition.

With `Labels.BESIDE`, the label column is as wide as the widest label in any group, so the controls of all groups line up.

In a row, the first field's label stands in the label column, and each further label stands before its control. Each field is as wide as its control, unless it grows, and its help lies under its control. The errors of the row's fields lie under the whole row, so an error does not move the controls. Where the form is too narrow, the row wraps, and a field on the next line keeps its label before its control.

## Warnings

A warning stands where an error would, also under a row, but the field stays valid and the form can be saved. When a field has an error too, only the error shows.

<Shot src="kit/structure-form-warning-{theme}-2x" alt="A driver version with a warning in amber under it, a host with a warning under its row, and the port's error below it in red" />

## With a Prop

A control made with a [`Prop`](/docs/concepts/editing#components-that-take-a-prop) shows its field's error in the same way as `.error(text)`, whether it comes from a rule, the app or a text that is no value.
