`Select.select` is a button with the current choice and a chevron that opens a [Menu](/docs/components/menu) of the choices below it, the current one checked. Use it for a few choices that one reads, such as a driver, an encoding or an isolation level. For more than a screenful, or where the user knows what to type, use a [ComboBox](/docs/components/combo-box); for two or three choices always in view, [Radio](/docs/components/radio) or [Segmented](/docs/components/segmented).

`Select.select(t, choices, selected, menuState, onSelect)`: the choices as texts, the index of the current one, a `Menu.State` the app keeps, and a handler told the new index. A null handler disables it. It has the text field's frame and width.

## Values instead of indexes

`Select.select(t, values, selected, text, menuState, onSelect)` chooses among values of any type, an enum's constants or records, with a function that gives each its text:

The selected value is found by `equals`; null, or a value that is not in the list, selects nothing. The handler gets the value; a null handler disables it. For an enum, pass `List.of(E.values())`. The tree is the one the form with indexes builds of the same texts.

## Keyboard

| Keys | Action |
| --- | --- |
| Enter, Space, Alt+Down, Alt+Up | Open; in the menu, as a menu's keys |
| Down, Up (closed) | Choose the next and the previous choice |
| Home, End (closed) | The first and the last |
| A letter or digit (closed) | The next choice that starts with it |

## With a Prop

`select(t, values, prop, text, menuState)` takes a `Prop` in place of the value and its handler, such as a field of an [Editing](/docs/concepts/editing) of a record: it writes the prop back, shows its field's error, and is disabled when the prop cannot be written.
