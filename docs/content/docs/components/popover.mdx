---
title: Popover
description: Non-modal floating panel anchored to a button or element, dismissed by Escape or clicking outside.
---

`Popover.popover` displays floating content anchored to an element (such as a filter form or detail card) while `Popover.State` is open. Unlike [Dialog](/docs/components/dialog), it is non-modal and closes when the user presses **Escape** or clicks outside. Use `Popover.flush` when dividers or section backgrounds need to reach the panel's edges without inner padding, and `Popover.form` for a titled panel with action buttons.

For hover-only hints, use [Tooltip](/docs/components/tooltip).

Javadoc: [`Popover`](/api/com/rethinkj/ui/kit/Popover.html), [`Popover.State`](/api/com/rethinkj/ui/kit/Popover.State.html).

Store a `Popover.State` in your app state (`isOpen()`, `open()`, `close()`, `toggle()`).

| Method | Description |
| --- | --- |
| `Popover.popover(anchor, popoverState, label, content)` | Floating panel below `anchor` |
| `Popover.popover(anchor, popoverState, side, align, label, content)` | Custom side and alignment (`START`, `CENTER`, `END`, `STRETCH`) |
| `Popover.flush(anchor, popoverState, side, align, label, content)` | Same as `popover`, without inner padding: the content fills the panel up to its border |
| `Popover.form(anchor, popoverState, title, content, buttons)` | Panel with heading, scrollable body (if tall), and bottom-right buttons |
| `Popover.panel(popoverState, label, content)` | Standalone overlay element to attach manually |

## Placement

The side and alignment are preferences. If the popover does not fit in the window below its anchor, it opens above the anchor instead. If it does not fit at `START` or `END`, it flips to the opposite end of the anchor. For example, a popover on a button at the right edge opens to the left.

Inside a dialog, the popover also stays inside the dialog along the anchor. With `START` or `END`, it picks the end that fits inside the dialog. If the popover still does not fit, it shifts into the dialog as far as the window allows, centering over the dialog when it is wider than the dialog.

## Keyboard

Opening moves focus to the first focusable element inside the popover; **Escape** closes it and restores previous focus. In the **Tab** order, the popover comes right after its anchor. Pressing **Tab** or **Shift+Tab** out of the popover closes it and leaves focus on the element it moved to.

A [Menu](/docs/components/menu) on an element inside the popover, such as a row's context menu, opens over it: a press in the menu or its submenus keeps the popover open, **Escape** closes the innermost first, and an item's handler that closes the popover's state closes both, the focus going back to where it was before the popover opened.
