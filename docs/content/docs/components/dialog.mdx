`Dialog.dialog` displays a centered modal overlay over a dimmed backdrop (scrim). When it opens, focus moves to the first field Tab can reach. If there is no such field (such as in a dialog of read-only `Properties`), focus moves to `defaultButton`, or to the first button. It traps keyboard focus inside while open and restores previous focus when closed. Use it for confirmations and short forms.

For lightweight non-blocking overlays, use [Popover](/docs/components/popover). For brief status messages, use [Toast](/docs/components/toast).

Javadoc: [`Dialog`](/api/com/rethinkj/ui/kit/Dialog.html), [`Dialog.Options`](/api/com/rethinkj/ui/kit/Dialog.Options.html).

Control visibility from your state by attaching `root.overlay(open ? dialog : null)`.

| Parameter | Description |
| --- | --- |
| `title` | Dialog heading and accessibility label |
| `content` | Body element (set its width, e.g. `.w(320)`, to size the dialog) |
| `buttons` | Bottom-right action buttons (omitted if empty and no `start(...)` items exist) |
| `defaultButton` | Button triggered when pressing **Enter** in a single-line or read-only field (while enabled) |
| `onDismiss` | Handler called on **Escape** or clicking the backdrop |

For a standalone dialog window, register `root.onKey(Dialog.enterPresses(button))` on the container holding the form, passing the button element from the same view build.

Custom frameless title bars remain usable behind a dialog so users can still move or close the window.

## A dialog over a dialog

Keyboard input goes only to the top dialog. While it is open, `onKey` handlers on the dialog below do not run:

- **Escape** goes to the focused element first. For example, if a combo box list is open, Escape closes that list. If nothing in the top dialog handles Escape, only the top dialog's `onDismiss` runs and the dialog below stays open.
- **Enter** stays in the top dialog. Either the focused control handles it (for example, a combo box opening its list), or it triggers the top dialog's default button. It never triggers the lower dialog's default button, even when the top dialog's default button is disabled.
- **Focus:** When the top dialog closes, focus returns to the element that had focus before it opened. If the button that opened it had focus (for example, after Tab and Enter), focus returns to that button. Clicking a button leaves focus where it was (for example, in a field). Focus finds that element by its position among its siblings. If the build that closes the top dialog adds or removes siblings before it (as the line of properties in the example does), give the element a key (see [keys for identity](/docs/concepts/app#rules-for-your-view-function)).

| Option | Description |
| --- | --- |
| `leading(El)` | Element placed before the title |
| `trailing(El...)` | Elements at the right end of the header (long titles truncate with a tooltip) |
| `start(El...)` | Left-aligned elements in the button row |
| `defaultButton(El)` | Sets the default Enter-key button |

## Tall content

If the dialog content is taller than the window, the body scrolls automatically while the header and button row stay pinned:

## Keyboard

| Key | Action |
| --- | --- |
| Tab, Shift+Tab | Cycle focus inside the dialog |
| Enter | Click `defaultButton` (from single-line and read-only fields) |
| Escape | Call `onDismiss` |
| Page Up, Page Down | Scroll overflowing dialog content |
