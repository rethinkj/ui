`Dialog.dialog` is a modal overlay in the middle of the window: a title, the content and buttons at the bottom right, over a scrim that dims the rest. It takes the focus as it opens, keeps it inside, and gives it back when it closes. Use it to ask before something that cannot be undone, or for a short form. For something light that need not block the window, use a [Popover](/docs/components/popover); for a message that goes by itself, a [Toast](/docs/components/toast).

`s.renaming` is a boolean and `s.name` and `s.newName` are strings, all in the app's state. Whether the dialog is open is the app's state: the root attaches it with `root.overlay(open ? dialog : null)`.

| Parameter | |
| --- | --- |
| `title` | The heading, and the dialog's label |
| `content` | Any element |
| `buttons` | Shown at the bottom right, in order |
| `defaultButton` | One of `buttons`, which Enter presses while it is enabled (in the form with this parameter) |
| `onDismiss` | Called on Escape and on a press on the scrim: cancel |

Enter without modifiers presses the default button from a field of the dialog. A focused button, checkbox or select presses itself, and a multi-line field keeps Enter for its line breaks. `Dialog.enterPresses(button)` is that key handler alone, for a window that is a dialog itself.

The dialog's key is `dialog`. A second dialog open at the same time, such as a question over a dialog, needs a key of its own: chain `.key("discard")` onto it. It then lies over the first with a scrim of its own. Without its own key, building the view throws, as for any two siblings with one key.

A frameless window's own title bar stays usable under a dialog. Closing the window closes the dialog without calling `onDismiss`.

## Options

`Dialog.dialog(theme, title, content, buttons, onDismiss, Dialog.options()…)` adds a mark of what the dialog edits before the title, a badge or a close button at the end of the head, and a secondary action or a status at the start of the button row.

| Option | |
| --- | --- |
| `leading(El)` | Before the title, centred on its line |
| `trailing(El...)` | At the end of the head. The title gives way and ends in an ellipsis, with the whole title in a tooltip |
| `start(El...)` | At the start of the button row, with the buttons at its end |
| `defaultButton(El)` | One of `buttons`, which Enter presses, as the parameter of the other form |

A dialog is as wide as its content, title and button row ask for, up to the window's width less a margin. Size it by sizing the content, such as `field.w(320)`. It opens with the focus in the first field of its content; a close button in the head is the last Tab stop.

## Higher than the window

Where the content does not fit in the window, it scrolls between the head and the buttons, which stay in view; content wider than the window scrolls sideways. The wheel scrolls the content, and Tab scrolls a focused field into view.

## Keyboard

| Keys | Action |
| --- | --- |
| Tab, Shift+Tab | Go around inside the dialog |
| Enter | Press the default button |
| Escape | `onDismiss` |
| Page Up, Page Down | Scroll content higher than the window, while the focus is on something that does not take these keys, such as a button |
