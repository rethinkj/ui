title: CodeEditor
description: A multi-line editor for code with line numbers, highlighting, brackets, a find bar and line commands.

`CodeEditor.codeEditor` is a multi-line field for code: line numbers in a gutter, the caret's line and matching brackets highlighted, other occurrences of the word at the caret marked, colours from a highlighter such as `Sql`, a [find bar](/docs/components/find) and commands that duplicate, move, delete and comment lines. It handles texts of 100 000 lines. For prose or a short note, use a [text area](/docs/components/text-field#text-areas); for completions, add [Completion](/docs/components/completion).

## Example

```java snippet="code-editor"
```

- `s.sql` is the text, which every edit hands to `onChange`.
- `s.editor` is a `CodeEditor.State` the app keeps, one per editor (per tab). It holds the caret, selection, scroll and undo history, so an editor that leaves the tree comes back as it was, also in another window.
- `Sql.of(t)` colours SQL: keywords, strings, dollar quotes, numbers, comments and operators; identifiers in quotes keep the text's colour, and no keyword is coloured inside them. `Sql.of(t, Sql.Dialect.MYSQL)` does it as MySQL and MariaDB write SQL: identifiers in backticks, `#` comments, `--` as a comment only before a space, a tab or the line's end (`5--2` is 5 minus -2), and the backslash as the escape in strings; `/*! … */`, which MySQL runs, is coloured as a comment. The highlighter is also the key the field keeps its colours by, so pass the same or an equal object each time (`Sql.of` returns a record).
- Passing `app` gives the editor its find bar and its commands, which edit through the app as single steps of the undo history. Without it (`codeEditor(t, value, state, highlighter, onChange)`) the editor has neither.
- `.lines(n)` makes it `n` lines high; give it a width or let it grow.

## The state

| `CodeEditor.State` | |
| --- | --- |
| `caret()`, `anchor()` | Where the caret and the other end of the selection are, for a status line ("Ln 3, Col 9") or completions |
| `error(from, to)`, `noError()` | Underline a range in the danger colour, such as the name a query got wrong |
| `occurrences(boolean)` | Mark the other occurrences of the word at the caret; on by default |
| `findBar(boolean)`, `find()` | The find bar, on by default, and its `Find.State` |

## Commands

| Keys | `CodeEditor.Command` | |
| --- | --- | --- |
| Control+D | `SELECT_NEXT` | Select the word at the caret, then its next occurrence |
| Control+Shift+D | `DUPLICATE_LINES` | Duplicate the caret's line or the selected lines |
| Alt+Up, Alt+Down | `MOVE_LINES_UP`, `MOVE_LINES_DOWN` | Move them |
| Control+Shift+K | `DELETE_LINES` | Delete them |
| Control+/ | `TOGGLE_COMMENT` | Comment them out or in, with the highlighter's `LineComments` (`--` for SQL) |

`CodeEditor.run(app, state, command)` runs one from a menu. The editor's keys are its field's `onKey` handler; to add your own, keep them: `editor.onKey(mine.or(editor.onKey()))`, as the Workbench does for Control+Enter.

Besides these, it has every key of a multi-line text field: Tab indents (Control+M switches Tab between indenting and moving the focus), a second Home goes to the first character of the line that is not a space, Control+Z and Control+Y undo and redo. See [Text fields and editors](/docs/concepts/text-fields).

## A highlighter of your own

`Sql` is one `Highlighter`; any other language is a class of your own. A highlighter is asked about one line at a time, gets the state the line before ended in and returns the state its own line ends in, so that a string or a comment can go on across lines:

```java snippet="highlighter"
```

- `Object line(String line, Object state, Spans out)` gets the line's string without its line feed, the state the line before returned (null for the first line) and a `Spans` to describe it in. It returns the state at the end of the line, such as "inside a block comment", or null when nothing goes on. States are compared with `equals`, so use values: an enum, a record, `Boolean.TRUE`.
- A multi-line field asks only about the lines it shapes, those in view and a few around them, and keeps each line's answer with the state it was given. An edit forgets the lines it touched; a line whose state comes out as before keeps the spans of the lines after it. To show a line it needs the state that line starts in, so it first asks about the lines before it that it has not seen since they changed, with a `Spans` that keeps nothing. A highlighter must therefore depend only on its line and its state, never on what it was asked before.
- The highlighter is also the key the field keeps its spans by: pass an equal object on every build, which a record does. Another key asks about every line again.
- Implementing `CodeEditor.LineComments`, whose `lineComment()` returns what starts a comment to the end of the line (`--`, `//`, `;`), gives the editor's Control+/ that comment.

A highlighter is tested without native libraries: `new Spans(length)` takes what it is told, and its `toString()` lists it, one range per line, as `color 0-4 FF7C3AED`.

### Spans

Positions are indexes into the line's string; a range runs from `from` to `to`, exclusive, is clamped to the line and left out when empty, and where ranges of one kind overlap the later one wins. Colours are 0xAARRGGBB.

| `Spans` method | |
| --- | --- |
| `color(from, to, argb)` | The text of the range in this colour; costs nothing beyond the glyphs |
| `font(from, to, font)` | The range in another font at the text's size, such as `Font.monoBold()`; it is shaped on its own, so carets, selection and wrapping follow its glyphs. Give the font the fallbacks of the text's font (`withFallback`) where the range may hold characters it lacks |
| `background(from, to, argb)` | A rectangle behind the range, a line high |
| `underline(from, to, argb)` | A straight line under the range, where an input method's underline lies |
| `strike(from, to, argb)` | A line through the middle of the lower-case letters, behind the glyphs |
| `lineBackground(argb)` | A background across the whole width behind the line, every row of it when it wraps |

Backgrounds, underlines, struck ranges and line backgrounds show in multi-line fields only.

## Marks of your own

A `Decorator` marks the lines in view with backgrounds and underlines, as the editor does for the caret's line, brackets and the find bar's matches. Unlike a highlighter it keeps nothing: it is asked anew for each line in view and a few around them whenever the field lays out its rows, so it may read anything in the app's state, such as the caret or the errors of the last run.


`void line(int line, int start, String text, Spans out)` gets the line's index from 0, where the line starts in the field's whole string (a position `p` of the string is `p - start` in the line), the line's text and the `Spans` to mark it in; colours and fonts belong to the highlighter and are not taken from a decorator. `El.decorate` replaces the field's decorator, so call the one the editor gave, `editor.decorator()`, from yours, or its own marks go.
