title: CodeEditor
description: Multi-line code editor with line numbers, code folding, code vision, syntax highlighting, gutter markers, diagnostics, find bar, and line commands.
---

`CodeEditor.codeEditor` is a multi-line code editor capable of handling 100,000+ lines. It includes line numbers, code folding, gutter markers, syntax highlighting (such as `Sql`, [`Json`](#json), and [`Java`](#java)), current-line and matching-bracket highlights, word-occurrence highlights, indentation guides, a built-in [Find](/docs/components/find) bar, and line editing shortcuts.

For plain notes or prose, use a [text area](/docs/components/text-field#text-areas). To add autocomplete, wrap it with [Completion](/docs/components/completion).

`CodeEditor` lives in its own module, `rethinkj-ui-editor`, in package `com.rethinkj.ui.editor`:

```xml
<dependency>
  <groupId>com.rethinkj.ui</groupId>
  <artifactId>rethinkj-ui-editor</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

Javadoc: [`CodeEditor`](/api/com/rethinkj/ui/editor/CodeEditor.html), [`CodeEditor.State`](/api/com/rethinkj/ui/editor/CodeEditor.State.html), [`Language`](/api/com/rethinkj/ui/editor/Language.html), [`Highlighter`](/api/com/rethinkj/ui/Highlighter.html), [`Spans`](/api/com/rethinkj/ui/Spans.html).

### Formatting JSON

The editor does not wrap lines, so format minified JSON (such as a database column value) before displaying it. `Json.format` puts each member and array element on its own line with four-space indentation. It keeps numbers, escape sequences, and member order as written. Multi-line text fields convert line separators (U+2028) and paragraph separators (U+2029) into line feeds, which breaks JSON strings that contain them directly. To avoid this, `Json.format` escapes them as `\u2028` and `\u2029`. If your app displays JSON without formatting it, replace those two characters in strings with these escapes yourself. `Json.format` returns a `Formatted` result with either the formatted text or, for invalid JSON, the first problem's position and kind. You can show that problem as a [diagnostic](#gutter-markers-and-diagnostics) with `Texts.formatProblem`. Because event handlers run outside the view, pass the texts you read in the view with `Texts.CURRENT.get()`:

```java snippet="code-editor-json-format"
```

You can then show `cell` with `codeEditor(state.app, state.cell, state.cellEditor, Json.of(), null)`. In an editable editor, **Ctrl+Alt+L** formats the text with `Json.format` as one undo step (Ctrl+Z) and keeps the cursor on the same token. If the JSON is invalid, the text stays unchanged, and the problem appears as an error diagnostic with its message above the cursor until the text changes. `Json.format` is safe for untrusted text. Deeply nested values do not use extra call stack, and input whose formatted text would exceed 64 Mi characters returns the `TOO_LARGE` kind.

Javadoc: [`Json`](/api/com/rethinkj/ui/json/Json.html), [`Formatted`](/api/com/rethinkj/ui/Formatted.html).

## Gutter, markers and diagnostics

The left gutter displays a marker column, line numbers, and fold chevrons. You can attach:
- **Marked blocks (`block(from, to)`):** Highlights a range of lines on the gutter rail (for example, the SQL statement that Ctrl+Enter will run).
- **Markers (`markers(list)`):** Clickable or static gutter icons with tooltips, at positions in the current string.
- **Markup layers (`markup(layer, text, list)`):** Named layers of `CodeEditor.Mark` items — `Diagnostic`, `Marker`, or `Highlight` (a background in `code().occurrence()`, such as usages of a symbol) — computed for `text`. Each provider uses its own layer name (such as `"analysis"`, `"references"`, or `"app"`), and all layers show together. Marks move across edits elsewhere in the text without growing at their ends; a mark whose own text is edited is dropped, and undoing back to `text` restores the originals. The editor finds the edits by comparing the old and new text, so a very large bulk edit, beyond its limits, can also drop marks between its changes. Clear a layer with `noMarkup(layer)`.
- **Diagnostics (`diagnostics(text, list)`):** Shorthand for `markup("diagnostics", text, list)` (and `noDiagnostics()` for `noMarkup("diagnostics")`). Draws a squiggly underline under errors (`ERROR`) or warnings (`WARNING`) and adds a gutter marker with the message tooltip. Diagnostics move with edits elsewhere, are dropped when their own characters are edited, and come back when undoing back to `text`.

When you pass the app, **F8** moves the cursor to the start of the next diagnostic and **Shift+F8** moves to the previous one, wrapping around at both ends. The diagnostic message appears above the cursor (styled like the marker's tooltip) while the editor has focus. It stays visible until the cursor leaves the diagnostic or you press **Escape**. **Escape** closes an open completion list or find bar first. If there are no diagnostics, these keys do nothing.

```java snippet="code-editor-marks"
```

All positions (for `select(caret, anchor)`, diagnostics, and gutter markers) are UTF-16 offsets in the editor's normalized displayed text, where CRLF (`\r\n`) is normalized to LF (`\n`). To jump the cursor to a diagnostic, call `select(caret, anchor)` on `CodeEditor.State`.

`line()` and `column()` on `CodeEditor.State` return the cursor's line and column numbers, starting at 1 (for example, for a [StatusBar](/docs/components/status-bar)). Columns count characters the same way positions do, so a tab counts as one character no matter how wide it looks. Both values reflect the text from the editor's last build, so read them after building the editor (such as in a status bar below it).

## Folding

Multi-line bracket pairs (`()`, `[]`, `{}`) can be collapsed in the editor, ignoring brackets inside strings and comments when the highlighter marks brackets (such as `Json` and `Sql`). Folded lines show a chevron (`›`) in the gutter and a clickable `…` pill at the end of the line; hovering a line that starts a foldable block reveals its fold chevron (`⌄`). Press **Ctrl+Shift+[** to fold the innermost block around the cursor (moving the cursor to the end of its first line) and **Ctrl+Shift+]** to unfold it. Folding also works in read-only editors.

<Shot src="examples/docs/code-editor-folding/folded-{theme}" alt="A JSON document in the code editor with the customer object folded to a single line showing a right chevron in the gutter and a clickable ellipsis pill" />

`CodeEditor.State` keeps the active folds across rebuilds, shifts folds below inserted or removed lines, and drops a fold if an edit removes its brackets. Read `folds()` and call `folds(list)` to save and restore folded ranges per document:

## Code vision

Call `codeVision(list)` on `CodeEditor.State` to place muted hint rows above declarations — such as usage counts or authorship — without turning them into editable text. Each `CodeEditor.Vision(line, symbol, label, onPress)` takes a 0-based line index, an optional leading `Icon`, a label, and an optional press handler (`null` for read-only entries). Entries for the same line share one inserted row in list order, aligned with that line's indentation in the code font. Clickable entries keep focus in the editor when pressed, and an enclosing fold hides entries inside it. The editor computes nothing itself; pass `List.of()` to clear them.

## Inserting text

To insert a snippet from a button or menu, call `replaceSelection(text)` on `CodeEditor.State` in its handler. It replaces the current selection (or inserts at the cursor) and puts the cursor after the inserted text. To place the cursor at `caret` inside `text` instead (such as between the parentheses of `()`), call `replaceSelection(text, caret)`. To edit a range you calculated (such as a line below the cursor), call `replace(from, to, text, caret)`. It replaces the exact characters from `from` to `to`, and Ctrl+Z restores the previous selection. The edit runs right after the handler, calls `onChange` like typed text, and counts as one undo step for Ctrl+Z. Nothing happens if the editor is no longer in the tree after the handler.

## Writing a custom highlighter

Implement `Highlighter` to support other languages. It processes one line at a time, receiving the state from the previous line and returning the state at the end of the current line (for multi-line strings or block comments):

```java snippet="highlighter"
```

- `Object line(String line, Object state, Spans out)` receives the line without `\n`, the previous line's end state (`null` for line 0), and a `Spans` builder. Return a value object (enum, record, `Boolean.TRUE`, or `null`) so state changes can be compared with `equals`.
- Keep highlighters pure (depending only on `line` and `state`) and implement `equals` (e.g., as a Java `record`).
- Override `lineComment()` (e.g., `"//"`, `"--"`) to enable **Ctrl+/** commenting.
- Override `formatter()` to enable **Ctrl+Alt+L** formatting. Return a function (such as `Json::format`) that takes the editor's text with line feeds only and returns a `Formatted`. If the text cannot be formatted, the function returns the first problem and its position in the text instead of throwing. When the formatter only changes whitespace (as `Json::format` does), the cursor stays on the same token. The default is `null`, which means the language has no formatter and the command does nothing.
- Override `wordCharacters()` to specify extra characters that count as part of a word besides letters, digits, and `_` (such as `"$"` for JavaScript). Word-based features then treat `$gt` as a single word: Ctrl+Arrow, double-click, word-occurrence highlights, Ctrl+D (both the first selection and next matches), the find bar's word at the cursor and whole-word search, and [Completion](/docs/components/completion).
- Override `marksBrackets()` to return `true` and call `out.bracket(at)` on code brackets so brackets inside strings or comments are ignored during bracket matching.

To also report the ranges of comments and doc comments and parse doc comments into `DocComment`, implement `Language` (as [`Java.of()`](#java) does), a `Highlighter` with these methods, and pass it to `codeEditor` in place of the highlighter. `Comments.scan` finds the ranges of at most 4,000 lines per call, so a text of many lines does not block a frame; the limit does not cover the work on one very long line. `Language.of(highlighter)` makes a language of a highlighter without comments, such as `Sql.of()` or `Json.of()`.

### Spans

`Spans` ranges use `[from, to)` character offsets within the line (later overlapping ranges win). Available methods: `color`, `font`, `background`, `underline`, `squiggle`, `strike`, `guide` (vertical indentation guide), and `lineBackground`. See [`Spans` Javadoc](/api/com/rethinkj/ui/Spans.html).

## State API

| `CodeEditor.State` method | Description |
| --- | --- |
| `caret()`, `anchor()` | Current cursor and selection anchor offsets |
| `select(caret, anchor)` | Sets cursor/selection and scrolls it into view on the next build |
| `replaceSelection(text)` | Replaces the selection with `text` right after the handler, as one undo step |
| `replaceSelection(text, caret)` | Same as above, placing the cursor at `caret` inside `text` (from 0 to its length) |
| `replace(from, to, text, caret)` | Replaces characters from `from` to `to` with `text` in the same way, placing the cursor at `caret` inside `text` |
| `markup(layer, text, list)`, `noMarkup(layer)` | Sets or clears a named layer of `CodeEditor.Mark` items (`Diagnostic`, `Marker`, `Highlight`) for `text`, moving them across edits |
| `diagnostics(text, list)`, `noDiagnostics()` | Shorthand for `markup("diagnostics", text, list)` and `noMarkup("diagnostics")` |
| `markers(list)` | Sets gutter `CodeEditor.Marker(at, symbol, tone, label, onPress)` items at positions in the current string |
| `codeVision(list)` | Sets `CodeEditor.Vision(line, symbol, label, onPress)` hint rows above lines |
| `block(from, to)`, `noBlock()` | Highlights a line range on the gutter rail |
| `folds()`, `folds(list)` | Reads or restores the editor's folded `El.Fold` line ranges |
| `occurrences(boolean)` | Toggles highlighting other occurrences of the word under the cursor (on by default) |
| `findBar(boolean)`, `find()` | Enables/disables the find bar (on by default) and returns its `Find.State` |
| `readOnly(boolean)` | Makes the editor read-only, so it needs no `onChange` (off by default) |

## Keyboard commands

| Shortcut | `CodeEditor.Command` | Action |
| --- | --- | --- |
| Ctrl+D | `SELECT_NEXT` | Select current word, then next occurrence |
| Ctrl+Shift+D | `DUPLICATE_LINES` | Duplicate current or selected lines |
| Alt+Up, Alt+Down | `MOVE_LINES_UP`, `MOVE_LINES_DOWN` | Move lines up or down |
| Ctrl+Shift+K | `DELETE_LINES` | Delete current or selected lines |
| Ctrl+/ (or Ctrl+Shift+7, Ctrl+#, Ctrl+Numpad/) | `TOGGLE_COMMENT` | Toggle line comments using `lineComment()` |
| Ctrl+Alt+L | `FORMAT` | Format all text using `formatter()`, or show why formatting failed |
| Ctrl+Shift+[ | `FOLD` | Fold the innermost bracket range around the cursor |
| Ctrl+Shift+] | `UNFOLD` | Unfold the folded range at or around the cursor |
| F8, Shift+F8 | — | Go to the next or previous diagnostic and show its message |

Trigger any command from a menu with `CodeEditor.run(app, editorState, command)`. Some Linux desktops (such as Xfce and Cinnamon) use Ctrl+Alt+L to lock the screen before the app receives it. Providing a menu item still lets users format on those desktops. To add custom shortcuts (like Ctrl+Enter) without overriding built-in shortcuts, use `editor.onKeyFirst(...)`.

Also supports all standard [multi-line text field shortcuts](/docs/concepts/text-fields): auto-indent on Enter, Tab indentation (**Ctrl+M** toggles Tab between indent and focus navigation), smart Home, and Ctrl+Z / Ctrl+Y undo/redo.
