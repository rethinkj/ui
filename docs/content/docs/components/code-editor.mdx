title: CodeEditor

`CodeEditor.codeEditor` is a multi-line field for code. It has line numbers in a gutter, highlights the caret's line and matching brackets, and marks other occurrences of the word at the caret. Colours come from a highlighter such as `Sql`. It has a [find bar](/docs/components/find) and commands that duplicate, move, delete and comment lines, and it handles texts of 100 000 lines. For prose or a short note, use a [text area](/docs/components/text-field#text-areas); for completions, add [Completion](/docs/components/completion).

Javadoc: [`CodeEditor`](/api/com/rethinkj/ui/kit/CodeEditor.html), [`CodeEditor.State`](/api/com/rethinkj/ui/kit/CodeEditor.State.html), [`Highlighter`](/api/com/rethinkj/ui/Highlighter.html), [`Spans`](/api/com/rethinkj/ui/Spans.html).


- `state.sql` is the text, which every edit hands to `onChange`.
- `state.editor` is a `CodeEditor.State` in the app's state, one per editor (per tab). It holds the caret, selection, scroll and undo history, so an editor that leaves the tree comes back as it was, also in another window.
- `Sql.of(theme)` colours SQL: keywords, strings, dollar quotes, numbers, comments and operators. `Sql.of(theme, Sql.Dialect.MYSQL)` colours SQL as MySQL and MariaDB write it: identifiers in backticks, `#` comments, `--` as a comment only before a space, and the backslash as the escape in strings. Pass the same or an equal highlighter on every build (`Sql.of` returns a record), or the editor colours every line again.
- `state.app` gives the editor its find bar and its commands, which edit through the app as single steps of the undo history. Without it (`codeEditor(theme, value, editorState, highlighter, onChange)`) the editor has neither.
- `.lines(n)` makes it `n` lines high; give it a width or let it grow.

## In a card

The editor has the frame of a text field, which makes a box in a box inside a card. `CodeEditor.embedded(theme, editor)` gives it the look of the card's body instead: as wide as the card, without corners or a frame of its own, and with a line along its top that takes the accent's colour while the editor has the focus. Put it into a [flush card](/docs/components/card), below the card's toolbar or header, or into a panel that frames it. Keep the framed editor where it stands among other fields.

## A highlighter of your own

`Sql` is one `Highlighter`; for any other language, write a class of your own. A highlighter is asked about one line at a time. It gets the state the line before ended in and returns the state its own line ends in, so that a string or a comment can go on across lines:

```java snippet="highlighter"
```

- `Object line(String line, Object state, Spans out)` gets the line's string without its line feed, the state the line before returned (null for the first line) and a `Spans` to describe it in. It returns the state at the end of the line, such as "inside a block comment", or null when nothing goes on. States are compared with `equals`, so use values: an enum, a record, `Boolean.TRUE`.
- The editor asks only about the lines it needs, and asks again about a line after an edit. So a highlighter must depend only on its line and its state, never on what it was asked before.
- Make it a record, so that it is equal on every build, as `Sql.of` is.
- Implement `CodeEditor.LineComments`, whose `lineComment()` returns what starts a comment to the end of the line (`--`, `//`, `;`), to give Control+/ that comment.

A highlighter can be tested without native libraries: `new Spans(length)` takes what it is told, and its `toString()` lists it, one range per line, as `color 0-4 FF7C3AED`.

### Spans

Positions are indexes into the line's string. A range runs from `from` to `to`, exclusive; it is clamped to the line and left out when empty. Where ranges of one kind overlap, the later one wins. Colours are 0xAARRGGBB.

`color(from, to, argb)` gives the text of a range a colour, and `font(from, to, font)` another font at the text's size, such as `Font.monoBold()`. Give the font the fallbacks of the text's font (`withFallback`) where the range may hold characters it lacks. `background`, `underline`, `strike` and `lineBackground` are on [`Spans`](/api/com/rethinkj/ui/Spans.html).

Backgrounds, underlines, struck ranges and line backgrounds show in multi-line fields only.

## Marks of your own

A `Decorator` marks the lines in view with backgrounds and underlines, as the editor does for the caret's line, brackets and the find bar's matches. Unlike a highlighter, it keeps nothing: it is asked again for each line in view whenever the field lays out its rows, so it may read anything in the app's state, such as the caret or the errors of the last run.


`void line(int line, int start, String text, Spans out)` gets the line's index from 0, where the line starts in the field's whole string (a `position` in the string is `position - start` in the line), the line's text and the `Spans` to mark it in. Colours and fonts from a decorator are ignored; they belong to the highlighter. `El.decorate` replaces the field's decorator, so call the editor's own, `editor.decorator()`, from yours, or its marks go.

## The state

Positions are indexes into the string as the editor shows it. A carriage return, with or without a line feed after it, and U+2028 and U+2029 are each one line feed there; the editor hands the app that string at the first edit.

| `CodeEditor.State` | |
| --- | --- |
| `caret()`, `anchor()` | Where the caret and the other end of the selection are, for a status line ("Ln 3, Col 9") or completions |
| `select(caret, anchor)` | Put the caret or a selection there and scroll it into view at the next build, also while the editor is away, as in a tab that is not shown |
| `error(from, to)`, `noError()`, `errorFrom()`, `errorTo()` | Underline a range in the danger colour, such as the name a query got wrong |
| `block(from, to)`, `noBlock()` | Mark the lines of a range with `code().block()` behind them, such as the statement Control+Enter would run |
| `occurrences(boolean)` | Mark the other occurrences of the word at the caret; on by default |
| `findBar(boolean)`, `find()` | The find bar, on by default, and its `Find.State` |

## Commands

| Keys | `CodeEditor.Command` | |
| --- | --- | --- |
| Control+D | `SELECT_NEXT` | Select the word at the caret, then its next occurrence |
| Control+Shift+D | `DUPLICATE_LINES` | Duplicate the caret's line or the selected lines |
| Alt+Up, Alt+Down | `MOVE_LINES_UP`, `MOVE_LINES_DOWN` | Move them |
| Control+Shift+K | `DELETE_LINES` | Delete them |
| Control+/ | `TOGGLE_COMMENT` | Comment them out or in, with the highlighter's `LineComments` (`--` for SQL) |

`CodeEditor.run(app, editorState, command)` runs one from a menu. The editor's keys are its field's `onKey` handler. To add your own, keep them: `editor.onKey(mine.or(editor.onKey()))`, as the Workbench does for Control+Enter.

The editor also has every key of a multi-line text field. Tab indents, and Control+M switches Tab between indenting and moving the focus. A second Home goes to the first character of the line that is not a space. Control+Z and Control+Y undo and redo. See [Text fields and editors](/docs/concepts/text-fields).
