`CodeEditor.codeEditor` is a multi-line code editor capable of handling 100,000+ lines. It includes line numbers, gutter markers, syntax highlighting (such as `Sql` and [`Json`](#json)), current-line and matching-bracket highlights, word-occurrence highlights, indentation guides, a built-in [Find](/docs/components/find) bar, and line editing shortcuts.

For plain notes or prose, use a [text area](/docs/components/text-field#text-areas). To add autocomplete, wrap it with [Completion](/docs/components/completion).

Javadoc: [`CodeEditor`](/api/com/rethinkj/ui/kit/CodeEditor.html), [`CodeEditor.State`](/api/com/rethinkj/ui/kit/CodeEditor.State.html), [`Highlighter`](/api/com/rethinkj/ui/Highlighter.html), [`Spans`](/api/com/rethinkj/ui/Spans.html).

- `Sql.of()` highlights standard SQL (see [SQL](#sql)). Call it in the view so it picks up the active theme's code colors, and ensure custom highlighters implement `equals` (e.g., as a record) so lines are not re-highlighted unnecessarily.

## JSON

`Json.of()` highlights JSON as RFC 8259 defines it: member names, strings, numbers, `true`, `false` and `null`, and brackets, where only the brackets outside strings are matched. A member name takes the `property` color of `Theme.Code` when its colon is on the same line. Invalid JSON is colored as far as it goes. JSON has no comments, so Ctrl+/ does nothing.

`Json` is in its own module, `rethinkj-ui-json`, in the package `com.rethinkj.ui.json`:

### Formatting JSON

The editor does not wrap lines, so a minified value, such as one from a database's column, is best formatted before it shows. `Json.format` puts each member and element on a line of its own, indented by four spaces, and keeps numbers, escapes and the order of members as they are written. A multi-line field turns a line separator (U+2028) or paragraph separator (U+2029) into a line feed, which breaks a JSON string that holds one as it is, so `Json.format` writes both as `\u2028` and `\u2029`. An app that shows JSON without formatting it replaces both characters in its strings with these escapes itself. `Json.format` returns a `Formatted`: the formatted text, or, for invalid JSON, the first problem with its place and kind, which the app can show as a [diagnostic](#gutter-markers-and-diagnostics) with the message of `Texts.formatProblem`. A handler runs outside the view, so it takes the texts the view read with `Texts.CURRENT.get()`:

```java snippet="code-editor-json-format"
```

The editor then shows `cell` with `codeEditor(state.app, state.cell, state.cellEditor, Json.of(), null)`. In an editor that can change its text, **Ctrl+Alt+L** formats it with `Json.format` as one step for Ctrl+Z, and keeps the cursor at the same token. Invalid JSON stays as it is: its problem shows as an error diagnostic with its message above the cursor, until the text changes. `Json.format` takes untrusted text: a value nested however deep needs no deeper stack, and one whose formatted text would be longer than 64 Mi characters gives the kind `TOO_LARGE`.

## Gutter, markers and diagnostics

The left gutter displays a marker column and line numbers. You can attach:
- **Marked blocks (`block(from, to)`):** Highlights a range of lines on the gutter rail (for example, the SQL statement that Ctrl+Enter will run).
- **Markers (`markers(list)`):** Clickable or static gutter icons with tooltips.
- **Diagnostics (`diagnostics(text, list)`):** Underlines errors (`ERROR`) or warnings (`WARNING`) and adds a gutter marker with the message tooltip. Diagnostics stay tied to the exact `text` they were computed for — editing clears them automatically, and undoing back restores them.

With the app passed, **F8** moves the cursor to the start of the next diagnostic and **Shift+F8** to the previous one, wrapping around at the ends. The message then shows above the cursor, in the look of the marker's tooltip, while the editor has the focus, until the cursor leaves the diagnostic or **Escape** hides it. Escape still closes an open completion list or find bar first. Without diagnostics, the keys do nothing.

```java snippet="code-editor-marks"
```

All positions (for `select(caret, anchor)`, diagnostics, and gutter markers) are UTF-16 offsets in the editor's normalized displayed text, where CRLF (`\r\n`) is normalized to LF (`\n`). To jump the cursor to a diagnostic, call `select(caret, anchor)` on `CodeEditor.State`.

`line()` and `column()` on `CodeEditor.State` give the cursor's line and column, both counted from 1, such as for a [StatusBar](/docs/components/status-bar). The column counts characters as the positions do, so a tab is one character however wide it shows. They are about the text of the editor's last build, so read them after building the editor, as for a status bar below it.

## Inserting text

To insert a snippet from a button or menu, call `replaceSelection(text)` on `CodeEditor.State` in its handler. It replaces the selection, or inserts at the cursor, and puts the cursor after the text, or, with `replaceSelection(text, caret)`, at `caret` in the text, such as between the parentheses of `()`. To insert at a place you computed, such as a line below the one with the cursor, call `replace(from, to, text, caret)`: it replaces exactly the characters `from` to `to`, and Ctrl+Z brings back the selection from before. The edit runs right after the handler, goes to `onChange` like typed text, and is one step for Ctrl+Z. Nothing happens if the editor is no longer in the tree after the handler.

## Writing a custom highlighter

Implement `Highlighter` to support other languages. It processes one line at a time, receiving the state from the previous line and returning the state at the end of the current line (for multi-line strings or block comments):

```java snippet="highlighter"
```

- `Object line(String line, Object state, Spans out)` receives the line without `\n`, the previous line's end state (`null` for line 0), and a `Spans` builder. Return a value object (enum, record, `Boolean.TRUE`, or `null`) so state changes can be compared with `equals`.
- Keep highlighters pure (depending only on `line` and `state`) and implement `equals` (e.g., as a Java `record`).
- Override `lineComment()` (e.g., `"//"`, `"--"`) to enable **Ctrl+/** commenting.
- Override `formatter()` to enable **Ctrl+Alt+L** formatting: return a function from the editor's text, with line feeds only, to a `Formatted`, such as `Json::format`. For a text it cannot format, it returns the first problem, at its place in that text, instead of throwing. The cursor stays at the same token when the formatter changes only white space, as `Json::format` does. `null`, the default, means the language has no formatter, and the command does nothing.
- Override `wordCharacters()` to name the characters that belong to a word of the language besides letters, digits and `_`, such as `"$"` for JavaScript. Ctrl+Arrow, double-click, highlighted occurrences, the word the first Ctrl+D selects, the find bar's word at the cursor and [Completion](/docs/components/completion) then take `$gt` as one word.
- Override `marksBrackets()` to return `true` and call `out.bracket(at)` on code brackets so brackets inside strings or comments are ignored during bracket matching.

### Spans

`Spans` ranges use `[from, to)` character offsets within the line (later overlapping ranges win). Available methods: `color`, `font`, `background`, `underline`, `strike`, `guide` (vertical indentation guide), and `lineBackground`. See [`Spans` Javadoc](/api/com/rethinkj/ui/Spans.html).

## State API

| `CodeEditor.State` method | Description |
| --- | --- |
| `caret()`, `anchor()` | Current cursor and selection anchor offsets |
| `select(caret, anchor)` | Sets cursor/selection and scrolls it into view on the next build |
| `replaceSelection(text)` | Replaces the selection with `text` right after the handler, as one undo step |
| `replaceSelection(text, caret)` | The same, with the cursor at `caret` in `text`, from 0 to its length |
| `replace(from, to, text, caret)` | Replaces the characters `from` to `to` with `text` in the same way, with the cursor at `caret` in `text` |
| `diagnostics(text, list)`, `noDiagnostics()` | Sets or clears `CodeEditor.Diagnostic(from, to, severity, message)` items for `text` |
| `markers(list)` | Sets gutter `CodeEditor.Marker(at, symbol, tone, label, onPress)` items |
| `block(from, to)`, `noBlock()` | Highlights a line range on the gutter rail |
| `occurrences(boolean)` | Toggles highlighting other occurrences of the word under the cursor (on by default) |
| `findBar(boolean)`, `find()` | Enables/disables the find bar (on by default) and returns its `Find.State` |
| `readOnly(boolean)` | Makes the editor read-only, so it needs no `onChange` (off by default) |

## Keyboard commands

| Shortcut | `CodeEditor.Command` | Action |
| --- | --- | --- |
| Ctrl+D | `SELECT_NEXT` | Select current word, then next occurrence |
| Ctrl+Shift+D | `DUPLICATE_LINES` | Duplicate current or selected lines |
| Alt+Up, Alt+Down | `MOVE_LINES_UP`, `MOVE_LINES_DOWN` | Move lines up or down |
| Ctrl+Shift+K | `DELETE_LINES` | Delete current or selected lines |
| Ctrl+/ (or Ctrl+Shift+7, Ctrl+#, Ctrl+Numpad/) | `TOGGLE_COMMENT` | Toggle line comments using `lineComment()` |
| Ctrl+Alt+L | `FORMAT` | Format the whole text using `formatter()`, or show why it cannot |
| F8, Shift+F8 | — | Go to the next or previous diagnostic and show its message |

Trigger any command from a menu with `CodeEditor.run(app, editorState, command)`. Some Linux desktops, such as Xfce and Cinnamon, lock the screen on Ctrl+Alt+L before the app sees it; a menu item still formats there. To add custom shortcuts (like Ctrl+Enter) without overriding built-in shortcuts, use `editor.onKeyFirst(...)`.

Also supports all standard [multi-line text field shortcuts](/docs/concepts/text-fields): auto-indent on Enter, Tab indentation (**Ctrl+M** toggles Tab between indent and focus navigation), smart Home, and Ctrl+Z / Ctrl+Y undo/redo.
