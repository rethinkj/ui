`Markdown.markdown` renders a parsed `MarkdownDocument` as a virtualized scrollable page supporting CommonMark plus GitHub tables, task lists, strikethrough, and autolinks. Only visible blocks are built, so long documents scroll smoothly.

Javadoc: [`Markdown`](/api/com/rethinkj/ui/kit/Markdown.html), [`Markdown.Options`](/api/com/rethinkj/ui/kit/Markdown.Options.html), [`Markdown.Section`](/api/com/rethinkj/ui/kit/Markdown.Section.html), [`Markdown.Definition`](/api/com/rethinkj/ui/kit/Markdown.Definition.html), [`MarkdownDocument`](/api/com/rethinkj/ui/kit/MarkdownDocument.html).

| Option | Description |
| --- | --- |
| `onLink(destination -> …)` | Called when a link is clicked (external URL or `#id` heading anchor). Open a URL with [`app.openUri`](/docs/concepts/platform#open-a-web-address) |
| `images(address -> image)` | Returns an `Image` for a path/URL, or `null` while loading (shows a placeholder) |
| `languages(language -> highlighter)` | Returns a highlighter for a fenced code block's language (the first word after the opening fence), or `null` for no highlighting |
| `copy(clipboard)` | Enables code-block copy buttons (and full-document Ctrl+A / Ctrl+C copy when `.state(Markdown.State)` is also set) |
| `copied(Button.Copied)` | Enables brief check-mark and tooltip confirmation on code-block copy buttons without a `Markdown.State` (overrides the state's own when both are set) |
| `state(Markdown.State)` | Preserves full-document selection and default copy-button confirmation state |
| `scroll(ScrollState)` | Keeps the document's scroll offsets for `markdown` (ignored by `fragment` and `definitions`), so switching documents preserves positions, `app.scrollToRow` jumps to headings, and `Markdown.current` tracks the heading in view |
| `textColor(color)` | Overrides the prose text color (`0xAARRGGBB`, such as `theme.code().comment()`) for `markdown`, `fragment`, and `definitions` descriptions |

Pass a `ScrollState` to `scroll(...)`, then jump to a heading with `app.scrollToRow(scroll, Markdown.rowOf(document, id))` and mark the heading in view in an outline of `document.headings()`, such as a [`NavList.outline`](/docs/components/nav-list), with `Markdown.current(document, headings, scroll)`. Use `Markdown.text(document)` to extract plain text. A link with a title shows its title as a tooltip. Raw HTML in Markdown is rendered safely as plain text. Table columns take their natural width when the table fits, wrap proportionally to fit narrower containers, and scroll horizontally only when their longest words cannot fit.

With `images(...)`, images—including images inside links, emphasis, strong, or strikethrough—render as images; a linked image is a focusable `role=link` labeled by its alt text that passes its destination to `onLink`. Consecutive images in a paragraph separated only by spaces or line breaks sit in one wrapping row, while images among text break the paragraph above and below. Headings and table cells holding only images (and links or emphasis around them) show those images; headings and table cells that mix text and images keep the alt text, since a block of text is one field whose lines cannot make room for an image. Without `images(...)`, only an image alone in its paragraph renders as a framed placeholder, and all other images stay their alt text.

Drag or Shift+click to select text across blocks (paragraphs, lists, quotes, tables, and code blocks)—including blocks scrolled out of view—and press Ctrl+C to copy the selected text with line breaks between blocks. Dragging near or past the top or bottom edge scrolls the document while extending the selection.

Wrap the element `Markdown.markdown` returns with [`Find.find(app, rendered, state.find)`](/docs/components/find) to search across all its blocks in order: **Ctrl+F** opens the find bar from any block, highlights every match in view, displays the match count, and **Enter** / **Shift+Enter** (or **F3** / **Shift+F3**) step between matches, scrolling rows out of view into sight and selecting the current match so **Ctrl+C** copies it.

## Fragments and definition lists

When Markdown belongs inside another element—such as a rendered doc comment, a quick-documentation popover, or completion details—use `Markdown.fragment(document, options)`. It renders the same blocks in a plain, non-scrolling column with compact spacing that takes its container's width, supporting links, images, syntax-highlighted code blocks, copy buttons, and selection across blocks. To let a selection span several fragments (such as chat messages in a list), mark their enclosing container with `.selectionScope()`.

A long fragment in a row of a virtual list with `RowHeights`, such as an answer in a chat transcript, should use `Markdown.options().virtual()`. The fragment is then a virtual list of its blocks, as high as they are, and it builds and lays out only the blocks in view. A rebuild, like a key typed next to a long answer or a streamed piece of it, costs what is on screen rather than the whole document. The transcript's row grows with the blocks as they are measured. A selection scope around the transcript reaches the blocks out of view for selecting, finding and copying. Like any virtual list, a virtual fragment takes its width from its container. The scrollbar is based on estimated heights for blocks not shown yet. For a long document of its own, use `Markdown.markdown`.

Pair it with `Markdown.definitions(sections, options)` for labeled documentation sections. Pass `Markdown.Section(label, definitions)` with localized labels from `Texts` (`parameters()`, `returns()`, `thrown()`, `seeAlso()`) and `Markdown.Definition(term, description)` entries (omit `term` with `null` for entries without a name, such as a return value). Section labels align in a muted left column, terms render as small monospace chips, and descriptions render as compact muted Markdown fragments beside them, or below a term that leaves them too little room.

## Streaming

When a document grows at its end while streaming, keep the `MarkdownDocument` in your state and replace it with `document.next(text)` for each piece. Blocks that did not change keep their identity, so `Markdown.markdown` and `Markdown.fragment` reuse what they already built, highlighted, and measured for them, while unfinished constructs at the end (such as an unclosed code fence, table, or list) render as CommonMark reads them so far.

## Fonts

Every font `Markdown` draws—body, headings, emphasis, strong, strong emphasis, strong text in headings, table headers, inline code, code blocks, and definition terms—comes from [`Theme.Prose`](/api/com/rethinkj/ui/kit/Theme.Prose.html). To replace them for part of a view only, derive a theme from the app's theme with `withProse`, keep it in the state until the app's theme changes, and scope it with `Theme.CURRENT.with`. ## State API

Store one `Markdown.State` per document to track **Ctrl+A** full-document selection (`allSelected()`, `selectAll(boolean)`); a pointer press or **Escape** clears it.
