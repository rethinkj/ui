title: Tree

`Tree.tree` displays expandable hierarchical data (such as servers, databases, schemas, tables, and columns). It builds only visible rows, so 100,000 expanded nodes scroll smoothly. Your app implements `Tree.Model` and stores which nodes are expanded and selected.

For flat navigation lists, use [NavList](/docs/components/nav-list). For multi-column tables, use [DataGrid](/docs/components/data-grid).

Javadoc: [`Tree`](/api/com/rethinkj/ui/kit/Tree.html), [`Tree.Model`](/api/com/rethinkj/ui/kit/Tree.Model.html), [`Tree.Options`](/api/com/rethinkj/ui/kit/Tree.Options.html).

Pass `new Tree.Options<Node>()` to `Tree.tree(model, options)`:

| Option | Description |
| --- | --- |
| `open(isOpen, onToggle)` | Returns whether a node is expanded and handles expand/collapse clicks (start async child loading here) |
| `select(selected, onSelect)` | Tracks selection (`onSelect` fires only when selection changes; required for keyboard focus) |
| `onActivate(handler)` | Runs on **Enter** or double-click (for example, opening a table) |
| `toggleOnDoublePress(predicate)` | Controls whether double-click also expands/collapses a node (all nodes by default) |
| `drag(dragging, canDrag, canDrop, onDrop)` | Lets users drag and drop nodes before, after, or into other nodes (see [Drag and drop](#drag-and-drop)) |

Right-clicking selects the row before opening a `Menu.contextMenu(tree, menuState, items)`. Inside a card, wrap the tree in `Card.inset(tree)`. Expand/collapse chevrons require `rethinkj-ui-icons`.

## `Tree.Model`

| Method | Description |
| --- | --- |
| `roots()` | Top-level nodes |
| `children(node)` | Returns `Tree.ready(list)`, `Tree.loading([text])`, or `Tree.failed(message[, action, onAction])` |
| `isLeaf(node)` | Returns `true` for leaf nodes (hides expand chevron) |
| `label(node)` | Row label text |
| `icon(node)` | Optional leading element/icon (`null` by default) |
| `detail(node)` | Optional muted trailing text such as type or row count (`null` by default) |
| `muted(node)` | Renders label in muted color, e.g., for system schemas (`false` by default) |
| `key(node)` | Optional stable unique row key (no spaces/quotes, not digits-only) |

Each nesting level indents a row further, up to half the row width. Deeper rows stay at that maximum indent so their chevrons and labels remain visible at any depth. In a tree dump, `level` still reports the real depth.

## Drag and drop

`drag(dragging, canDrag, canDrop, onDrop)` lets users move nodes by dragging. Store one `Tree.Dragging` per tree in your app state. `canDrag` decides which nodes can be dragged, `canDrop` decides whether a `Tree.Move` is allowed, and `onDrop` receives the move on drop. The tree does not modify your data. Your app moves the node in its model.

```java snippet="tree-drag"
```

A `Tree.Move` contains the dragged `node`, the `target` node, and a `place`: `BEFORE` or `AFTER` the target among its siblings, or `INTO` the target. Because the model has no parent links, `target` tells you where the node goes. The tree never offers a move into the dragged node itself or any of its descendants, and it never calls `canDrop` for one.

- Hovering over the middle half of a row that can accept the node means `INTO`. The tree outlines that row.
- Above that zone means `BEFORE` the row's node. Below it means `AFTER` the node, or `BEFORE` the first child if the node is open. A line marks the drop position.
- In the lower part of the last row inside an open node, the pointer's horizontal position picks the target level. Over the row, it drops after that row's node. One indent to the left, it drops after the parent node. This lets you choose between "after the last child" and "after the open node itself". For rows deeper than the maximum indent, the line stays at that deepest indent, and a drop there goes after the row above the line.
- Below all rows means `AFTER` the last root.
- If `canDrop` rejects `INTO`, the upper and lower half of the row's middle follow the rules for above and below it instead. Wherever `canDrop` rejects the move, no drop indicator appears and releasing the pointer does nothing.

<Shot src="kit/tree-{theme}-drop-line" alt="A schema tree while the table changes is dragged: its label muted, and a line in the accent's color below notification_preferences, at the level of the tables" />

<Shot src="kit/tree-{theme}-drop-into" alt="The same drag over the schema public, whose row is outlined in the accent's color" />

Holding the pointer near the top or bottom edge scrolls the tree. If a closed node can accept the dragged node, resting the pointer on it for the theme's `submenuDelay` expands it. **Escape** cancels the drag. Clicking or double-clicking without dragging still selects, expands, and activates rows as before. Select the moved node in `onDrop` so the tree follows it to its new position.

In a script, drag with `down`, `move`, and `up`. Aiming at a row's center means `INTO` when the node can drop there. Otherwise, it targets the position below the row. For other drop positions, aim near a row's top or bottom edge with `at` (see [A point near an edge](/docs/testing/selectors#a-point-near-an-edge)):

```text
down role=treeitem label="orders"
move role=treeitem label="audit" at top+2
up role=treeitem label="audit" at top+2   # before audit
frame
```

Use `at bottom-2` to aim below a row, following the rules above. On the last row inside an open node, add a horizontal offset from the left to pick the target level, such as `at left+20,bottom-2`.

## Keyboard

| Key | Action |
| --- | --- |
| Up, Down, Home, End, Page Up, Page Down | Move selection |
| Right | Expand node, or move to first child |
| Left | Collapse node, or move to parent |
| Enter | Activate (`onActivate`) |
| Typing letters/digits | Type-ahead jump to matching visible node |
