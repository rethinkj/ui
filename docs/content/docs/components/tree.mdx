title: Tree

`Tree.tree` displays expandable hierarchical data (such as servers, databases, schemas, tables, and columns). It builds only visible rows, so 100,000 expanded nodes scroll smoothly. Your app implements `Tree.Model` and stores which nodes are expanded and selected.

For flat navigation lists, use [NavList](/docs/components/nav-list). For multi-column tables, use [DataGrid](/docs/components/data-grid).

Javadoc: [`Tree`](/api/com/rethinkj/ui/kit/Tree.html), [`Tree.Model`](/api/com/rethinkj/ui/kit/Tree.Model.html), [`Tree.Options`](/api/com/rethinkj/ui/kit/Tree.Options.html).

Pass `new Tree.Options<Node>()` to `Tree.tree(model, options)`:

| Option | Description |
| --- | --- |
| `open(isOpen, onToggle)` | Returns whether a node is expanded and handles expand/collapse clicks (start async child loading here) |
| `select(selected, onSelect)` | Tracks selection (`onSelect` fires only when selection changes; required for keyboard focus) |
| `onActivate(handler)` | Runs on **Enter** or double-click (for example, opening a table) |
| `toggleOnDoublePress(predicate)` | Controls whether double-click also expands/collapses a node (all nodes by default) |
| `drag(dragging, canDrag, canDrop, onDrop)` | Lets the user drag nodes and drop them before, after or into others (see [Drag and drop](#drag-and-drop)) |

Right-clicking selects the row before opening a `Menu.contextMenu(tree, menuState, items)`. Inside a card, wrap the tree in `Card.inset(tree)`. Expand/collapse chevrons require `rethinkj-ui-icons`.

## `Tree.Model`

| Method | Description |
| --- | --- |
| `roots()` | Top-level nodes |
| `children(node)` | Returns `Tree.ready(list)`, `Tree.loading([text])`, or `Tree.failed(message[, action, onAction])` |
| `isLeaf(node)` | Returns `true` for leaf nodes (hides expand chevron) |
| `label(node)` | Row label text |
| `icon(node)` | Optional leading element/icon (`null` by default) |
| `detail(node)` | Optional muted trailing text such as type or row count (`null` by default) |
| `muted(node)` | Renders label in muted color, e.g., for system schemas (`false` by default) |
| `key(node)` | Optional stable unique row key (no spaces/quotes, not digits-only) |

## Drag and drop

`drag(dragging, canDrag, canDrop, onDrop)` lets the user move nodes. Keep one `Tree.Dragging` per tree in your state. `canDrag` says which nodes can be dragged, `canDrop` whether a `Tree.Move` is allowed, and `onDrop` receives the move on release. The tree changes nothing itself: your app moves the node in its model.

```java snippet="tree-drag"
```

A `Tree.Move` has the dragged `node`, the `target` it was dropped on, and a `place`: `BEFORE` or `AFTER` the target among its siblings, or `INTO` the target. The model has no parents, so the target tells where the node goes. The tree never offers a move into the node itself or one of its descendants, and never asks `canDrop` about one.

- The middle half of a row that can take the node means `INTO`; the tree outlines the row.
- Above that it means `BEFORE` the row's node, below it `AFTER` the node, or `BEFORE` the first child of an open node. A line shows the place.
- In the lower part of the last row inside an open node, the pointer's horizontal position picks the level: over the row it means after that row's node, one indent further left after its parent. So "after the last child" and "after the open node itself" are different drops.
- Below all rows means `AFTER` the last root.
- Where `canDrop` says no, nothing shows and a release does nothing.

<Shot src="kit/tree-{theme}-drop-line" alt="A schema tree while the table changes is dragged: its label muted, and a line in the accent's color below notification_preferences, at the level of the tables" />

<Shot src="kit/tree-{theme}-drop-into" alt="The same drag over the schema public, whose row is outlined in the accent's color" />

Near the top or bottom edge the tree scrolls while the pointer waits there. A closed node opens after the pointer rests on it for the theme's `submenuDelay` where the node could go into it. **Escape** cancels the drag. A click or double-click without dragging selects, opens and activates as before. Select the moved node in `onDrop`, so the rows follow it to its new place.

A script drags with `down`, `move` and `up`. A row's center means `INTO` where the node may go there, else the place below the row. For other places, aim near a row's top or bottom edge with `at` (see [A point near an edge](/docs/testing/selectors#a-point-near-an-edge)):

```text
down role=treeitem label="orders"
move role=treeitem label="audit" at top+2
up role=treeitem label="audit" at top+2   # before audit
frame
```

`at bottom-2` aims at the place below a row, as the rules above give it. In the last row inside an open node, add a distance from the left for the level, as in `at left+20,bottom-2`.

## Keyboard

| Key | Action |
| --- | --- |
| Up, Down, Home, End, Page Up, Page Down | Move selection |
| Right | Expand node, or move to first child |
| Left | Collapse node, or move to parent |
| Enter | Activate (`onActivate`) |
| Typing letters/digits | Type-ahead jump to matching visible node |
