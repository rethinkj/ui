---
title: DiffView
description: Two versions of a text side by side or unified, with changed lines and words tinted, unchanged lines collapsed, and F7 to go from change to change.
---

`DiffView` shows how two versions of a text differ, in the code editor's look. The app supplies both strings, such as a file and its version in the app's repository; the framework holds no version control. It lives in `rethinkj-ui-editor`, package `com.rethinkj.ui.editor`, beside [CodeEditor](/docs/components/code-editor).

Javadoc: [`DiffView`](/api/com/rethinkj/ui/editor/DiffView.html), [`DiffView.State`](/api/com/rethinkj/ui/editor/DiffView.State.html), [`DiffView.Side`](/api/com/rethinkj/ui/editor/DiffView.Side.html), [`DiffView.Lines`](/api/com/rethinkj/ui/editor/DiffView.Lines.html), [`Diff`](/api/com/rethinkj/ui/editor/Diff.html).

- Added lines are tinted green and removed lines red. Side by side, lines that replace others are tinted blue on both sides; unified, they show as removed lines above added ones. The changed words inside them are stronger. The gutter's change lane and the scrollbar mark each change.
- Unchanged lines more than three away from a change collapse into a row that expands on a press.
- **F7** goes to the next change and **Shift+F7** to the one before. `DiffView.State.nextChange()` and `previousChange()` do the same from a button.
- Both sides are read-only. `Diff.lines(oldText, newText)` gives the changes without a view.

## Review comments

`DiffView.State.markup(side, layer, text, marks)` puts the marks of a [CodeEditor](/docs/components/code-editor) layer on the old or the new side, and `noMarkup(side, layer)` clears them; the layer name `"diff"` is the view's own. Side by side, a `CodeEditor.Block` on one side gets empty space of the same height on the other, so the lines below stay beside each other while a thread grows. Lines with marks never collapse. `lineAction(symbol, label, onPress)` offers an action in the gutter of both sides and reports the side and the lines.

In the unified view, `Side.NEW` marks apply directly to the editor, and `Side.OLD` marks on unchanged lines map onto their matching new lines. On removed lines, a `CodeEditor.Block` splits the removed lines right below its line, `Highlight.Tone.NOTE` tints the row and draws the gutter stripe, markers show in the gutter icon lane, and hovering a removed row reveals the gutter line action (dragging over removed rows stays within the same removed run). Because the keyboard cannot reach removed lines, the line action's context menu item acts on `Side.NEW` lines only.

<Shot src="examples/docs/diff-view-review-unified/view-{theme}" alt="A unified SQL diff with a hovered plus button on a removed line, a violet noted removed line with its gutter stripe, and a framed review card placed right below that removed line" />

Keep one `DiffView.State` per view in the app's state. It holds which change is current, which unchanged lines are expanded, and the app's markup layers and line action, and it can be passed to either layout.
