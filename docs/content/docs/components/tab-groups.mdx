---
title: TabGroups
description: Multi-window and split tab manager supporting drag reordering, split panes, tearing tabs off into new windows, and docking them back.
---

`TabGroups` manages tabs across multiple windows and split groups, just like a web browser or IDE: users can reorder tabs, split groups side by side or stacked within any window (with `.splits(true)`), drag a tab out into a new floating window, and drop it onto any group's tab bar — or onto its panel when splits are enabled. Store one `TabGroups` in your shared app state and render each window with `groups.tabs(frame, ...)`.

For single-window tabs without splitting, tear-off, or multi-group management, use [Tabs](/docs/components/tabs).

Javadoc: [`TabGroups`](/api/com/rethinkj/ui/kit/TabGroups.html), [`TabGroups.Frame`](/api/com/rethinkj/ui/kit/TabGroups.Frame.html), [`TabGroups.Group`](/api/com/rethinkj/ui/kit/TabGroups.Group.html).

- Every window has a `TabGroups.Frame<T>` holding a binary tree of splits whose leaves are `TabGroups.Group<T>` instances. `groups.main()` returns the primary window's frame; `groups.frames()` lists every open frame. For single-window apps that only need split groups (no tear-off windows), use `new TabGroups<>(tabs)` without an opener.
- The window-opener callback receives the new `Frame<T>` and opens a window running an `App` over the same state so all windows stay synchronized. Pass the provided `Window.Options` through (adding `frameless()` or an icon if desired).
- `groups.tabs(frame, tabToUi, tabToContent)` builds the frame's tab bar(s) and active content (`tabToContent` receives `null` when a group is empty). Hand `tabs.onKey()` (never `null`) to your window root so tab shortcuts act on the frame's active group from anywhere in the window.
- Tabs are compared by object identity (`==`); each tab instance can live in at most one group at a time (duplicates in the constructor or `add` are rejected).
- When closing the main window of a multi-window app, close every open window in `loop.windows().all()` from the main window's `onCloseRequest` (see [Documents](/docs/examples/documents)).

## Splitting within a window

Splits are opt-in: call `.splits(true)` on your `TabGroups` instance to enable them in every window (including torn-off windows).

<Shot src="examples/docs/tab-groups-split/drop-zone-{theme}" alt="Dragging the Ideas tab over the right edge of the panel shows an inset drop-zone preview" caption="Dropping on a panel's outer third splits the group to that side." />

- Each tab's context menu adds **Split right** (`Ctrl+\`) and **Split down**, disabled for a group's only tab or whenever both halves would be smaller than `Theme.Sizes.minTabGroup`. On keyboard layouts where `\` requires AltGr (such as German), use the tab's context menu or drag to an edge instead of `Ctrl+\`.
- While dragging a tab, each group's panel in any open window (except a following tear-off window itself) shows drop zones on top of its content (including content with its own `onDrop`, such as a `Tree`): the outer third toward an edge splits the tab out to that side wherever the target group is non-empty and both halves fit `Theme.Sizes.minTabGroup`, and the center docks it at the end of another group. On the dragged tab's own group, only the edge split zones are active (releasing over its own center leaves the tab in place), and zones are disabled on the dragged tab's own panel when it is that group's only tab (other one-tab groups can still receive it). An inset preview overlay marks the target area (`#zone` with `value="left"`, `"right"`, `"top"`, `"bottom"`, or `"center"` in tree dumps).
- With splits on, a drag tears its tab off into a new window only once the pointer leaves every window of the app (without a window runner, it stays inside). An emptied source group is pruned only when the drag commits, so pressing **Escape** restores the tab to its original group, split, and divider position.
- Split groups render with `Split.cards` starting at a 0.5 share; double-clicking or pressing Enter on a divider resets it to half.
- When a group in a split becomes empty, it leaves its frame and its sibling takes the split's place (handing keyboard focus to that sibling if the closed group had focus). A frame with one group renders identically to a plain `Tabs` component; in a split frame, each group's root is keyed `#group-<id>` from a counter that never repeats.
- `frame.active()` tracks the active group of a window (updated on `onFocusIn` or any press in a group, including pressing its already-active tab without moving focus). Only the active group shows the accent mark along the top of its active tab; inactive groups omit it.
- Programmatically split with `groups.split(from, index, beside, side)` (`Side.LEFT`, `RIGHT`, `TOP`, `BOTTOM`), focus a group with `groups.focusGroup(group)`, inspect `frame.groups()` (top-left first) and `group.frame()`.

## Opening drags from elsewhere

Call `.accept(payload -> …)` so users can drag items from elsewhere in the app — such as a sidebar row with `El.dragPayload` and `El.onDrag` — into any group's tab bar or, with `.splits(true)`, onto a group's center or split edges, in any open window (on Wayland only in the window the drag began in):

```java snippet="tab-groups-accept"
```

- The handler receives any drag payload that is not a tab of these groups and returns the tab to open, or `null` to refuse it. Because it runs on each drag step over a group (to decide whether to show the bar's insertion marker or panel drop zones) and once on the drop, keep it cheap and free of side effects until the drop.
- If the handler returns a tab that is already open in some group (by identity, `groupOf(tab) != null`), `TabGroups` moves that tab to the drop spot instead of opening it twice; otherwise the returned tab is added there, made active, and its group is focused.
- Panel drop zones for external drags listen on the panel itself rather than an intercepting overlay, so drop targets inside a tab's content (such as a `Tree`) still take precedence. Pressing **Escape** or dropping outside leaves the groups unchanged.

## Callbacks and programmatic control

```java snippet="tab-groups-options"
```

| Method | Description |
| --- | --- |
| `splits(boolean)` | Enables splitting within windows (off by default) |
| `accept(payload -> …)` | Opens or moves a tab when a non-tab drag drops on a bar, center, or split edge (returns `null` to refuse) |
| `onWindowClose(frame -> …)` | Action when a detached window closes, by a close request or the app's `Handle.close()`: `dockAll` (default) or `closeAll` |
| `onCloseTab((group, index) -> …)` | Custom close handler (e.g., to confirm unsaved changes before calling `close`) |
| `onCloseTabs((group, tabs) -> …)` | Optional batch close handler for **Close others** and **Close to the right** (defaults to `onCloseTab` per tab, stopping if a tab stays open) |
| `onClosed(tab -> …)` | Notification after a tab is closed |
| `onAdd(group -> …)` | Shows a `+` button and binds Ctrl+T in each group's bar, passing the group |
| `tabMenu((group, tab) -> …)` | Appends app-specific items to each tab's context menu (separated from the built-in items) |

You can also manipulate tabs from code with `select`, `focusGroup`, `add`, `close`, `move`, `dock`, `split`, `toNewWindow` (a no-op on a detached window's lone tab), `dockAll` (into the main frame's active group or a chosen target group), `closeAll`, `frames`, `groups`, and `groupOf(tab)`. See [`TabGroups` Javadoc](/api/com/rethinkj/ui/kit/TabGroups.html).

## Focus and state across splits and windows

`TabGroups` remembers keyboard focus per tab automatically. Moving a group into or out of a split re-parents it in the element tree, just as moving a tab to another window does — so identity-bound state (caret, undo history, scroll offsets, remembered focus) does not survive a split, unsplit, or window move. Keep a field's caret and undo history in a `FieldState` and a scroll offset in a `ScrollState` inside each tab's own model object; the remembered focus starts anew (see [Several windows](/docs/concepts/windows) and the [Workbench](/docs/examples/workbench) example).

## User interaction

- Drag a tab along a bar to reorder, drag it onto a group's outer edge or center (in the same or another window) to split or dock when splits are enabled, drag it outside to tear off into a new window, or drop it onto another group's tab bar to dock it. Press **Escape** to cancel a drag and return the tab where it came from (including its split and divider position). When you tear off a tab near a screen edge, the new window shifts fully into the screen's work area (above the taskbar) as far as its minimum size allows. On Wayland, the compositor places the window instead.
- Right-click any tab for **Close**, **Close others**, **Close to the right** (respecting each tab's `closable` flag and `onCloseTab`), **Split right** and **Split down** (when splits are enabled), **Move to new window** and **Move back to main window** (when a window opener is configured; essential on Linux Wayland, where apps cannot position floating windows), plus any custom items from `tabMenu`.
- When a group's tabs overflow its bar, an **All tabs** button appears at the bar's end to list every tab in the group and scroll the chosen one into view.

## Keyboard

All [Tabs](/docs/components/tabs#keyboard) shortcuts apply to the frame's active group, plus the split-group shortcuts below:

| Key | Action |
| --- | --- |
| Left, Right, Home, End | Switch tabs while a group's tab bar is focused |
| Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+PageDown, Ctrl+PageUp | Next / previous tab in the active group |
| Ctrl+Shift+PageUp, Ctrl+Shift+PageDown | Reorder active tab within its group |
| Ctrl+W, Ctrl+F4 | Request to close the active tab if closable (invokes `onCloseTab`) |
| Ctrl+T | Add a tab in the active group (when `onAdd` is set) |
| Ctrl+\ | Split active tab right (when `splits(true)` and room allows) |
| F6, Shift+F6 | Cycle focus to the next / previous split group in the window |
| Ctrl+1 … Ctrl+9 | Focus split group 1–9 (top-left first) in a split window |
| Menu key, Shift+F10 | Open the active tab's context menu while a group's tab bar has focus |
| Escape | Cancel an active tab drag and restore its previous position |

## In a tree dump

In addition to the [Tabs](/docs/components/tabs#in-a-tree-dump) keys (`#tablist`, `#tab-<index>`, `#close-<index>`, `#add`, `#overflow`, `#panel`, `#marker`), `TabGroups` adds:

- `#group-<id>`: root of each group inside a split frame (monotonically increasing id, omitted when a frame has only one group)
- `#content-<n>`: per-tab wrapper inside `#panel` that remembers focus by identity
- `#drop` and `#zone`: drop-zone hit layer and preview overlay inside `#panel` during a drag (`value="left"`, `"right"`, `"top"`, `"bottom"`, or `"center"`)
