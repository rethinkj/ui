title: ComboBox
description: A choice made by typing, a free text with suggestions, and choices with icons, images or details.

`ComboBox.comboBox` looks like a [Select](/docs/components/select) when closed; typing opens a field with the choices below it, filtered by fuzzy matching. Use it for many choices or ones the user knows by name: a schema among dozens, a language. `ComboBox.free` is a text field whose every edit is the value, with suggestions, for a host or a database name. `ComboBox.items` is a choice of items with an icon, image or own element and a detail.

| Call | |
| --- | --- |
| `comboBox(t, choices, selected, state, onSelect)` | One of the choices, told by index |
| `free(t, value, suggestions, state, onChange)` | Any text; suggestions open as one types, none highlighted, so Enter keeps what was typed |
| `items(t, items, selected, state, onSelect)` | Items: `ComboBox.item(text).icon(symbol)`, `.image(image)`, `.leading(theme -> element)`, `.detail(text)` |

The app keeps a `ComboBox.State` and the value. A null handler disables it. It is the control height unless the view sets one, so it fits a grid's cell. Pass the same list on every build, so that the box keeps what its filter found.

## Values instead of indexes

`comboBox(t, values, selected, text, state, onSelect)` and `items(t, values, selected, value -> item, state, onSelect)` choose among values of any type, such as records, and tell the value:

```java snippet="combo-items-typed"
```

The selected value is found by `equals`, a null among the values too; null where the list has none, or a value not in the list, selects nothing. Equal values show once, so that the keys go on from the selected value to the next one that differs; a null handler disables it. The texts or items are made again in every build, one call per value, and while they come out equal to the last build's (for items: equal values, texts and details), the box hands on the list of the last build, so its filter keeps what it found although the view maps its values anew. What stands before an item's text is taken to follow from its value.

## Keyboard

| Keys | Action |
| --- | --- |
| A letter or digit, Alt+Down, Alt+Up, a press | Open |
| Up, Down, Page Up, Page Down, Home, End | Move the highlight |
| Enter | Choose; the focus stays on the combo box |
| Escape, Tab, Shift+Tab, a press outside | Close; the choice stays as it was |

## With a Prop

`comboBox(t, values, prop, text, state)`, `items(t, values, prop, item, state)` and `free(t, prop, suggestions, state)` take a `Prop` in place of the value and its handler, such as a field of an [Editing](/docs/concepts/editing) of a record: they write the prop back, show its field's error, and are disabled when the prop cannot be written.
