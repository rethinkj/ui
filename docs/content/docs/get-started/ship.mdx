---
title: Ship your app
description: Package your app with its own Java runtime using jpackage.
---

Use `jpackage` (included with JDK 25) to bundle your app into a standalone app image containing a native launcher, a minimal Java runtime, and your JARs. End users do not need Java installed.

The commands below assume you started from the Maven project in [Installation](/docs/get-started). When a step differs on Windows, the tabs show PowerShell and cmd commands.

## 1. Build the app image

First, copy all runtime dependencies (including fonts, icons, and native libraries) into `target/lib`:

```sh
mvn -q package dependency:copy-dependencies -DincludeScope=runtime -DoutputDirectory=target/lib
```

Then add your app JAR and build the app image with `jpackage`:

<Tabs groupId="shell" persist items={['Linux', 'PowerShell', 'cmd']}>
<Tab value="Linux">

```sh
cp target/lights-1.0-SNAPSHOT.jar target/lib/
jpackage --type app-image --name Lights \
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights \
  --add-modules java.base \
  --java-options --enable-native-access=ALL-UNNAMED \
  --dest target/dist
```

</Tab>
<Tab value="PowerShell">

```powershell
cp target/lights-1.0-SNAPSHOT.jar target/lib/
jpackage --type app-image --name Lights `
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights `
  --add-modules java.base `
  --java-options --enable-native-access=ALL-UNNAMED `
  --dest target/dist
```

</Tab>
<Tab value="cmd">

```bat
copy target\lights-1.0-SNAPSHOT.jar target\lib\
jpackage --type app-image --name Lights ^
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights ^
  --add-modules java.base ^
  --java-options --enable-native-access=ALL-UNNAMED ^
  --dest target/dist
```

</Tab>
</Tabs>

- `--add-modules java.base` keeps the bundled runtime small because `core` and `kit` only need `java.base`. Add any extra JDK modules your own code uses.
- `jpackage` builds for the current operating system only. Run it on Windows to build a Windows app image.

## 2. Run the packaged app

<Tabs groupId="shell" persist items={['Linux', 'PowerShell', 'cmd']}>
<Tab value="Linux">

```sh
target/dist/Lights/bin/Lights                                            # open in a window
target/dist/Lights/bin/Lights --script lights.txt --out target/packaged  # run headless with a script
```

</Tab>
<Tab value="PowerShell">

```powershell
target\dist\Lights\Lights.exe                                                      # open in a window
target\dist\Lights\Lights.exe --script lights.txt --out target\packaged | Out-Host  # run headless with a script
```

</Tab>
<Tab value="cmd">

```bat
target\dist\Lights\Lights.exe
target\dist\Lights\Lights.exe --script lights.txt --out target\packaged | more
```

</Tab>
</Tabs>

On Windows, `Lights.exe` is a GUI program. An interactive PowerShell or cmd prompt does not wait for it or show its output. Piping the output as shown above makes the prompt wait for the script and print the image and tree paths.

## Optional: App icon

Without `--icon`, the launcher and installer use the default `jpackage` icon. To use your own icon, save your window's `WindowIcon` to a file in a build step and pass it to `--icon`. On Windows, write the bytes from `icon.ico()` to `Lights.ico`. On Linux, write a PNG from the bytes of `Png.encode(icon.image(256))`.

## Optional: Faster startup with an AOT cache

Java 25 supports an ahead-of-time (AOT) class cache ([JEP 514](https://openjdk.org/jeps/514)) to make startup faster.

1. Close the app, then build the app image again while keeping the `java` binary (remove `--strip-native-commands` from `--jlink-options`):

<Tabs groupId="shell" persist items={['Linux', 'PowerShell', 'cmd']}>
<Tab value="Linux">

```sh
rm -rf target/dist
jpackage --type app-image --name Lights \
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights \
  --add-modules java.base \
  --jlink-options '--strip-debug --no-man-pages --no-header-files' \
  --java-options --enable-native-access=ALL-UNNAMED \
  --dest target/dist
```

</Tab>
<Tab value="PowerShell">

```powershell
Remove-Item -Recurse -Force target\dist
jpackage --type app-image --name Lights `
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights `
  --add-modules java.base `
  --jlink-options '--strip-debug --no-man-pages --no-header-files' `
  --java-options --enable-native-access=ALL-UNNAMED `
  --dest target/dist
```

</Tab>
<Tab value="cmd">

```bat
rmdir /s /q target\dist
jpackage --type app-image --name Lights ^
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights ^
  --add-modules java.base ^
  --jlink-options "--strip-debug --no-man-pages --no-header-files" ^
  --java-options --enable-native-access=ALL-UNNAMED ^
  --dest target/dist
```

</Tab>
</Tabs>

2. Run the app once to record the cache, close the window, and add the cache flag to `Lights.cfg`:

<Tabs groupId="shell" persist items={['Linux', 'PowerShell', 'cmd']}>
<Tab value="Linux">

```sh
JAVA_TOOL_OPTIONS=-XX:AOTCacheOutput=target/dist/Lights/lib/app/lights.aot target/dist/Lights/bin/Lights
echo 'java-options=-XX:AOTCache=$APPDIR/lights.aot' >> target/dist/Lights/lib/app/Lights.cfg
```

</Tab>
<Tab value="PowerShell">

```powershell
$saved = $env:JAVA_TOOL_OPTIONS
$env:JAVA_TOOL_OPTIONS = '-XX:AOTCacheOutput=target\dist\Lights\app\lights.aot'
target\dist\Lights\Lights.exe | Out-Host
$env:JAVA_TOOL_OPTIONS = $saved
Add-Content target\dist\Lights\app\Lights.cfg 'java-options=-XX:AOTCache=$APPDIR\lights.aot'
```

Use `Add-Content`, not `>>`. Windows PowerShell 5.1 writes `>>` output as UTF-16, and the launcher skips that line.

</Tab>
<Tab value="cmd">

```bat
cmd /d /c "set JAVA_TOOL_OPTIONS=-XX:AOTCacheOutput=target\dist\Lights\app\lights.aot&& target\dist\Lights\Lights.exe"
echo java-options=-XX:AOTCache=$APPDIR\lights.aot>> target\dist\Lights\app\Lights.cfg
```

</Tab>
</Tabs>

> **Note:** Rebuild the `.aot` cache whenever you rebuild the app image. An outdated cache will be ignored with a startup warning.

If your app runs heavy initialization before opening its first window, you can also call [`GpuPresenter.prepare()`](/api/com/rethinkj/ui/render/GpuPresenter.html#prepare()) early in `main` to initialize the GPU on a background thread. Skip it when `main` runs a script instead (`Script.handle`), which opens no window. The Agent Chat example does this. On Windows, that brings its first frame about 75 ms sooner without the cache and about 20 ms sooner with it, because the cache shortens the app's own start.

## Optional: Pre-extract native libraries

By default, the app extracts native libraries into a per-user cache on first launch. To avoid extraction at runtime, you can unpack them into the app image during packaging and set `rethinkj.ui.natives.dir`. That saves the extraction, about 0.3 s on Windows, but not Microsoft Defender's check of DLLs it has not seen before, which can hold their first load for several seconds. Close the app first, because Windows cannot delete files while the app is running:

<Tabs groupId="shell" persist items={['Linux', 'PowerShell', 'cmd']}>
<Tab value="Linux">

```sh
mkdir target/lib/natives
unzip -j target/lib/rethinkj-ui-natives-linux-x64-0.1.0-SNAPSHOT.jar \
  'META-INF/rethinkj-ui/natives/linux-x64/*' -x '*/licenses/*' -d target/lib/natives
rm target/lib/rethinkj-ui-natives-linux-x64-0.1.0-SNAPSHOT.jar
rm -rf target/dist
jpackage --type app-image --name Lights \
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights \
  --add-modules java.base \
  --java-options --enable-native-access=ALL-UNNAMED \
  --java-options '-Drethinkj.ui.natives.dir=$APPDIR/natives' \
  --dest target/dist
```

</Tab>
<Tab value="PowerShell">

```powershell
mkdir target\lib\natives
tar -xf target\lib\rethinkj-ui-natives-windows-x64-0.1.0-SNAPSHOT.jar -C target\lib\natives `
  --strip-components 4 --exclude "*/licenses/*" "META-INF/rethinkj-ui/natives/windows-x64/*"
rm target\lib\rethinkj-ui-natives-windows-x64-0.1.0-SNAPSHOT.jar
Remove-Item -Recurse -Force target\dist
jpackage --type app-image --name Lights `
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights `
  --add-modules java.base `
  --java-options --enable-native-access=ALL-UNNAMED `
  --java-options '-Drethinkj.ui.natives.dir=$APPDIR\natives' `
  --dest target/dist
```

</Tab>
<Tab value="cmd">

```bat
mkdir target\lib\natives
tar -xf target\lib\rethinkj-ui-natives-windows-x64-0.1.0-SNAPSHOT.jar -C target\lib\natives ^
  --strip-components 4 --exclude "*/licenses/*" "META-INF/rethinkj-ui/natives/windows-x64/*"
del target\lib\rethinkj-ui-natives-windows-x64-0.1.0-SNAPSHOT.jar
rmdir /s /q target\dist
jpackage --type app-image --name Lights ^
  --input target/lib --main-jar lights-1.0-SNAPSHOT.jar --main-class com.example.Lights ^
  --add-modules java.base ^
  --java-options --enable-native-access=ALL-UNNAMED ^
  --java-options "-Drethinkj.ui.natives.dir=$APPDIR\natives" ^
  --dest target/dist
```

</Tab>
</Tabs>

`$APPDIR` points to the app's JAR directory inside the image. Windows includes `tar` (which can unpack JAR files), while `unzip` is usually not installed. Remember to include the third-party license files from `META-INF/rethinkj-ui/natives/<platform>/licenses/` when distributing your app.

Rebuilding the app image removes any AOT cache. To use both pre-extracted native libraries and an AOT cache, add `--jlink-options` from the AOT section to this `jpackage` command, then record the cache again as shown in step 2 of the AOT section.
