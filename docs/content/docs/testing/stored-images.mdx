You can test your views in JUnit by running a script and comparing each `snap` against stored reference ("golden") files in your repository — images pixel by pixel, and trees line by line. When you intentionally change a view, regenerate the stored files and review them before committing.

- `Script.run` returns the generated files (`.png`, `.tree.txt`, `.clipboard.txt` when clipboard text exists, `.opened.txt` when the app opened web addresses, and `.windows.txt` when more than one window is open).
- `Png.decode` loads a PNG into `Pixels` without needing `java.desktop`.
- Pass `-Dgolden.update=true` to overwrite stored files after intentional UI changes, then inspect the updated images and tree diffs before committing.

## What to test

- **Element trees:** Fast, tiny in Git, and easy to read in diffs. Compare trees in every UI test.
- **Screenshots:** Catch visual issues that trees cannot see (colors, alignment, clipping, text rendering). Store a few key screenshots per view (use `scale 2` for sharp text, and both themes when testing colors).
- **Direct assertions:** Assert key states directly (for example, check that `role=switch label="Lamp"` has `checked`) so test failures immediately explain what broke.
