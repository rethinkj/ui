title: Stored images as tests
description: JUnit tests that run a script and compare its images and trees with stored ones.
---

A view test runs a script against the app and compares what each `snap` wrote with files stored in your repository: images pixel for pixel, trees line by line. After a deliberate change, the test stores the new files instead, and you look at them before committing.

## A test

```java snippet="stored-images" title="StoredImagesTest.java"
```

- `app.textRendering(TextRendering.LINUX)` fixes the text rendering, so the images are the same on Windows and Linux. The system property `rethinkj.ui.textRendering` (`linux` or `windows`) does the same for a whole test run, for example in Surefire's `systemPropertyVariables`.
- `Script.run` returns the files it wrote, `.png` and `.tree.txt` for each snap, and `.clipboard.txt` when the `main` window's clipboard holds text.
- `Png.decode` reads a PNG into `Pixels` without `java.desktop`.
- Run it with `-Dgolden.update=true` to store new snaps, then look at the images and the tree diff before you commit.

The tests need the native libraries for text. Where they cannot load, skip the test with an assumption:

```java snippet="assume-text"
```

## What to compare

- **Trees** are cheap to store, read well in a diff and say what matters: roles, labels, states, rectangles. Compare them in every test.
- **Images** catch what trees do not: colors, clipping, text rendering. Store a few per view, at scale 2 where text matters, and in both themes where colors matter.
- Assert the states the test is about directly, so a failure says what is wrong: that the line with `role=switch label="Lamp"` ends in `checked`.
