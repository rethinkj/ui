---
title: Targets and selectors
description: How script commands find UI elements by key, role, label, text, state, or coordinates.
---

Commands like `press`, `move`, `wheel`, `drop`, `focus`, and `scroll` take a **target**: either coordinates or a **selector** that matches exactly one element from the last rendered frame.

## Target syntax

| Target | Meaning |
| --- | --- |
| `x,y` | Coordinates in logical pixels. |
| `#key` | Element with this `.key(...)`. While a modal overlay (such as a dialog) is open, searches only inside the modal and overlays above it. |
| `role=<role>` | Element with this role (for example: `button`, `switch`, `textbox`, `gridcell`, `treeitem`). |
| `label="<text>"` | Element with this label (escape quotes and backslashes as `\"` and `\\`). |
| `text="<string>"` | Text element showing this exact string. |
| State filter | `selected`, `current`, `checked`, `checked=false`, `checked=mixed`, `expanded`, `expanded=false`, `disabled`, `readonly`, `password`, `revealed`, `invalid`, `busy`, `grabbed`, `modified`, `level=<n>`, `pos=<n>/<size>`, `sort=ascending`, `sort=descending`, `value="<text>"`. |
| `in <window> <target>` | Target inside another window (for pointer commands and `drop`). For `focus` and `scroll`, call `window <name>` first. |
| `screen <x>,<y>` | Physical screen coordinates, hitting whichever window is at that point (for pointer commands and `drop`). |

Combine multiple parts with spaces — every part must match:

```text
press role=switch label="Lights"
press role=treeitem expanded label="public"
press #cell-2-1 clicks 2
move role=button label="Refresh"
```

Commands act on the center of the element's visible area (or the middle of the first line for an `El.range`).

**Animations and visibility:** Elements that are fading out (`exiting`) or at opacity `0` cannot be matched. Because most kit components fade in from opacity `0`, advance the clock before interacting with a newly opened element: run `advance 1` and `frame` first.

**Modal overlays:** While a modal dialog is open, selectors only search inside the dialog and overlays above it, so a `Cancel` button in the dialog will not collide with a `Cancel` button behind it.

## Virtual lists

Virtual row lists only build visible rows (plus a small buffer), so selectors can only match built rows. Scroll to a row before clicking it:

```text
scroll #rows row 765432
frame
press #row-765432
```

## Debugging selector errors

- **No match:** The error lists all available keys, roles, labels, states, texts, and built row ranges. If an element matched everything except a state, it shows that element's actual states.
- **Multiple matches:** The error lists every matching element with its bounds so you can narrow your selector.

## Best practices

- Prefer `role` and `label` selectors: they stay readable and do not break when layouts shift.
- Add `.key(...)` to repeated elements like rows and cells (kit components already add keys like `row-<index>`, `cell-<row>-<column>`, and `item-<index>`).
- Check the **In a tree dump** section on each component's documentation page to see its exact roles, keys, and states.
