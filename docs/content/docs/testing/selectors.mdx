---
title: Targets and selectors
description: How script steps find the element they act on.
---

The target of a `press`, `move`, `wheel`, `drop`, `focus` or `scroll` is a position or a selector. A selector finds exactly one element of the last frame by its role and label, key, text or states.

## Targets

| Target | Meaning |
| --- | --- |
| `x,y` | A position in logical pixels. |
| `#key` | The element with this key, anywhere in the tree and its overlays; while a modal overlay is open, such as a dialog, only in it and the overlays above it. |
| `role=<role>` | The element with this role, such as `button`, `switch`, `textbox`, `gridcell`, `treeitem`. |
| `label="<text>"` | The element with this label. `\"` and `\\` inside. |
| `text="<string>"` | The text element showing exactly this string, written as the tree writes it. |
| a state | `selected`, `current`, `checked`, `checked=false`, `checked=mixed`, `expanded`, `expanded=false`, `disabled`, `readonly`, `password`, `revealed`, `invalid`, `busy`, `grabbed`, `modified`, `level=<n>`, `pos=<n>/<size>`, `sort=ascending`, `sort=descending`, `value="<text>"`. |
| `in <window> <target>` | A target in another window, for the pointer's steps (`press`, `down`, `up`, `move`, `wheel`) and `drop`. For `focus` and `scroll`, choose the window first with `window <name>`. |
| `screen <x>,<y>` | A point of the script's screen in physical pixels, in whichever window lies there; for the pointer's steps and `drop` only. |

Combine parts with spaces: all must match.

```text
press role=switch label="Lights"
press role=treeitem expanded label="public"
press #cell-2-1 clicks 2
move role=button label="Refresh"
```

A step acts on the center of the visible part of the element's rectangle; for an element over a range of text (`El.range`), on the middle of the range's first row. Elements that are fading out (`exiting`) or at opacity 0 never match, as the pointer does not hit them either. An element with motion, as most kit components have, fades in from opacity 0 when it appears in a parent that was already there, so in the frame it appears it does not match; the clock moves only with `advance`, so run `advance 1` and `frame` before the step. The error then says that what matches is fading in or out.

While a modal overlay is open, such as a dialog, a selector searches only in it and the overlays above it, since presses reach nothing below it. A `Cancel` in a toolbar does not compete with the dialog's `Cancel`. A selector that matches only what lies below it fails and says so.

## Lists of rows

A list of rows builds only the rows in view and a few around them, so a selector finds only those. Scroll first, then press:

```text
scroll #rows row 765432
frame
press #row-765432
```

## When a selector fails

When a selector matches nothing, the error lists the keys, roles, labels, states and texts that exist, and the built rows of each list. When only its states do not match, it lists the elements that match the rest, with their states. When it matches several, it lists them with their rectangles. Pick the right selector from that list.

## Choosing good selectors

- Prefer `role` and `label`: they survive layout changes and read like the user's action.
- Give elements a `.key(...)` where there are many of a kind, such as rows and cells; the kit's components do (`row-<index>`, `cell-<row>-<column>`, `item-<index>`).
- Each component's page lists what it shows in the tree, under "In a tree dump".
