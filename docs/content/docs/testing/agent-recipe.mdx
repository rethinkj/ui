---
title: An agent builds a view
description: Step-by-step workflow for an AI agent (or developer) to build, inspect, and test a view without opening a window.
---

AI agents cannot see a desktop window, but they can read PNG screenshots and `.tree.txt` dumps. Follow this loop to build and verify views headlessly: write the view, run a script, inspect the tree and image, and save the script as a test.

## 1. Add script support to `main`

Call `Script.handle(args, app)` before opening a window (see [The first app](/docs/get-started/first-app)):

```java snippet="lights-main" title="Lights.java"
```

## 2. Build the view

Compose your UI from `rethinkj-ui-kit` components. Give interactive elements clear labels or keys so scripts can target them. Keep all state in your state object and only modify it inside handlers. See [Components](/docs/components) for examples and tree dump formats.

## 3. Write a script

List the user actions one per line, adding `snap` after each state you want to inspect:

```text snippet="dialog-script" title="dialog.txt"
```

- Add `advance 0.3` after opening a menu, dialog, or tooltip so fade-in animations finish (elements at opacity `0` or `exiting` cannot be clicked).
- Add `await` after triggering background work so results arrive before the next `frame` (or `await progress` to capture an in-progress snapshot).
- Use `scroll <list> row <n>` before clicking rows outside the current viewport.

## 4. Run the script

In a project set up as in [Installation](/docs/get-started):

```sh
mvn -q compile exec:exec -Dargs="--script my.txt --out target/my"
```

Or run it in Java with `Script.run(text, app, folder)`. If a step fails, the error message tells you the exact line and what to change.

## 5. Check the tree, then the screenshot

Verify roles, focus, and states in the `.tree.txt` file first:

```text file="examples/src/test/resources/golden/docs/dialog/open.tree.txt" start="overlay"
```

Here, the modal dialog is open, focus is inside the text field with the cursor at the end, and both buttons are enabled. Next, inspect the `.png` screenshot for visual issues: alignment, spacing, colors, clipped text, and overlaps. Check both dark and light themes at `scale 2`.

## 6. Save it as a JUnit test

Turn your script into a JUnit test using [Stored images as tests](/docs/testing/stored-images). Generate the reference files with `-Dgolden.update=true`, review them, and commit them with your view.

## Tips

- Prefer `role` and `label` selectors (`press role=button label="Save"`) over coordinates — they survive layout changes and give helpful error messages.
- Expose visual states in the tree (`selected`, `invalid`, `busy`, `value`) rather than relying on color alone. All kit components do this automatically.
- Keep script window sizes compact (`size 420 260`) for faster rendering and smaller images.
- Browse the full documentation as Markdown via [/llms.txt](/llms.txt).
