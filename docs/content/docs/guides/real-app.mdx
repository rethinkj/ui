The concept and component pages explain one piece each. This guide puts them together in one small app: a list of customers in a [DataGrid](/docs/components/data-grid), loaded from a slow server, edited in a [Dialog](/docs/components/dialog) and saved back, and a second view with notes. All of it is one class, `Customers`, which is the state; its static methods are the view.

## 2. Loading off the app's thread

The list comes from a server, and the app's thread must not wait for it. `app.background` runs the call on another thread and brings the result back as a task on the app's thread, where the handler may change the state ([Work off the app's thread](/docs/concepts/background-work)). Keep the returned `Work` in the state: `loading` says that a load runs, and `cancel()` stops it, so neither handler runs. Here leaving the customers cancels their load, and Reload cancels the load that runs before it starts another.

The customers view shows each state the load can be in: an [EmptyState](/docs/components/empty-state) while nothing has arrived, with Try again after a failure and with a hint while the list is empty, the grid once there are rows, and an indeterminate [Progress](/docs/components/progress) line under the toolbar while a load runs. The grid's columns are the record's parts; without `onCommit` the grid edits nothing ([Rows of records](/docs/components/data-grid/typed)).

## 3. Editing a record

The dialog edits a copy of a customer. An `Editing<Customer>` in the state holds the edited value, the text of fields that does not parse yet, and the errors; while it is not null, the dialog is open. Each field gets the `Prop` of its part, `e.at(Customer.EMAIL)`, so the view needs no value, handler or error per field ([Form](/docs/components/form#with-a-prop)).

- The name's format refuses blank text. Its error shows once the field was edited, or after `showErrors()`.
- A rule across two fields, company and VAT ID, shows its message at the VAT ID at once.
- Save is enabled once something changed. On a press while the edit is not valid, it calls `showErrors()`, so that an empty name the user never touched shows its error too.

## 4. Saving and errors

Save runs in the background like the load. While it runs, `saving` makes Save busy and Cancel disabled. The made-up server refuses an email that another customer has: it throws an exception that names the field, and `prop.error(message)` shows the message at that field until the user edits it. On success, the handler puts the saved record into the list, closes the dialog by clearing `editing`, and shows a [Toast](/docs/components/toast).
