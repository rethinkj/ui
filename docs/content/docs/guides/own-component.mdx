When you need a control that `rethinkj-ui-kit` does not include, you can build your own. This guide builds a tag input step by step: each tag is a removable [Badge](/docs/components/badge), followed by a text field where pressing Enter adds a new tag. It follows the same conventions as built-in components so it works smoothly inside forms and test scripts.

## 2. Style with theme tokens

Always read colors, spacing, sizes, radii, fonts, and springs from `Theme.CURRENT` instead of hardcoding values. This ensures your component works in both dark and light themes and adapts when the user changes themes (see [Themes](/docs/concepts/themes)).

Use `Colors` helpers (like `Colors.over`) for color mixing, and reuse existing kit components whenever possible — here each tag is a `Badge` with `onRemove`, which already provides the remove button, hover state, and focus ring.

## 4. Keyboard and focus

Because the inner text field is focusable, pressing Tab automatically moves through each tag's remove button and then to the text field. `onKey` on the text field runs before default text editing: return `true` to handle the key yourself, or `false` to let the text field handle it.


- **Enter** adds the typed tag and clears the draft text.
- **Backspace** in an empty field removes the last tag.
- Clicking a tag's remove button keeps focus in the text field because `Badge` sets `keepFocus()` on its remove button.

See [Input, focus and keys](/docs/concepts/input#keyboard-and-focus) for key handling order and [Text fields and editors](/docs/concepts/text-fields) for text field details.

## 5. Roles, labels and states

Add semantic roles, labels, and states so [tree dumps](/docs/testing/tree-dump), [selectors](/docs/testing/selectors), and assistive tools can understand your component:

- The outer container has `role("group")`, the joined tags as its `value`, and `disabled` when `onChange` is `null`. The caller's `.label("Tags")` names it.
- The text field uses its placeholder as its label, and each remove button is labeled `Remove <tag>`.
- Give repeating items unique keys (`tag-orders`, `tag-daily`) so animations and identity stay accurate when a tag is removed. Because sibling keys must be unique (duplicate keys throw an error), reject duplicate tags on Enter and deduplicate loaded tags (for example with `LinkedHashSet`).

See [States and roles](/docs/concepts/states) for the full list of supported states.
