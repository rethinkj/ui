---
title: Platforms and native libraries
description: Supported operating systems, native libraries, troubleshooting, and platform differences.
---

rethinkj UI supports **Windows 11+** and **Linux** (both x64) with **JDK 25**. On Linux, the native libraries need **glibc 2.38 or later**, as on Ubuntu 24.04, Debian 13 or Fedora 39 and later. They do not load on Ubuntu 22.04 or Debian 12.

It uses native libraries for windows, GPU rendering, and text:
- **SDL 3** for windows, input, clipboard, and dialogs
- **wgpu-native** for GPU rendering (Direct3D 12 on Windows, Vulkan on Linux)
- **FreeType** and **HarfBuzz** for text shaping and font rendering

All native libraries are packaged into one JAR per platform and load on first use.

## Bundled native library versions

| Library | Version | Purpose |
| --- | --- | --- |
| SDL | 3.4.20 | Windows, input, clipboard, and file dialogs |
| wgpu-native | 29.0.1.1 | GPU rendering |
| FreeType | 2.15.0 | Glyph rasterization |
| HarfBuzz | 15.1.0 | Text shaping |
| DirectX Shader Compiler | 1.9.2609 | Fast shader compilation on Direct3D 12 (Windows only) |

On Windows, the DirectX Shader Compiler (`dxcompiler.dll`, LLVM Release License) speeds up initial shader compilation and adds about 10 MB to the Windows JAR. If you ship pre-extracted natives via `rethinkj.ui.natives.dir` and omit `dxcompiler.dll` from `manifest.txt`, Windows falls back to its built-in FXC compiler. Third-party license files are included in each natives JAR under `META-INF/rethinkj-ui/natives/<platform>/licenses/`.

## Loading native libraries

On first run, native libraries are extracted to a per-user cache folder:
- **Windows:** `%LOCALAPPDATA%\rethinkj-ui\natives\`
- **Linux:** `$XDG_CACHE_HOME/rethinkj-ui/natives/` (defaults to `~/.cache/rethinkj-ui/natives/`)

System properties:
- `rethinkj.ui.natives.cache` — Extract native libraries to a custom cache folder.
- `rethinkj.ui.natives.dir` — Load native libraries directly from a pre-extracted folder containing the libraries and `manifest.txt` (useful for packaged apps).

Required JVM flags:
- **Classpath:** `--enable-native-access=ALL-UNNAMED`
- **Module path:** `--enable-native-access=com.rethinkj.ui --add-modules com.rethinkj.ui.natives.linux.x64` (or `windows.x64`). Without the natives module, add `--add-modules com.rethinkj.ui.fonts,com.rethinkj.ui.icons` for the resource modules you use.

## Troubleshooting

| Problem | Cause and solution |
| --- | --- |
| Warning or error about native access | Add `--enable-native-access=ALL-UNNAMED` (classpath) or `--enable-native-access=com.rethinkj.ui` (module path) to your JVM arguments. |
| `UnsatisfiedLinkError`: No native libraries on the class path | The natives JAR for your OS is missing from the runtime classpath. |
| `UnsatisfiedLinkError` naming a `GLIBC_` version that is not found | The system's glibc is older than the native libraries need; see the version at the top of this page. |
| Linux library fails to load from cache | The cache directory is on a `noexec` filesystem. Set `-Drethinkj.ui.natives.cache=<path>` to an executable directory. |
| No GPU adapter found | No Vulkan (Linux) or Direct3D 12 (Windows) GPU driver is available. Headless scripts and `Headless.render` still work using the CPU renderer. Note: GPU initialization happens on the first frame inside `WindowLoop.run`, not in `new GpuPresenter`. |
| CMake fails on Windows (building from source) | Install **C++ CMake tools for Windows** in Visual Studio, or pass `$env:CMAKE = '<folder>\bin\cmake.exe'`. |
| CMake fails on Linux (building from source) | A required development package is missing. Install the `apt` packages listed below. |
| Download fails on first source build | Internet access is required once to fetch native sources. |

## Platform differences

| Feature | Windows | Linux X11 | Linux Wayland |
| --- | --- | --- | --- |
| Frameless window snap layouts | Yes | Move and resize only | Move and resize only |
| Window positioning and tear-off tabs following the cursor | Yes | Yes | No (compositor controls placement) |
| Taskbar badge | Yes | No | No |
| System accent color detection | Yes | No | No |
| Native file dialogs | Windows dialog | XDG portal or zenity | XDG portal or zenity |

## What a build needs

This section only applies if you are [building rethinkj UI from source](/docs/get-started/from-source). The first build downloads native archives, verifies SHA-256 checksums, and compiles some libraries from source. Subsequent builds reuse the cached binaries even after `mvn clean`.

<Tabs items={['Linux', 'Windows']}>
<Tab value="Linux">

Building SDL, FreeType, and HarfBuzz uses `cmake` and `make` (about 1 minute). On Debian/Ubuntu:

```sh
sudo apt install build-essential cmake pkg-config xz-utils libx11-dev libxext-dev \
  libxrandr-dev libxcursor-dev libxfixes-dev libxi-dev libxtst-dev libwayland-dev \
  libxkbcommon-dev libegl-dev libdbus-1-dev
```

The built libraries depend on the `glibc` version of the build machine: built on a newer one, they may need a newer glibc than the published natives JAR.

</Tab>
<Tab value="Windows">

Install Visual Studio 2022+ (or Visual Studio Build Tools) with the **Desktop development with C++** workload. Maven detects it automatically; nothing needs to be on `PATH`. If you did not install "C++ CMake tools for Windows", download the CMake ZIP from cmake.org and run once with `$env:CMAKE = '<folder>\bin\cmake.exe'`.

</Tab>
</Tabs>

To build from source without native libraries, pass `-P '!natives-linux-x64'` (or `'!natives-windows-x64'`).
